🐍 渲染为 Python 代码

前面我们讲了 CZEmaker 弹窗、全局命令、音符块、调整图层、过渡动画、批量赋音效、渲染为音频文件、渲染视频文件。现在讲一个“代码化”的功能——渲染为 Python 代码。它能把整份 Itoc 工程的数据打包成一个 Python 脚本文件，方便你嵌入到其他 Python 项目里，或者用 Python 直接运行。

📌 本篇的范围：
讲的是“渲染为 Python 代码”的入口、前置条件、窗口界面、参数设置、生成结果和常见问题。关于工程本身怎么编辑，请参考《CZEmaker 弹窗编排》系列；关于其他渲染格式，请参考《渲染为音频文件》《渲染视频文件》等文档。

一、这个功能是干嘛的？

Itoc 工程文件（.czemidi）本质上是 JSON 数据。渲染为 Python 代码，就是把这堆 JSON 数据“翻译”成一段 Python 代码，并把数据直接写在代码里。生成的 .py 文件可以被其他 Python 程序导入，也可以单独运行（如果模板支持的话）。

跟其他渲染功能相比，它输出的是代码，不是音频、视频，也不是可直接播放的 CzeData 文件。适合这些场景：

  • 想把 Itoc 工程的数据嵌入到自己的 Python 脚本里
  • 想用 Python 代码的形式查看工程里的音符、命令、配置
  • 想二次开发，基于 Itoc 的数据做自己的播放器或工具

二、从哪里打开？

菜单位置：「渲染(R)」 → 「渲染为Python代码」。

快捷键：Ctrl + Shift + R。

💡 别按错了：
音频渲染是 Ctrl+Alt+E，视频渲染是 Ctrl+Alt+V，CZE 数据文件是 Ctrl+R，Python 代码是 Ctrl+Shift+R。四个入口别搞混。

前置条件

打开“渲染为 Python 代码”前，程序会先检查：

检查项不满足时的提示怎么解决
是否有打开的工程“请先打开或保存一个工程文件”先新建或打开一个工程
工程里是否有音符“当前工程没有音符数据”先在时间轴上画几个音符

如果工程已经改过（标题栏工程名带 *），还会先弹一个确认框：

  • 是：先保存工程，再打开渲染窗口
  • 否：不保存，直接用未保存的修改进行渲染
📌 为什么建议先保存？
渲染过程读的是工程文件里的数据。如果你在编辑器里改了但没保存，渲染出来的代码会缺少最新的修改。所以程序会提醒你先保存。

三、窗口界面

打开后是一个左右分栏的窗口，左边是设置和预览，右边是数据预览和代码预览。

区域内容
左栏工程信息、BPM 设置、选项、底部按钮
右栏上部数据预览表格（音符、命令列表）
右栏下部Python 代码预览（深色背景，带简单语法高亮）

3.1 工程信息

显示当前工程的文件名、音符数量、命令数量、目标 BPM。这些信息是只读的，帮你确认打开的是正确的工程。

3.2 BPM 设置

一个输入框，让你设置渲染时使用的 BPM。默认是工程当前的 target_bpm。旁边会实时显示“每拍多少秒”。

修改 BPM 会影响音符的时间换算——音符数据会从“节拍”转换成“秒”。比如 BPM 设成 120，那么 1 拍就是 0.5 秒。

3.3 选项

选项默认说明
包含CZEmaker勾选是否把音符的 CZEmaker 配置（弹窗参数）一起写进代码
保留节拍数据不勾选是否在代码里同时保留节拍单位（默认只保留秒单位）
包含全局命令勾选是否把全局命令一起写进代码
💡 选项怎么选：
· 如果你只是想要一份能用的代码，保持默认即可。
· 如果你不需要弹窗配置，可以取消“包含CZEmaker”，代码会更小。
· 如果你需要节拍数据做其他计算，可以勾选“保留节拍数据”。

3.4 数据预览

右栏上部是一个表格，显示转换后的音符和命令数据。表格列包括：序号、类型、音高/描述、时间(s)、时长(s)、结束(s)。

点击“刷新预览”按钮可以重新生成预览。修改 BPM 或选项后，预览不会自动刷新，需要手动点一下“刷新预览”。

3.5 代码预览

右栏下部是生成的 Python 代码预览，深色背景，关键字、字符串、数字、注释有简单的颜色区分。

代码预览显示的是最终会保存的内容。如果你修改了 BPM 或选项，点“刷新预览”后代码预览也会更新。

3.6 底部按钮

按钮作用
开始渲染生成最终代码，并弹出保存对话框
取消关闭窗口，不生成文件
刷新预览用当前设置重新生成预览

四、操作步骤

  1. 打开一个包含音符的工程。
  2. 点击菜单「渲染(R)」→「渲染为Python代码」，或按 Ctrl+Shift+R。
  3. 如果工程已修改，按提示选择是否保存。
  4. 在窗口里调整 BPM 和选项（一般保持默认即可）。
  5. 点“刷新预览”查看转换后的数据和代码。
  6. 确认无误后，点“开始渲染”。
  7. 在弹出的保存对话框里选择保存位置，默认文件名是 工程名_render.py。
  8. 保存成功后，会弹窗提示生成的文件名、大小、音符数量、命令数量。

五、生成结果

生成的 .py 文件是一个完整的 Python 脚本，里面包含一个 CZEDATA_CONTENT 变量，存储了工程的所有数据。大致结构如下：

CZEDATA_CONTENT = {
    "version": "2.0",
    "source_project": "工程文件名",
    "render_time": "渲染时间",
    "render_bpm": 120,
    "notes": [
        {
            "note_value": 60,
            "start_s": 0.0,
            "duration_s": 0.5,
            "end_s": 0.5,
            "cze_makers": { ... }
        },
        ...
    ],
    "global_commands": [ ... ]
}

具体内容取决于你勾选的选项：

  • 勾选“包含CZEmaker” → 每个音符里会有 cze_makers 字段
  • 勾选“包含全局命令” → 会有 global_commands 字段
  • 勾选“保留节拍数据” → 音符里会额外保留节拍单位
📌 生成的文件怎么用？
你可以用 Python 直接导入这个文件，读取 CZEDATA_CONTENT 变量，然后用自己的代码处理这些数据。也可以把它作为数据文件，配合 Itoc 的解释器使用。

六、常见问题

Q1：点“开始渲染”后没反应？

检查一下前置条件：有没有打开工程、工程里有没有音符。如果都满足，看看是不是弹出了保存对话框但被其他窗口挡住了。

Q2：生成的代码里没有 CZEmaker 配置？

检查“包含CZEmaker”选项有没有勾选。如果没勾选，生成的代码里就不会有 cze_makers 字段。

Q3：BPM 改了，但预览没变？

需要手动点一下“刷新预览”按钮。BPM 输入框修改后不会自动刷新预览。

Q4：生成的代码能直接运行吗？

生成的代码本身只是一个数据文件，定义了一个变量。它能不能直接运行，取决于你用的模板。默认模板是给 Itoc 解释器用的，单独运行不会有界面或声音。

Q5：保存时提示“找不到模板文件”？

说明程序目录下缺少模板文件。模板文件通常在 sys_accessories/to_py/to_py_Original.txt 或程序根目录的 to_py_Original.txt。如果文件丢失，需要重新获取或恢复。

Q6：可以只渲染一部分音符吗？

这个功能目前不支持范围选择，它会处理工程里的全部音符。如果你只想渲染一部分，可以先用时间选区圈出范围，然后导出工程片段，再对片段进行渲染。

Q7：生成的代码文件很大怎么办？

如果工程里音符很多，生成的代码文件会比较大。可以尝试取消“包含CZEmaker”和“保留节拍数据”，只保留核心的音符时间数据，这样文件会小很多。（这个主意非常雷霆）

七、小结

「渲染为Python代码」是 Itoc 提供给开发者的一个数据导出功能，把工程数据变成 Python 代码，方便嵌入、查看和二次开发。

  • 入口：菜单「渲染(R)」→「渲染为Python代码」，或 Ctrl+Shift+R
  • 前置条件：有打开的工程 + 有音符数据
  • 窗口左侧设置 BPM 和选项，右侧预览数据和代码
  • 支持包含/排除 CZEmaker、全局命令、节拍数据
  • 生成一个 .py 文件，内含 CZEDATA_CONTENT 变量
  • 适合嵌入其他 Python 项目或做二次开发
