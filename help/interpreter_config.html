🎛️ 解释器自定义配置

前面我们讲了 CZEmaker 弹窗、全局命令、音符块、调整图层、过渡动画、批量赋音效、渲染为音频文件、渲染视频文件、渲染为 Python 代码、渲染为 CZE 数据文件、编译为 exe、组装打包模式。现在讲一个底层但重要的功能——解释器自定义配置。它决定了“用什么程序来运行你的工程”。

📌 本篇的范围：
讲的是解释器的概念、两种配置（主解释器、测试运行解释器）、四种模式、配置入口、配置保存和常见问题。关于编译为 exe 和组装打包模式的完整流程，请参考对应的文档。

一、什么是解释器？

Itoc 工程本身只是数据，它需要“解释器”才能运行。解释器负责读取 .CzeData 数据文件，然后按照里面的时间轴播放弹窗、执行命令、显示动画。

可以这么理解：

角色对应文件作用
编辑器Itoc 主程序写“源代码”（.czemidi 工程）
编译器渲染器把工程编译成 .CzeData
解释器runCZEx64window.exe 等运行 .CzeData，播放弹窗

解释器自定义配置就是让你指定“用哪个解释器程序来运行”。默认情况下，Itoc 自带四个解释器，但如果你有自己定制或修改过的解释器，可以通过这个功能替换。

二、两种解释器配置

Itoc 里有两个独立的解释器配置：

配置用途
主解释器用于编译、组装打包、双击 .CzeData 文件等正式场合
测试运行解释器专门用于 F5 一键测试运行，独立配置
💡 为什么要分开？
因为测试运行经常需要调试、看日志、输出报错信息，所以你可能会用“带控制台窗口的解释器”来测试，但正式打包时希望用“无控制台窗口的解释器”。分开配置，互不干扰。

三、从哪里打开？

有两个入口可以打开解释器配置：

3.1 从「编译(C)」菜单打开

菜单项作用
配置Itoc解释器打开主解释器配置窗口
配置Itoc测试运行解释器打开测试运行解释器配置窗口

3.2 从「首选项」→「解释器」打开

打开首选项窗口（菜单「文件」→「首选项」），在左侧分类里点「解释器」，右侧会出现两个按钮：

  • 打开Itoc解释器配置 —— 主解释器
  • 打开测试运行解释器配置 —— 测试运行专用
📌 建议：
首选项里的解释器页面只是入口按钮，真正的配置窗口是独立的。点按钮后弹出的就是配置窗口。

四、四种解释器模式

每种解释器配置（主解释器、测试运行解释器）都支持四种模式：

模式默认文件说明
64位 - 窗口runCZEx64window.exe64 位，带窗口，推荐
64位 - 控制台runCZEx64.exe64 位，带控制台窗口，方便调试
32位 - 窗口runCZEx86window.exe32 位，带窗口
32位 - 控制台runCZEx86.exe32 位，带控制台窗口

4.1 64位 vs 32位

  • 64位：适合现代 64 位 Windows 系统，推荐默认使用。
  • 32位：适合老旧系统或特殊兼容需求。

4.2 窗口 vs 控制台

  • 窗口模式：只有弹窗，没有命令行窗口，画面干净，适合正式演出。
  • 控制台模式：会保留一个黑色的命令行窗口，能看到运行日志和报错信息，适合调试。

4.3 当前选中模式

四种模式里，同一时刻只有一个被选中为“当前使用模式”。编译为 exe、组装打包、双击 .CzeData 等操作，都会使用当前选中模式的解释器路径。

五、配置窗口界面

点开解释器配置后，会看到四种模式的配置项：

字段说明
模式名称显示“64位 - 窗口”等标签
当前状态显示使用的是自定义路径还是默认解释器
路径输入框可以手动输入解释器路径
浏览按钮从文件对话框里选择一个 exe 文件
单选按钮选中某个模式作为当前使用模式

5.1 自定义 vs 默认

每种模式都可以：

  • 留空：使用 Itoc 自带的默认解释器（runCZE 目录下的对应文件）
  • 填自定义路径：使用你指定的解释器
💡 什么时候需要自定义？
· 你修改过解释器源码，重新编译了一个定制版
· 你把解释器放在了别的目录
· 你需要用某个特定版本的 Python 或解释器

六、测试运行解释器

测试运行解释器是独立于主解释器的，专门用于 F5 一键测试运行。它有自己的配置窗口和配置字段。

6.1 为什么要独立配置

测试运行的场景和正式运行不太一样：

  • 你可能希望测试时看到日志和控制台，所以用控制台模式
  • 你可能希望测试时用另一个 Python 环境
  • 你可能不希望测试时的调试信息影响正式运行

6.2 留空则用主解释器

如果测试运行解释器留空，那么 F5 测试运行会自动使用主解释器配置。只有当你填了自定义路径，才会用独立的测试解释器。

七、配置保存在哪里？

解释器配置保存在 shezhi.txt 里，字段如下：

字段内容
interpreter_64_window64 位窗口解释器路径
interpreter_64_console64 位控制台解释器路径
interpreter_32_window32 位窗口解释器路径
interpreter_32_console32 位控制台解释器路径
current_interpreter_mode当前选中模式，取值为 64_window / 64_console / 32_window / 32_console
test_interpreter_path测试运行专用解释器路径（留空则用主解释器）

这些配置在程序启动时自动加载，关闭时自动保存。不需要手动编辑。

八、解释器用在哪里？

配置好的解释器会在这些地方被使用：

场景使用的解释器
F5 一键测试运行测试运行解释器（留空则主解释器）
编译为 exe不直接用解释器，而是用 PyInstaller 打包
组装打包模式主解释器
双击 .CzeData 文件主解释器
运行库管理当前 Python 环境
📌 组装打包模式特别重要：
组装打包模式会把主解释器复制过去并重命名成你的程序名。所以主解释器配置直接决定了组装打包出来的程序用哪个解释器版本。

九、常见问题

Q1：我不知道该选哪个模式？

一般选 64位 - 窗口。这是最通用的模式，64 位 Windows 系统都能用，而且没有控制台窗口，画面干净。

Q2：自定义路径填错了会怎样？

程序会检测路径是否存在。如果路径无效（文件不存在），会显示“❌ 路径无效”。这种情况下，使用该模式时会回退到默认解释器，或者报错提示找不到解释器。

Q3：默认解释器在哪里？

默认解释器位于程序目录下的 runCZE/ 文件夹里，对应四个文件名。如果这些文件存在，就会自动作为默认值使用。

Q4：可以同时使用多个解释器吗？

不可以。同一时刻只有一个“当前选中模式”生效。四种模式的配置可以同时存在，但当前使用的只有一个。

Q5：测试运行解释器可以不配置吗？

可以。留空即可。留空时，F5 测试运行会用主解释器的当前选中模式。

Q6：解释器配置会影响工程文件吗？

不会。解释器配置保存在 shezhi.txt 里，属于软件设置，不会写进工程文件。分享工程文件给别人时，对方用自己的解释器配置。

Q7：我把解释器放到别的目录了，怎么配置？

在对应的模式里，点“浏览”按钮，选择你的解释器 exe 文件即可。或者手动把路径粘贴到输入框里。

Q8：为什么编译为 exe 不直接用解释器？

编译为 exe 是用 PyInstaller 把 Python 代码打包成一个独立的 exe，不是简单地复制解释器。所以它走的是另一条路径，不使用解释器配置。
如果你想要“复制解释器”的分发方式，请用组装打包模式。

Q9：解释器配置和运行库是什么关系？

解释器是一个已经打包好的独立程序，它自带运行所需的依赖。运行库是指当前电脑上 Python 环境里的第三方库，两者是独立的。
编译为 exe 时需要运行库，组装打包模式不需要。

Q10：可以分享我的解释器配置给别人吗？

可以，但一般不需要。解释器配置属于个人环境设置，别人可能有不同的安装路径。如果确实需要，可以把 shezhi.txt 里对应的字段复制给对方。

十、小结

「解释器自定义配置」是 Itoc 的底层设置，决定了“用什么程序来运行你的工程”。

  • 入口：菜单「编译(C)」→「配置Itoc解释器」/「配置Itoc测试运行解释器」，或「首选项」→「解释器」
  • 两种配置：主解释器、测试运行解释器
  • 四种模式：64位窗口 / 64位控制台 / 32位窗口 / 32位控制台
  • 每种模式可以留空（用默认）或自定义路径
  • 当前选中模式决定了组装打包、双击 .CzeData 等使用哪个解释器
  • 测试运行解释器留空时会自动用主解释器
  • 配置保存在 shezhi.txt，属于软件设置，不影响工程文件
