💾 将工程导出为 MIDI

在 Itoc 里辛辛苦苦画了几百个音符块，调好了弹窗时间，突然有一天，你想把这套节奏和旋律拿到别的软件（比如 FL Studio、Cubase）里去编曲，或者分享给朋友……

这时候，你就需要把 Itoc 工程“反向”导出为 MIDI 文件了。Itoc 不仅能读 MIDI，也能写 MIDI 哦！

一、从哪里打开？

在菜单栏找到 「文件」→「将工程导出为 MIDI」。

如果当前工程里空空如也（一个音符都没有），程序会弹窗拦住你：“当前工程内没有音符数据，无法导出！”。所以先画几个音符吧。

二、导出选项

弹出的窗口非常小巧，只有几个选项：

选项 / 设置说明
包含歌词 默认勾选。如果你在音符块的“注释文本”里写了字（比如“只因你太美”），勾选这个后，这些字会被写成 MIDI 文件里的 Lyrics 元事件。拿到别的软件里，如果有歌词显示窗，就能直接看到词。
保存路径 默认保存在你的工程文件同级目录下，名字是 工程名_export.mid。你可以点“浏览”自己挑个地方。

三、它到底是怎么导出的？

点下“开始导出”后，后台会悄咪咪地做这几件事（了解这些，有助于你排查为什么导出后看起来不对）：

3.1 按轨道拆分

你在 Itoc 里画在不同轨道上的音符，导出时会被分别塞进 MIDI 里的不同 Track（音轨） 里。比如你在轨道 0 画了鼓点，轨道 1 画了旋律，导出的 MIDI 里就会有两个独立的音轨，并且保留了你在 Itoc 里设置的轨道名称。

3.2 精度对齐（480 Ticks per beat）

MIDI 文件不是用“秒”来记录时间的，而是用 Tick（滴答数）。Itoc 导出时，统一使用 480 拍分辨率（ticks_per_beat=480）。这意味着，每个节拍会被切分成 480 份。你的音符在时间轴上精确到哪一秒，导出时就会换算成对应的 Tick 数，保证节奏不会跑偏。

3.3 防止音效打架的排序

如果在同一个时间点，既要“关闭上一个音符”，又要“开启下一个音符”，还要“显示歌词”，谁先谁后呢？
程序定的规则是：先处理 Note Off（关音符） → 再处理 Lyrics（歌词） → 最后处理 Note On（开音符）。这样能保证连续的音符听起来是干净的断奏，不会黏在一起。

3.4 终极修复：强制 GBK 编码（防乱码）

这是代码里提到的一个“骚操作”。有些国外的宿主软件（或者老版本的软件）在读取 MIDI 里的中文轨道名和歌词时，默认用 ASCII 或者 ANSI 编码，导致中文全变成乱码。

为了解决这个问题，Itoc 在导出时，会强行把文字转成 GBK 编码再塞进 MIDI 文件里。这样国内大部分软件打开就不会乱码了。

⚠️ 编码小提示：
如果你的宿主软件比较特殊，打开中文轨名依然是乱码，那可能是它只认 UTF-8。这时候你只能手动在宿主软件里把轨名改成英文了。不过大多数主流软件（FL Studio, Cubase 等）读 GBK 是没问题的。

四、导出完成后

进度条跑完后，如果成功了，右下角的轮播图会弹出一个通知：“工程已成功导出为 MIDI”。

你可以直接去保存路径里找到那个 .mid 文件，拖进你的编曲软件里，或者发给你的好基友啦！

如果你反而需要把外部音频变成 MIDI，请参考 音频转 MIDI (扒谱)。
