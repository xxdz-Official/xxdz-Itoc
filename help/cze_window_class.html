🏷️ 窗口类名

前面我们讲了侧边栏、显示器、参考媒体，还有一大堆全局命令。这篇要讲一个听起来很基础、但实际上是整个 Itoc 世界观里最容易被搞混的概念——窗口类名。

📌 本篇的范围：
讲的是 Itoc 自己工程里的窗口类名（音符块/弹窗的唯一标识）、侧边栏里的窗口类名管理器，以及它跟操控第三方窗口时用到的"系统窗口类名"有什么区别。关于全局命令里怎么用类名，请参考对应的全局命令文档；关于编组，请参考《编组》文档。

一、先搞清楚：一共有两种"窗口类名"

这是本篇文章最重要的部分。Itoc 的世界观里，"窗口类名"这个词会出现在两个完全不同的地方，它们的含义、来源、用途都不一样。很多新手会在这里绕晕，所以我们先把它掰开。

Itoc 内的窗口类名第三方窗口的窗口类名
是什么 你自己给一个音符块/弹窗起的名字 Windows 系统给每个窗口分配的类型标识
从哪来 在 CZEmakers 面板的「窗口类名」输入框里手填 由操作系统决定，你用拾取器抓取出来
长什么样 随意字符串，如 LoginBox、bgm_player、提示框1 固定英文类名，如 Notepad、Chrome_WidgetWin_1、Notepad++
谁在用 Itoc 自己的弹窗系统、链接位置、全局命令、阵列、动画 Windows API，用来定位外部程序的窗口
唯一性 你自己保证，同一个工程里不重复 系统保证，同类窗口可能有多个实例
能不能改 随便改，随时改 改不了，是程序写死的
💡 一句话记忆：
· Itoc 窗口类名 = 你给自己弹窗起的"外号"，Itoc 内部认这个外号。
· 第三方窗口类名 = Windows 给别的程序窗口分的"物种名"，操作系统认这个物种名。

二、Itoc 内的窗口类名是干嘛的？

Itoc 的每个弹窗（音符块）都可以带一个类名。这个类名不是必须的，但一旦你填上，它就成了这个弹窗在整个工程里的"身份证"。

它的主要用途有以下几个：

  1. 窗口链接：位置配置里选「与窗口链接」时，需要填一个目标窗口类名，让新弹窗跟着那个窗口走。
  2. 全局命令：像「关闭某类名的弹窗」「获取焦点与置顶」这类命令，需要你指定一个类名来选中目标。
  3. 窗口位移动画：动画目标选「窗口类名」时，会对工程里所有带这个类名的弹窗一起做位移。
  4. 阵列变换：阵列作用于编组，但编组本质上是按类名/编组名管理弹窗的。
  5. 销毁模式：决定这个弹窗关闭时是"销毁即销毁"还是"销毁即脱壳"。

2.1 在哪里填？

打开侧边栏的 CZEmakers（配参）面板，在「窗口内容」那一行的右侧，有一个「窗口类名」输入框。填进去，点应用，就存进这个音符块了。

一个音符块的类名，会一起存进工程文件。保存、重新打开、编译 exe，都会带着。

⚠️ 别把类名当成"标题"用：
类名是给程序看的，标题是给用户看的。类名要短、要唯一、要避免中文和特殊字符，标题则可以随便起。
虽然 Itoc 不强制，但养成好习惯会让工程更好维护。

2.2 类名和编组的关系

很多新手会问：编组和类名到底什么关系？

编组类名
是什么 一组弹窗的"俱乐部" 单个弹窗的"身份证"
一个弹窗能有几个 最多一个 最多一个
一个编组/类名能管几个弹窗 多个 多个（但不推荐，容易出问题）
典型用途 批量关闭、整体位移、阵列 精确定位、窗口链接、唯一标识

简单说：编组管一群，类名管一个（或精准一组）。两者可以同时存在，互不冲突。

三、第三方窗口的窗口类名又是什么？

当你写全局命令去操控别的程序（比如记事本、浏览器、播放器）时，Windows 需要你告诉它"我要操作的是哪个窗口"。这个时候用的就是系统级的窗口类名和句柄。

3.1 它长什么样？

  • Notepad —— 记事本
  • Chrome_WidgetWin_1 —— Chrome / Edge 系浏览器
  • Notepad++ —— Notepad++
  • ApplicationFrameWindow —— UWP 应用的外壳窗口

这些名字不是你起的，是程序开发时就注册到 Windows 里的。两个不同的程序可能有相同的类名，同一个程序的多个窗口也会有相同的类名。

3.2 怎么获取？

Itoc 里所有需要填第三方窗口类名的地方，旁边都有一个 🔍 拾取窗口 按钮。点一下会打开一个独立的拾取器：

  1. 把鼠标移到你要操作的那个窗口上。
  2. 按键盘上的数字键 1。
  3. 拾取器会把该窗口的类名、句柄、标题都抓出来。
  4. 点确定，自动填进输入框。

如果你的窗口不支持用鼠标拾取（比如已经最小化了），也可以手填类名，但手填容易出错，建议还是用拾取器。

💡 拾取器抓的是"最内层控件"：
它默认抓鼠标正下方最内层的那个控件，这通常是你要操作的目标。如果你想抓整个窗口而不是里面的某个按钮，可以在拾取器里切换"顶层窗口"模式。

3.3 句柄比类名更精确

系统级的窗口标识有两个：类名和句柄。

  • 类名：标识"这一种窗口"，比如所有记事本窗口的类名都是 Notepad。
  • 句柄：标识"这一个窗口"，是每个窗口实例唯一的十六进制数字，比如 0x000811CE。

当你只填类名时，程序会从所有窗口里找第一个匹配的。当你填了句柄时，程序会精确找到那个窗口实例。

📌 什么时候用类名，什么时候用句柄？
· 只关心"这一类"窗口（比如无论哪个记事本都行）→ 用类名。
· 精确锁定"某一个"窗口（比如用户刚才打开的那一个）→ 用句柄。
· 类名和句柄可以只填一个，也可以都填。都填时句柄优先。

四、两种类名各自出现在哪些地方？

为了让大家不再搞混，我们把 Itoc 里所有出现"窗口类名"的地方列个表。

出现位置用的是哪种类名说明
CZEmakers 面板的「窗口类名」输入框 Itoc 内 给这个音符块本身起名
侧边栏 → 窗口类名选项卡 Itoc 内 查看工程里所有已使用的类名
位置配置 → 与窗口链接 → 目标 Itoc 内 链接到工程里另一个带该类名的弹窗
全局命令 → 关闭某类名的弹窗（按类名模式） Itoc 内 关闭工程里所有带该类名的弹窗
全局命令 → 关闭某类名的弹窗（指定第三方窗口模式） 第三方 关闭外部程序的窗口，要用拾取器抓
全局命令 → 获取焦点与置顶（按类名模式） Itoc 内 让自己工程里的某类弹窗获得焦点
全局命令 → 获取焦点与置顶（指定第三方窗口模式） 第三方 让外部程序窗口获得焦点
全局命令 → 鼠标移动（移动到目标窗口） 第三方 鼠标移到外部窗口的位置

调整图层 → 目标类名 Itoc 内 指定哪个弹窗出现时激活这个特效层
⚠️ 最容易踩的坑：
在全局命令的「窗口位移动画」里选目标类型时，「窗口类名」和「第三方窗口」是两个不同的选项：
· 选「窗口类名」→ 填 Itoc 自己的类名，动的是自己工程里的弹窗。
· 选「第三方窗口」→ 用拾取器抓，动的是外部程序的窗口。
填反了，要么找不到窗口，要么动错目标。

五、窗口类名管理器

讲了这么多概念，你可能会问：我怎么知道工程里到底用了哪些类名？ 答案就是侧边栏顶部的「窗口类名」选项卡——也就是这一节要讲的窗口类名管理器。

5.1 它在哪？

窗口类名管理器不是独立窗口，它就在侧边栏上半部分，选项卡标题是「窗口类名」。它和「显示器」「历史操作」在同一排选项卡里，紧挨着「窗口编组」选项卡。

如果侧边栏当前是隐藏状态，先通过菜单「视图(V)」→「显示侧边栏（停靠）」把它显示出来，然后点「窗口类名」选项卡即可。

5.2 界面布局

从上到下分成三部分：

区域内容
顶部搜索栏搜索框（带占位提示「搜索窗口类名...」）、清空按钮「×」、刷新按钮「刷新」
中间列表工程里所有已使用的窗口类名列表
底部状态列表的滚动条（内容多时出现）

5.3 搜索过滤

搜索框就在选项卡顶部，左边是输入区，右边依次是「×」清空按钮和「刷新」按钮。

  • 输入关键字：列表会实时过滤，只留下类名里包含关键字的行。
  • 清空：点「×」按钮，清空搜索框并恢复完整列表，同时焦点回到搜索框，方便继续输入。
  • 占位提示：搜索框为空时会显示灰色的「搜索窗口类名...」，开始输入后提示消失。
💡 搜索是"包含匹配"：
输入 login 会匹配 login_dialog、itoc_login_box 等所有包含这个片段的类名。不区分大小写。

5.4 刷新

点「刷新」按钮，会重新扫描当前工程里的所有音符块，把最新的类名列表拉出来。

什么时候需要手动刷新？

  • 你在 CZEmakers 面板里新填了一个类名并应用之后。
  • 你删除了某个音符块，想让它从列表里消失。
  • 你打开了另一个工程，列表还停留在上一个工程的内容。
📌 切到选项卡会自动刷新：
每次你点「窗口类名」选项卡把它切到前台时，列表都会自动刷新一次，不需要每次都手动点「刷新」。

5.5 双击跳转

列表里的每一行代表工程里正在使用的一个窗口类名。双击某一行，主程序的判定线会跳到该音符块所在的位置，画布也会滚动到它旁边。

这个功能在排查问题时特别好用：比如你想确认某个类名到底是哪个音符块在用，双击一下就过去了。

5.6 列表和工程数据是同步的

窗口类名管理器不保存任何数据，它只是一个"查看器"。数据来源是当前工程里所有音符块的 window_class 字段。

  • 工程里有的类名，列表里就有。
  • 工程里没的类名，列表里就没有。
  • 类名改了，刷新一下列表跟着变。
  • 工程关了，列表会清空。
⚠️ 列表里看到重复的类名要警惕：
如果同一个类名在列表里出现多次，说明工程里有多个音符块共用了这个类名。这会导致链接、动画、脱壳缓存互相干扰。建议给它们改成不同的类名。

5.7 和"窗口编组"选项卡的区别

侧边栏里紧挨着「窗口类名」的还有一个「窗口编组」选项卡，长得几乎一样，但管的是不同的东西：

窗口类名选项卡窗口编组选项卡
展示的是 单个弹窗的类名 一组弹窗的编组名
数据来源 音符块的 window_class 音符块的 window_group
典型用途 精确定位、排查类名冲突 批量操作、阵列、整体位移
搜索框提示 搜索窗口类名... 搜索窗口编组...

六、为什么叫"类名"而不是"句柄"？

坦白说，这个名字是初代版本留下的历史遗留问题。早期做的时候没想太多，随手起了个"窗口类名"，后来发现叫"句柄"在语义上更贴切。但这个名字已经用在了工程文件格式、代码字段和所有帮助文档里，改名成本太大，就一直沿用下来了。

读者只要记住一点即可：Itoc 里的"窗口类名"就是弹窗的唯一标识，跟第三方窗口类名不是一回事。

💡 怎么和第三方区分？
Itoc 内部 → 窗口类名（自定义字符串）
操控第三方时 → 系统窗口类名 / 系统窗口句柄（Windows 概念）
加"系统"两个字，从字面上就把两者分开了。

七、销毁模式：销毁即销毁 vs 销毁即脱壳

这是 Itoc 窗口类名体系里一个很特别的概念，跟类名强绑定。

7.1 什么是销毁模式？

当一个带类名的弹窗关闭时，Itoc 可以选择两种行为：

模式行为适用场景
销毁即销毁 弹窗彻底消失，不留任何痕迹 默认模式，普通弹窗用这个
销毁即脱壳 弹窗本体消失，但它的几何信息（位置和尺寸）会被存进内存缓存 需要后续"引用这个弹窗最后位置"的场景

7.2 脱壳有什么用？

脱壳的本质是：虽然窗口没了，但"它最后在哪、多大"这个信息还在。

这样后续的操作就能引用这个信息。典型用途包括：

  • 窗口链接：链接到一个已经关闭的窗口，新窗口会出现在它最后的位置。
  • 窗口位移动画：对一个已经关闭的编组/类名做位移，它会从缓存位置"出发"。
  • 阵列变换：编组里部分弹窗已经关闭时，阵列能按缓存位置补齐布局。
💡 举个例子：
你做了一个"主窗口 → 子窗口"的链接。主窗口关闭后子窗口才出现。
· 如果主窗口是"销毁即销毁"，子窗口会出现在屏幕中央（因为找不到主窗口）。
· 如果主窗口是"销毁即脱壳"，子窗口会出现在主窗口最后待过的地方，位置刚好接上。

7.3 在哪里设置？

在 CZEmakers 面板的「窗口类名」输入框旁边，有一个 ↠∅ 按钮。点它，会弹出一个小菜单，两个选项：

  • 销毁即销毁（默认）
  • 销毁即脱壳

选一个，当前音符块的销毁模式就定了。带对勾的那个是当前生效的。

📌 销毁模式也是"每个音符块独立设置"的：
同一个类名的不同音符块，可以设置成不同的销毁模式。不过这样容易混乱，建议同类名用同一种模式。

八、类名唯一性：一个善意的提醒

Itoc 不会强制你保证类名唯一，但强烈建议你保证。窗口类名管理器就是帮你检查这件事的最好工具——列表里如果同一个类名出现了多次，就说明有冲突。

8.1 不唯一会发生什么？

  • 窗口链接：可能链接到错误的窗口，位置飘忽不定。
  • 关闭某类名弹窗：会关掉所有同名的，包括你不想关的。
  • 窗口位移动画：会一起移动所有同名的，包括你没打算动的。
  • 脱壳缓存：同名的多个窗口会互相覆盖缓存，最后存下来的不一定是你想要的那个。

8.2 怎么避免重复？

  • 用有意义的命名，比如 login_box、error_dialog、bgm_panel。
  • 不同功能的弹窗不要用同一个类名。
  • 同类弹窗（比如多个相同提示）用编组来管理，不要共用类名。
  • 定期打开窗口类名管理器看一眼，发现重复立刻改。
💡 一个小习惯：
把类名和标题"看着像但是不一样"。比如：
· 标题：登录，类名：login_dialog
· 标题：提示，类名：hint_box_01
类名用英文小写下划线，标题用中文，两者一眼能区分。

九、常见问题

Q1：类名可以留空吗？

可以。留空的弹窗没有唯一标识，不能用类名链接、不能用类名关闭、不能参与类名模式下的动画。但可以用编组管理。窗口类名管理器里也不会出现它们。

Q2：类名改了，之前链接它的弹窗怎么办？

链接会失效。因为链接是按类名字符串匹配的，改了就找不到。需要把链接目标也一起改。

Q3：类名支持中文吗？

技术上支持，但强烈不建议。中文类名在某些场景下（比如编译 exe、跨语言环境）可能出问题。建议用英文。

Q4：Itoc 类名和第三方类名能用一样的吗？

能，但没必要。比如你的弹窗类名叫 Notepad，同时又去操控记事本，容易在调试时看混。建议 Itoc 内部类名加个前缀，比如 itoc_login，一眼区分。

Q5：窗口类名管理器里的列表为什么是空的？

常见原因：

  • 还没打开工程，或者工程里一个类名都没填。
  • 搜索框里有残留的关键字，把列表都过滤掉了。点「×」清空试试。
  • 工程里刚改了类名，还没刷新。点「刷新」。

Q6：窗口类名管理器里双击没反应？

双击跳转需要主程序能定位到对应的音符块。如果那个音符块已经被删除，或者类名是手动编造的不存在的值，双击就不会有跳转。刷新一下列表试试。

Q7：改了销毁模式，之前的弹窗会受影响吗？

不影响已经创建的弹窗，只影响之后关闭的弹窗。已经在跑的弹窗会按照它创建时的销毁模式来。

Q8：为什么拾取器抓不到我的目标窗口？

常见原因：

  • 目标窗口被其他窗口遮挡了。
  • 目标窗口是 UWP 应用，内层控件和顶层窗口类名不同，需要切换模式。
  • 目标窗口的管理员权限比你高（比如任务管理器），Windows 不允许低权限进程读取高权限窗口。

Q9：第三方窗口类名可以改吗？

不行。那是程序在开发时注册到 Windows 的，普通用户改不了。你只能"引用"它。

Q10：一个弹窗可以同时有类名和编组吗？

可以，而且推荐。类名负责精准定位，编组负责批量管理，两者互补。

十、小结

「窗口类名」是 Itoc 里一个看似简单、实际上手容易踩坑的概念。关键是要记住：

  • Itoc 里有两种窗口类名：Itoc 自己的，和第三方程序的。
  • Itoc 自己的类名：你起的，给工程内部用，用于链接、全局命令、阵列、动画、销毁模式。
  • 第三方窗口类名：系统给的，用于操控外部程序，要用拾取器抓。
  • Itoc 内部不叫"句柄"，是因为它在语义上更接近"类名"（自定义、跨工程保存、不会失效），加"系统"二字即可和第三方区分。
  • 窗口类名管理器在侧边栏顶部「窗口类名」选项卡里，用于查看工程里所有已使用的类名。
  • 窗口类名管理器支持搜索过滤、刷新、双击跳转，切到选项卡时会自动刷新。
  • Itoc 类名建议：英文、小写、下划线、唯一、有意义。
  • 销毁模式分「销毁即销毁」和「销毁即脱壳」，后者保留几何信息供后续引用。
  • 类名不强制唯一，但强烈建议唯一——窗口类名管理器就是帮你检查这件事的工具。
  • 类名和编组可以同时存在，一个管精准，一个管批量。
