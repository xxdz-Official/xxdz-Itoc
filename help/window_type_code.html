💻 执行代码

「执行代码」严格来说不是一种窗口类型——它是一个全局命令。在 CZEmaker 面板里它被归在窗口类型选择器里，因为从"绑在音符上执行一段东西"的角度看，它和其他窗口类型是平级的。但它的实际行为完全不同：它不弹窗，而是在后台跑一段 Python 代码。

这篇讲清楚执行代码能干什么、怎么用、有哪些坑。

什么时候用执行代码

执行代码适合这些场景：

  • 批量操作：一次性关闭所有弹窗、把所有窗口移到某个位置。
  • 动态逻辑：根据当前状态决定下一步做什么（比如根据时间判断显示不同内容）。
  • 调用外部程序：打开浏览器、执行 shell 命令、启动别的 exe。
  • 测试调试：临时打印一些变量、检查某个对象的状态。
  • 高级玩法：直接操作 Qt 窗口、改窗口属性、创建自定义控件。

如果你只是想弹个窗，用普通弹窗/图片框；只有「弹窗搞不定、需要写代码」的时候，才用执行代码。

⚠️ 重要限制：只有编译模式才会执行。 在 Itoc 里按 F5「测试运行」，执行代码不会跑。只有把工程编译成 exe 后，执行代码才会真正执行。所以别拿它做「预览阶段就需要看到效果」的逻辑。这是 Itoc 的设计决定，官方文档里也写了「预览和组装打包模式无法运用 Python 代码，只有编译模式可以」。

面板长什么样

切到「执行代码」之后，面板会发生这些变化：

  • 顶部右侧功能区：整个隐藏。
  • 位置配置区域：整个隐藏。
  • 窗口标题行 / 窗口内容行：隐藏。
  • 特殊功能区：出现一个「打开文本编辑窗口」按钮 + 一个暗色代码框。

代码框用的是 PyCharm 暗色配色：

  • 背景：#2B2B2B
  • 默认文字：#A9B7C6
  • 光标：#A9B7C6
  • 选中背景：#214283

下方还有一行提示文字：「代码将在编译模式下执行，支持 Python 标准库和用户自定义函数。」

语法高亮

代码框不是纯文本框，它带语法高亮。每次输入后会重新扫描整个文本，给不同 token 上色：

类型颜色示例
关键字橙红 #FF6B35if / for / def / class
字符串绿 #4CAF50"hello" / 'world' / 三引号
注释亮灰 #B0BEC5# 这是注释
数字蓝 #42A5F5123 / 3.14
函数名黄 #FFD54Fdef my_func 里的 my_func
类名青 #26C6DAclass MyClass 里的 MyClass
内置函数/类型亮蓝 #29B6F6print / len / int / list

高亮是「文本变化时全量重扫」的实现方式，小段代码无所谓，几千行的代码会稍微慢一点（但平时没人会往这里塞几千行）。

大编辑器

点「打开文本编辑窗口」会弹出一个 800×900 的独立编辑器，功能更全：

  • 暗色主题：和面板里的代码框同款配色。
  • 语法高亮：输入时实时高亮。
  • 编辑菜单：查找...（Ctrl+F）、替换...（Ctrl+H）、全选（Ctrl+A）。
  • 查找对话框：支持「查找下一个」和「查找全部」，找到的文本会黄色高亮。
  • 替换对话框：支持「替换下一个」和「替换全部」，替换后的文本会绿色高亮。
  • 确定 / 取消：回车确认，ESC 取消。
  • 模态：打开时主窗口不能操作，必须确认或取消。

大编辑器特别适合写长代码——比如一个完整的小脚本，在面板那个小框里编辑会很难受。

💡 面板代码框 vs 大编辑器： 两者编辑的是同一份代码。在大编辑器里确认后，内容会写回面板代码框，并重新应用语法高亮。所以你可以随时在大编辑器和面板之间切换。

代码里能拿到什么

执行代码时，程序会创建一个 exec_globals 字典，把常用对象塞进去，让你的代码能直接访问。能拿到的有：

Qt 相关

  • QApplication、QWidget、QMainWindow
  • QLabel、QPushButton、QLineEdit、QVBoxLayout、QHBoxLayout
  • QTimer、QThread、QPropertyAnimation、QEasingCurve
  • Qt、QPoint、QColor、QFont、QPainter
  • QPixmap、QImage、QIcon、QMovie
  • QMessageBox、QSystemTrayIcon、QMenu、QAction

程序对象

  • app：QApplication.instance()。
  • player：CzePlayer 实例，能访问 current_windows、named_windows、command_executor 等。
  • self：GlobalCommandExecutor 实例，能访问 execute_close_all_popups 等方法。

标准库

  • sys、os、time、math、random、json、re。

所以你可以在代码里直接写：

# 关闭所有弹窗
player.command_executor.execute_close_all_popups("sequential=True")

# 打开浏览器
import webbrowser
webbrowser.open("https://xxdz-official.github.io/xxdz-Itoc/")

# 打印当前窗口数量
print(f"当前有 {len(player.current_windows)} 个窗口")

# 用 QTimer 延迟执行
QTimer.singleShot(3000, lambda: print("3 秒到了"))

执行是同步还是异步

执行代码是异步的。程序会用 QTimer.singleShot(0, ...) 把执行任务扔到主线程的事件队列里，等当前事件处理完再执行。

这意味着：

  • 代码执行不会阻塞音符的调度。
  • 如果代码里有 time.sleep(10)，它会阻塞主线程 10 秒，整个 UI 会卡住。所以别在执行代码里做长耗时的同步操作。
  • 如果要做长耗时操作，自己开 threading.Thread。
⚠️ 主线程阻塞： 执行代码是在主线程跑的。如果你在里面写了死循环或者长时间 time.sleep，整个播放器会卡死。需要长耗时操作时，包一层 threading.Thread(target=..., daemon=True).start()。

异常处理

执行代码的异常会被捕获并打印，不会让程序崩溃：

try:
    exec(code_content, exec_globals)
except Exception as e:
    print(f"  [执行代码] 执行失败: {e}")
    import traceback
    traceback.print_exc()

所以如果你的代码写错了，控制台会看到完整的报错堆栈，但弹窗播放会继续。

💡 调试技巧： 在执行代码里写 print(...)，编译后的 exe 会把输出打到控制台（如果编译时保留了控制台）。如果编译时没有控制台，可以把日志写到文件：open("debug.log", "a").write("xxx\n")。

配置文件字段

字段名类型含义
window_typestring固定 code
code_contentstringPython 代码内容

执行代码不保存 window_title、window_content、window_position、window_class、window_group 这些字段——因为它压根不弹窗，这些字段没有意义。

常见问题

Q：测试运行时执行代码没反应？

A：正常。执行代码只在编译模式下生效。测试运行（F5）时，程序会跳过 code 类型。想测试，编译成 exe 再跑。

Q：执行代码报「NameError: name 'xxx' is not defined」？

A：你用了 exec_globals 里没有的对象。检查一下：是不是拼写错了？是不是忘了 import？是不是想访问 self 但写成了别的名字？

Q：执行代码导致程序卡死？

A：大概率是写了死循环、长时间 sleep、或者在主线程做了大量计算。把耗时操作挪到子线程：threading.Thread(target=my_func, daemon=True).start()。

Q：执行代码能不能修改其他窗口？

A：能。通过 player.current_windows 拿到窗口列表，遍历修改 windowOpacity、move、setGeometry 等。但注意别在主线程里做太重的操作。

Q：执行代码能不能创建新窗口？

A：能。但要注意两点：① 新窗口要自己管理生命周期（什么时候显示、什么时候关闭）；② 新窗口不会被自动注册到 Itoc 的窗口管理系统里，除非你手动调 player.command_executor.register_window_class 等方法。

小结

执行代码的三件事：

  1. 不是窗口：不弹窗，跑代码，位置/样式/按钮区都不生效。
  2. 只在编译模式跑：测试运行时不会执行，这是设计决定。
  3. 主线程执行：长时间操作要自己开线程，不然会卡死。

执行代码是 Itoc 的「后门」——它能做弹窗做不到的事，但也要小心用。写之前先想清楚：这个需求真的需要写代码吗？还是用普通弹窗/图片框就能解决？想清楚了再动手喵 ( ⓛ ω ⓛ *)
