🚫 启用 / 禁用事件块或全局命令

写工程的时候，经常会出现这种情况：某一段弹窗我不想让它出现了，但又舍不得删——万一以后想改回来呢？直接删掉又得重新配，太亏了。

Itoc 给你准备了一个「禁用」功能。被禁用的东西会留在工程里，画布上照样看得见，但是渲染出去后解释器不会执行它。就像代码里的注释——写在那儿给人看，机器不跑它。

这篇讲三件事：

  1. 怎么禁用：音符块、调整图层、全局命令，三种东西三种入口。
  2. 禁用后长什么样：画布上的视觉反馈。
  3. 渲染时怎么选：渲染 CzeData 窗口里的两个复选框，到底勾不勾？
💡 一句话记住：
禁用的东西留在工程里，画布上看得见，但解释器不会执行它。
你可以在渲染的时候选择「把被禁用的也导出」，也可以选择「默认跳过」——两种都对，看你需求。

一、三种能禁用的东西

对象 怎么禁用 存在哪 画布上的样子
音符块 选中音符 → 按 Ctrl+Q（或菜单） all_notes 元组第 8 个字段 灰色填充 + 变淡
调整图层 选中调整图层 → 按 Ctrl+Q layer["disabled"] 灰色填充 + 红色对角线
全局命令 右键菱形 → 「禁用该命令」 command["disabled"] 灰色菱形 + 红色斜线

三者的禁用效果是一样的——留在工程里，但解释器不执行。区别只在于入口不同、视觉反馈略有区别。

二、禁用音符块：Ctrl+Q

2.1 怎么用

  1. 在时间轴上框选或点选你想禁用的音符块。
  2. 按 Ctrl+Q。
  3. 音符块立刻变灰，完成。

再按一次 Ctrl+Q 就能恢复——这是一个切换操作，禁用的变启用，启用的变禁用。

💡 智能切换逻辑：
如果你选中的一堆音符全部都是已禁用状态，按 Ctrl+Q 会把它们全部启用。
如果选中的音符里有至少一个是启用状态（哪怕其他都禁用了），按 Ctrl+Q 会把它们全部禁用。

2.2 混选也能用

你同时选中了「音符块 + 调整图层」？没关系，Ctrl+Q 会同时处理两者：

  • 音符块会被改 all_notes 里的禁用字段。
  • 调整图层会被改 layer["disabled"]。
  • 两者互不干扰，各自记录状态。

切换完成后，控制台会打印类似这样的日志：

禁用了 5 个音符块、2 个调整图层

2.3 背后的实现

音符块的禁用状态存在 all_notes 元组的第 8 个字段（索引 7）。来看一眼元组结构：

all_notes[i] = (
    track_idx,          # 轨道索引 (0)
    start_beat,         # 起始节拍 (1)
    dur_beat,           # 持续节拍 (2)
    note_val,           # 音高 (3)
    note_id,            # 唯一 ID (4)
    cze_makers,         # CZEmaker 配置 (5)
    transition,         # 过渡动画配置 (6)
    True                # ← 禁用标记 (7)，启用的音符没有这个字段
)

启用的音符只有 7 个字段（索引 0-6），禁用的音符会多一个 True 作为第 8 个字段。这是为了保持向后兼容——旧工程里的音符没有这个字段，读出来自动当作「启用」。

⚠️ 注意： 不要在外部脚本里手动去改 all_notes 元组的长度。长度不对会导致读取时索引越界。想禁用请用 Ctrl+Q 或右键菜单。

2.4 撤销和重做

Ctrl+Q 的每一次切换都会保存撤销快照。所以你可以：

  • 按错了 → 按 Ctrl+Z 撤销。
  • 又后悔了 → 按 Ctrl+Shift+Z 重做。

快照里存的是整个工程的状态，所以撤销会恢复所有的音符和调整图层的禁用状态。

三、禁用调整图层：Ctrl+Q

调整图层和音符块的禁用方式完全一样——选中，按 Ctrl+Q，搞定。

区别在视觉上：

  • 启用的调整图层：淡紫色填充 + 主题色边框 + 上下装饰条 + "AL" 文字。
  • 禁用的调整图层：灰色填充 + 深灰边框 + 灰色装饰条 + 红色对角线（删除线效果）。

红色对角线是刻意加的视觉提示——一眼就能看出「这个图层不会生效」。

3.1 禁用状态存在哪

调整图层的禁用状态存在 layer["disabled"] 字段里。启用时会把这个字段完全删除（不是设为 False），避免冗余字段污染配置。

# 启用状态
{
    "id": 12345,
    "track_idx": 2,
    "start_beat": 10,
    "duration": 5,
    "effect_params": {...}
    # 注意：没有 disabled 字段
}

# 禁用状态
{
    "id": 12345,
    "track_idx": 2,
    "start_beat": 10,
    "duration": 5,
    "effect_params": {...},
    "disabled": true
}

3.2 解释器的行为

解释器在每 100ms 检查一次调整图层的激活状态（_check_adjust_layers）。检查逻辑是：

for layer in self.adjust_layers:
    # 被禁用的直接跳过，不激活
    if layer.get('disabled', False) is True:
        continue
    # 时间到了就激活特效...

所以被禁用的调整图层永远不会产生特效，即使它正好落在当前时间范围内。

四、禁用全局命令：右键菜单

4.1 怎么用

  1. 在时间轴上找到你想禁用的全局命令（蓝色菱形）。
  2. 右键点击菱形，弹出菜单。
  3. 点「禁用该命令」。
  4. 菱形变灰 + 红色斜线，完成。

想恢复就再右键一次，菜单会变成「启用该命令」，点一下就恢复了。

4.2 视觉反馈

被禁用的全局命令在画布上长这样：

  • 菱形填充色：从蓝色变成灰色（#AAAAAA）。
  • 菱形边框：从蓝色变成深灰（#666666）。
  • 文本颜色：从白色变成浅灰（#DDDDDD），但还能看清。
  • 额外：一条红色斜线从菱形左上角划到右下角，视觉上「划掉」。

一眼扫过去，启用的蓝色菱形和禁用的灰色菱形非常好区分。

💡 悬停预览也能区分：
鼠标悬停在禁用的全局命令上，悬浮提示卡片仍然会显示命令的完整详情（描述、节拍、具体参数）。所以你可以随时查看被禁用的命令原本是干什么的，不用恢复也能看。

4.3 背后的实现

全局命令的禁用状态存在 command["disabled"] 字段里，是布尔值。在 GlobalCommandManager.toggle_command_disabled 里处理：

  1. 找到命令。
  2. 保存撤销快照（save_undo_snapshot_before_modify）。
  3. 翻转 disabled 字段。
  4. 标记工程已修改。
  5. 用当前的绘制参数重绘所有命令（会走禁用状态的样式分支）。

4.4 导出时怎么处理

全局命令导出到 CzeData 时，默认会跳过被禁用的命令。转换函数 convert_commands_to_seconds 开头就有：

for command in commands_data:
    # 被禁用的直接跳过
    if command.get("disabled", False):
        continue
    ...

但渲染窗口里有个「禁用的全局命令」复选框，勾上之后就会把被禁用的也导出（带 disabled: true 字段）。详见第六节。

五、三个通用规则

5.1 禁用不会删除数据

被禁用的东西所有配置都还在：CZEmaker 配参、过渡动画、窗口位置、类名、编组……一样不少。所以：

  • 禁用之后随时可以恢复，配置不会丢。
  • 禁用期间仍可以在 CZEmaker 面板里查看和编辑配置。
  • 禁用不影响「另存为配参」之类的操作。

5.2 禁用会标记工程已修改

每次切换禁用状态，都会调 mark_project_modified()，标题栏的「已编辑*」会亮起来。这是正常的——因为禁用状态本身也是工程数据的一部分。

5.3 禁用状态可以保存和加载

工程文件（.czemidi）里会保留禁用状态：

  • 音符的禁用字段会存在 all_notes 元组里。
  • 调整图层的 disabled 会存在图层字典里。
  • 全局命令的 disabled 会存在命令字典里。

关掉工程再打开，禁用状态会原样恢复。

六、渲染时的选择：两个复选框

打开「渲染 CZE 数据文件」窗口，你能看到右侧选项区域有两个复选框：

复选框 默认 勾上之后
禁用的事件块 不勾选 把被禁用的音符块和调整图层也导出到 CzeData
禁用的全局命令 不勾选 把被禁用的全局命令也导出到 CzeData

6.1 不勾选（默认）：跳过

不勾选时，渲染会完全跳过被禁用的东西。CzeData 文件里不会出现它们的身影。解释器拿到数据时，根本没看到被禁用的东西，自然也不会执行。

适合场景：

  • 最终成品，禁用的东西就是不想让它出现。
  • 想减小 CzeData 体积（被禁用的数据不写进去）。
  • 纯净导出，不想要 disabled 字段污染。

6.2 勾选：保留 + 带 disabled 字段

勾选时，渲染会保留被禁用的东西，并在 CzeData 里带上 disabled: true 字段。解释器读取时会识别这个字段，仍然跳过不执行。

看一份示例 CzeData：

{
  "notes": [
    {
      "note_value": 60,
      "start_s": 1.0,
      "duration_s": 0.5,
      "end_s": 1.5,
      "cze_makers": {...}
    },
    {
      "note_value": 62,
      "start_s": 2.0,
      "duration_s": 0.5,
      "end_s": 2.5,
      "cze_makers": {...},
      "disabled": true          ← 被禁用的音符带着这个字段
    }
  ],
  "global_commands": [
    {
      "description": "关闭所有弹窗",
      "command": "close_all_popups:sequential=True",
      "time_s": 3.0
    }
  ],
  "adjust_layers": [
    {
      "id": 12345,
      "start_s": 4.0,
      "duration_s": 2.0,
      "effect_params": {...},
      "disabled": true          ← 被禁用的调整图层
    }
  ]
}
💡 为什么解释器仍会跳过？
解释器（runCZE）在读取 CzeData 时，会主动过滤 disabled=True 的音符和全局命令：

if _n.get('disabled', False) is True: continue

所以「勾选」只是保留数据，并不意味着「让它们生效」。它们仍然是注释，只是注释被带上了。

6.3 什么时候该勾选

  • 调试：你想在 CzeData 里看到被禁用的东西长什么样、它们的位置和配参，方便对照检查。
  • 后处理：你有一个工具或脚本要读取 CzeData，需要拿到被禁用的数据（比如统计哪些位置被跳过了）。
  • 分享原始数据：你想把「完整工程」和「精简工程」都输出一份，勾选能得到完整版。
  • 存档：保留 disabled 字段，以后想恢复的话有完整信息可查。

6.4 反过来的场景

如果你确定禁用的东西以后再也不用，那不勾选是最干净的做法。CzeData 会小一圈，也不会有 disabled 字段混在里面。

七、在 CzeData 里长什么样

7.1 音符的 disabled 字段

勾选「禁用的事件块」时，被禁用的音符会多一个 disabled: true：

{
  "note_value": 62,
  "start_s": 2.0,
  "duration_s": 0.5,
  "end_s": 2.5,
  "cze_makers": {...},
  "transition": {...},
  "disabled": true
}

启用的音符没有这个字段（不是 disabled: false，是压根没有）。这样能省点体积，也符合「默认值不写」的惯例。

7.2 调整图层的 disabled 字段

{
  "id": 12345,
  "track_idx": 2,
  "start_s": 4.0,
  "duration_s": 2.0,
  "effect_params": {...},
  "disabled": true
}

7.3 全局命令的处理

全局命令有点特殊：即使勾选了「禁用的全局命令」，转换后的命令不会带 disabled 字段。因为 convert_commands_to_seconds 内部会先过滤 disabled，然后把清理后的命令重新转换。

但注意——此时被禁用的全局命令的数据本身还是被保留了（在 CzeData 的 global_commands 里），只是没带 disabled 标识。如果你需要知道哪些是被禁用的，得回头查工程文件。

⚠️ 全局命令的 disabled 字段不会写进 CzeData。
这是当前的实现限制。如果你需要区分，建议在导出前手动检查工程文件里的 global_commands 数组。

八、解释器怎么处理

8.1 音符

解释器的 play() 方法里，会先过滤一遍所有音符：

_enabled_notes = []
for _n in self.notes:
    if isinstance(_n, dict) and _n.get('disabled', False) is True:
        continue
    _enabled_notes.append(_n)

所以不管 CzeData 里有没有 disabled 字段，只要值是 True，就会被跳过。

8.2 全局命令

同样的逻辑：

for _c in self.global_commands:
    if isinstance(_c, dict) and _c.get('disabled', False) is True:
        continue
    _enabled_commands.append(_c)

8.3 调整图层

调整图层的检查在 _check_adjust_layers 里，每 100ms 跑一次：

for layer in self.adjust_layers:
    if isinstance(layer, dict) and layer.get('disabled', False) is True:
        continue  # 跳过，不激活
    ...

8.4 日志输出

如果 CzeData 里带有被禁用的东西，解释器启动时会打印：

[禁用过滤] 跳过 5 个被禁用的音符
[禁用过滤] 跳过 2 个被禁用的全局命令

方便你确认「确实跳过了」。

九、配置文件字段一览

对象 文件 字段路径 类型
音符块 .czemidi notes[i][7]（元组第 8 位） bool
调整图层 .czemidi adjust_layers[i].disabled bool
全局命令 .czemidi global_commands[i].disabled bool
音符（CzeData） .CzeData notes[i].disabled bool（可选）
调整图层（CzeData） .CzeData adjust_layers[i].disabled bool（可选）
全局命令（CzeData） .CzeData 无（导出时会被过滤） —

十、常见问题

Q1：Ctrl+Q 按了没反应？

A：检查三件事：① 是否真的选中了音符/调整图层；② 焦点是否在时间轴上（不是在某个输入框里，输入框里的 Ctrl+Q 会被输入框自己处理）；③ 是不是刚好所有选中的东西都是已禁用状态，按了之后全部启用了，看起来像「没变化」。

Q2：禁用了音符，但 CZEmaker 面板还能编辑？

A：这是正常的。禁用只是不执行，配置数据和面板操作完全不受影响。你可以在禁用的音符上继续修改配参，改完启用立刻生效。

Q3：禁用的东西在画布上还能选中吗？

A：能。禁用的音符和调整图层仍然是完整的画布元素，可以点选、框选、拖动、右键菜单操作。只有「执行」被跳过，其他交互都正常。

Q4：禁用的全局命令还能拖动吗？

A：能。拖动逻辑不受禁用状态影响。你可以把禁用的菱形拖到任何位置，位置数据照常保存。

Q5：禁用了之后能撤销吗？

A：能。每次切换都会保存撤销快照。按 Ctrl+Z 可以撤销到切换前的状态。

Q6：禁用的音符会被导出到 CzeData 吗？

A：看你勾不勾「禁用的事件块」复选框。不勾选（默认）跳过，勾选则保留并带 disabled: true。

Q7：禁用的全局命令为什么在 CzeData 里看不到 disabled 字段？

A：当前实现里，convert_commands_to_seconds 会先过滤 disabled 的命令再转换，所以即使勾选了「禁用的全局命令」，CzeData 里的命令也不会带 disabled 标识。这是已知限制。

Q8：禁用状态会随工程一起保存吗？

A：会。禁用状态是工程数据的一部分，关掉工程再打开会原样恢复。

Q9：我禁用了音符，但忘了它本来长什么样怎么办？

A：三种方法：① 启用它看一眼，看完再禁用；② 打开 CzeMaker 面板（选中它就会加载配置）；③ 直接翻工程的 JSON 文件看 notes 数组。

Q10：能不能批量禁用一整个编组的音符？

A：当前没有「按编组批量禁用」的快捷键。你需要先框选整个编组的音符，然后按 Ctrl+Q。如果编组分布在多个轨道不同位置，框选会比较费劲。

Q11：禁用的东西会影响时间轴总长度吗？

A：不会。时间轴总长度由所有音符（含禁用）的最晚结束时间决定，因为禁用的音符仍然在画布上占位置。如果你想让时间轴缩短，需要真的删除它们。

Q12：为什么我禁用了音符，测试运行时还是在弹？

A：可能原因：① 那个音符没有被真正禁用（检查画布上它是不是灰色的）；② 同一个位置有另一个启用的音符在弹（检查是否有重叠）；③ 全局命令触发了弹窗（比如 window_animation 创建了新窗口）。禁用只影响「该音符本身的弹窗」，不影响其他命令。

十一、小结

启用/禁用的三件事：

  1. 三种对象都能禁用：音符块、调整图层（Ctrl+Q）、全局命令（右键菜单）。
  2. 禁用 = 注释：留在工程里，画布上看得见，解释器不执行。
  3. 渲染时可选择：默认跳过，勾选「禁用的事件块 / 禁用的全局命令」则保留并带 disabled: true。

记住几个关键点：禁用不会删数据，撤销随时可用，渲染窗口的两个复选框决定导不导出。搞清楚这几条，你就能放心大胆地「注释掉」不想要的东西了喵 ( ⓛ ω ⓛ *)
