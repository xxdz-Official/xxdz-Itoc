模类框（CZEmaker 视角）

📌 前置阅读：
这篇讲的是「模类框这个窗口类型，在 CZEmaker 面板里怎么用、运行时怎么表现」。

如果你还不了解「模类是什么、怎么用模类设计器做模类、模类怎么保存、模类管理器怎么用」，请先看下面三篇：
· 初识模类 —— 模类是什么、怎么保存、模类管理器基础
· 模类设计器详解 —— 10 种控件的完整字段、链接系统、JSON 语法
· 模类进阶与生态 —— 内部 ID / 哈希去重 / 解释器运行机制 / 最佳实践

那三篇是「怎么做模类」的说明书，这一篇是「怎么在 CZEmaker 里用模类」的说明书。两者是生产者和消费者的关系，互补不重复。

好，前置说明讲完了，我们进入正题。

模类框是 CZEmaker 面板里最特殊的一个窗口类型——它不是「运行时按配置动态创建控件」，而是「从你预先做好的 .UIclass 模板里还原窗口结构」。所以它和普通弹窗、图片框、视频框的交互方式都不一样：

  • 面板上有一堆控件会被禁用，因为那些配置由模类数据说了算。
  • 多了一个「选择模类」下拉框，专门用来挑模板。
  • 运行时走的是完全不同的创建路径（create_class_popup，而不是 RegularPopup / ImagePopup）。
  • 关闭流程也不一样（_close_class_window_with_animation，而不是 close_window）。

这篇就把这些「不一样」全部拆开讲清楚。读完你应该能回答：为什么我切到模类框之后面板变灰了？为什么我在下拉框里选了模类却没生效？为什么模类框的关闭按钮点了没反应？——这些问题都会在这篇里找到答案。

一、模类框是什么（简版）

模类框的 window_type 英文键名是 UIclass（同时也兼容 class 和中文 模类框 三种写法）。它引用的是一个 .UIclass 文件里定义好的窗口结构。

和普通弹窗的区别，一句话总结：

普通弹窗模类框
窗口结构程序写死的（图标 + 文本 + 按钮区）由 .UIclass 模板定义
控件数量固定任意（10 种控件，支持嵌套）
运行时类RegularPopupQMainWindow + create_class_popup
关闭方法close_window()_close_class_window_with_animation()
内容来源window_content 字段class_data_project 里的模类数据

关于「模类是什么、.UIclass 文件长什么样、模类设计器怎么用」——这些在 初识模类 和 模类设计器详解 里讲得很透，这里不再重复。

二、模类从哪来（简版）

模类有两个来源：

来源存储位置运行时能用吗
工程内置模类工程文件的 class_data_project / ui_Class_data 字段✅ 能
Itoc 全局模类程序目录的 UI_Class_Files/ 文件夹❌ 不能（必须先复制进工程）

记住这条铁律：解释器（runCZE）运行时只会从工程内置模类里查找，不会读 UI_Class_Files/ 文件夹。所以任何你想在最终作品里用到的模类，都必须先「搬进工程」。

关于「内部 ID 怎么生成、哈希去重是怎么做的、全局模类为什么要复制到工程」——这些机制在 模类进阶与生态 第一节讲得很细，这里直接跳过。

这一篇接下来要讲的，是「在 CZEmaker 面板里怎么把一个模类搬到工程、怎么选中它、选中之后面板会怎样」——也就是「消费者」这一侧的流程。

三、切换成模类框后，面板发生了哪些变化

这是很多新手第一次切到模类框会懵的地方。你从「信息框」切到「模类框」，会发现面板一下子灰了一大片。这不是 bug，是设计如此——因为那些配置项在模类框下没有意义，程序主动禁用了它们，防止你配了半天却不生效。

3.1 变化清单

切换成模类框后，面板会做这些调整：

区域变化为什么
顶部右侧功能区 - 图标下拉框 禁用（变灰） 模类框的窗口图标由模类数据的 icon_data_base64 字段控制，面板里的图标设置无效
顶部右侧功能区 - 控制钮下拉框 禁用 标题栏按钮由模类数据的 minimize_btn / maximize_btn / close_btn 控制
顶部右侧功能区 - 按钮区下拉框 禁用 模类框没有对话框按钮区，按钮都在模类里自己画
窗口标题输入框 禁用 + 显示模类名 窗口标题由模类数据的 name 字段决定
窗口内容文本框 禁用 + 灰色背景 + 显示控件列表 模类框没有"文字内容"，显示的是控件清单
自定义尺寸复选框 强制取消勾选 + 禁用 窗口尺寸由模类数据的 width / height 控制
窗口标题行第一位 插入「选择模类」标签 + 下拉框 让用户挑模板
💡 效果音和透明度仍然可用：
虽然图标、控制钮、按钮区都禁用了，但「效果音」下拉框和「透明度」输入框还是可用的。效果音在弹窗出现时播放（和模类内容无关），透明度作用在整个窗口上（包括模类里的所有控件）。

3.2 为什么只有这几个禁用？

你可能会问：为什么图标、控制钮、按钮区禁用，但效果音、透明度不禁用？

判断标准很简单：这个配置项在模类数据里有没有对应字段？

  • 图标 → 模类数据有 icon_data_base64，面板配置会和模类打架，禁用。
  • 控制钮 → 模类数据有 close_btn / maximize_btn / minimize_btn，禁用。
  • 按钮区 → 模类框没有按钮区概念，禁用。
  • 窗口标题 → 模类数据有 name，禁用。
  • 窗口内容 → 模类框没有"文字内容"，禁用。
  • 自定义尺寸 → 模类数据有 width / height，禁用。
  • 效果音 → 模类数据没有效果音字段，所以面板配置生效，不禁用。
  • 透明度 → 模类数据没有透明度字段，所以面板配置生效，不禁用。

这个判断标准很有用——以后你切到其他窗口类型时，也可以用它来判断哪些配置会生效、哪些不会呀。

3.3 图标禁用是"开关式"的

注意一个细节：图标下拉框的禁用不是永久的。你从模类框切回信息框，图标下拉框会自动恢复成可选状态。程序会按当前窗口类型动态刷新它的状态。

所以不用担心"切来切去图标下拉框就永久灰了"的问题哦。

3.4 内容框变灰是"只读展示"

内容框变灰后显示的是控件列表，格式在下一节详细讲。这里只强调一点：它不是让你编辑的，只是让你看个大概。想改控件，去模类设计器改，改完重新加载模类。qwq

如果你尝试在灰色内容框里点击输入，会发现没有光标、没有反应——因为它被设置成了只读状态。

四、选择模类：下拉框 + 自动复制流程

这是这篇文档的核心章节。选模类这件事看起来简单（下拉框选一个就完了），但背后有一整套流程，尤其是「选全局模类时会自动复制到工程」这个机制，很多人第一次遇到会一脸懵。

4.1 下拉框插在哪？

切到模类框后，「选择模类」标签和下拉框会插入到窗口标题行的第一个位置——在「窗口标题」标签之前。

这一行的顺序变成：

[选择模类 ▼]  [窗口标题 ______] [✕] [◥]  [所在编组 ▼]  ...右侧功能区...

为什么插在最前面？因为「选哪个模类」是模类框最优先的决定项——你选了模类，窗口标题、内容、尺寸、按钮就都定了；剩下能改的只有效果音、透明度、位置、寿命这些「外围」配置。

4.2 下拉框里有什么

下拉框的选项来源是两个地方合并去重：

  1. 工程内置模类：遍历 ui_Class_data 列表，对每一项：
    • 如果是文件路径（.UIclass 结尾），取文件名（不含扩展名）
    • 如果是 internal_id，从 class_data_project 里取 _original_filename 字段；取不到就从 internal_id 里剥掉 32 位哈希后缀
  2. Itoc 全局模类：扫描 UI_Class_Files/ 文件夹，取所有 .UIclass 文件的文件名（不含扩展名）

最后 sorted(set(...)) 去重排序。如果两个来源都是空的，下拉框会显示「暂无模类」。

⚠️ 下拉框里出现「暂无模类」怎么办？
说明工程里没有内置模类，全局文件夹里也没有 .UIclass 文件。解决方案：
· 去模类设计器里做一个，保存时选「保存到工程内置」
· 或者从别处拷一个 .UIclass 到 UI_Class_Files/ 文件夹
· 然后在模类管理器里点「🔄 刷新」重新扫描

4.3 选择模类后的完整流程

假设你在下拉框里点了一个模类，接下来程序会做什么？

第一步：判断模类来源

程序先检查这个模类名对应的文件是否存在于 UI_Class_Files/ 文件夹里。如果存在，说明它是全局模类；如果不存在，说明它是工程内置模类。

第二步 A：如果是全局模类 → 自动复制到工程

这是很多人不理解的地方。你选了一个全局模类，程序不会直接用它，而是先把它「搬进工程」：

  1. 弹出一个进度条窗口（标题「导入模类」，350×120，居中显示，带图标）。
  2. 读全局文件夹里的 .UIclass 文件。
  3. 算一个 MD5 哈希（基于文件内容的 JSON 序列化，sort_keys=True 保证稳定）。
  4. 遍历工程里所有已有的模类，算它们的哈希，和新的比对。如果找到相同的，认为「内容重复」，跳过复制，直接走加载流程。
  5. 如果没有重复，生成 internal_id = {模类名}_{32位哈希}，如果有冲突就加 _1、_2 后缀。
  6. 把模类数据存进 class_data_project[internal_id]，把 internal_id 追加到 ui_Class_data 列表。
  7. 标记工程已修改（mark_project_modified）。
  8. 刷新模类菜单（update_ui_class_menu）。
  9. 进度条跑到 100%，关闭进度窗。

整个过程在后台线程里做，主线程用 after(100, check_thread) 轮询进度。复制失败或超时的话，会走兜底：即使复制失败也尝试加载原始全局模类（只读预览），并标记已修改，让你能试试「应用」看能不能救回来。

💡 为什么选个模类还要复制？
因为解释器运行时只读工程内置模类。如果你选全局模类时不复制，那这个配参保存到工程后，运行时就会找不到模类，弹窗就弹不出来。自动复制是为了「保证工程自包含」——你把工程发给朋友，模类跟着走，不会出现「模类找不到」的尴尬。

第二步 B：如果是工程内置模类 → 直接加载

如果模类本来就是工程内置的，跳过复制，直接进入加载流程。加载是异步的：

  1. 状态标签显示「正在加载模类...」，橙色提示。
  2. 后台线程读模类数据（_get_class_data_by_name）。
  3. 回到主线程 _apply_loaded_class，设置窗口标题（禁用）、内容框显示控件列表、加载编组、加载位置、加载寿命。
  4. 状态标签显示「已加载模类: xxx」，绿色。

第三步：标记已修改

加载完成后，程序会调用 mark_property_edited('selected_class_name')，把「模类选择」标记为用户编辑过的属性。这样多选智能更新时，只会更新「模类选择」这一项，其他字段保持不变。

4.4 选择不会自动保存

这是最容易被忽略的一点：你选了一个模类，面板里显示了它，但配置还没写进音符。

你必须点「应用 (Insert)」按钮，才会把当前面板的配置（包括 selected_class_name、位置、寿命、透明度等）保存到选中的音符上。

如果你选完模类就直接切到别的音符，当前面板的修改会触发拦截层（如果之前有修改的话），或者直接丢弃（如果只是切换选中）。总之不会自动保存。

💡 选中模类 ≠ 应用到音符：
「选中模类」只是把模板加载到面板，「应用到音符」才是把配参写进音符数据。前者是「预览」，后者是「落盘」。两步要分开做。

4.5 模类选择器的"幂等创建"

有一个实现细节值得说一下：_create_class_selector 是幂等的。

当你切到模类框时，它会创建「选择模类」标签 + 下拉框。当你从模类框切到别的类型再切回来时，它会检查这两个控件是否还存在：

  • 如果都存在，只刷新下拉框的选项列表，不重建控件。
  • 如果有一个不存在，才移除旧的、重建新的。

这样设计是为了避免「模类框 → 模类框」这种同类型切换时反复销毁重建 row1 里的所有子控件，导致主程序 / 便利贴模块误判为「工程被修改」。

五、内容框显示的控件列表：长什么样

切到模类框后，窗口内容文本框会变成灰色只读，显示这个模类的控件列表。格式是这样的：

1. [label] 标题标签: 用户登录
2. [entry] 用户名输入框
3. [entry] 密码输入框
4. [button] 登录按钮: 登录
5. [button] 取消按钮: 取消
6. [groupbox] 账号信息组
7. [tabwidget] 设置选项卡
   选项卡: 基本设置, 高级设置, 关于
8. [progress] 加载进度条
   进度: 0% → 100%
9. [image] LOGO图片
   图片: logo.png

格式规则：

  • 每行开头是控件序号 + 控件类型（[type]）+ 控件名称。
  • 如果有文本内容（text 字段非空），跟在冒号后面，比如 [label] 标题标签: 用户登录。
  • 图片控件额外显示图片文件名，缩进一行。
  • 进度条额外显示 initial_value → end_value，缩进一行。
  • 选项卡额外显示 tab_titles 列表，缩进一行。

如果模类里一个控件都没有，会显示「（该模类没有包含任何控件）」。

这个列表是只读的，让你快速了解模类的结构。想改控件，去模类设计器改，改完重新加载模类。

六、模类框 + 样式钮：谁说了算

模类框也遵循样式钮的配置（普通边框 / 工具窗 / 无边框），但因为模类框的窗口结构是 QMainWindow 而不是 QWidget，所以样式钮的行为和普通弹窗略有不同。

6.1 三种样式的实际行为

样式钮选择窗口标志实际效果
普通边框（normal_fixed） Qt.Window | 按按钮配参 | 按置顶配置 标准标题栏，按钮按配参显示
工具窗（tool_fixed） Qt.Window | Qt.Tool | Qt.WindowCloseButtonHint 矮标题栏，只保留关闭按钮，忽略最大化/最小化配参
无边框（borderless） Qt.Window | Qt.FramelessWindowHint 无标题栏无边框，忽略所有按钮配参
📌 样式钮只决定「边框和按钮」：
模类框的完整外观是 4 个字段联合决定的，样式钮只负责其中 window_style 这一项：
· window_style：边框和按钮 ← 样式钮管这个
· window_background：有没有背景色（关掉 → 走透明/色键透明） ← 以模类数据为准
· window_material：亚克力/云母 ← 以模类数据为准
· window_topmost：是否置顶 ← 以模类数据为准
· window_opacity：整体透明度 ← 以模类数据为准

也就是说：在 CZEmakers 这边给模类框「勾亚克力 / 取消勾置顶 / 改透明度」都是不生效的，必须去模类设计器的窗口属性面板里改。详见 模类设计器详解 的 1.1 / 1.2 / 1.3。

6.2 帮助按钮的优先级

模类数据里有一个 help_btn 字段。如果它为 true，程序会启用帮助按钮（Qt.WindowContextHelpButtonHint）。

但这里有个联动：帮助按钮会占用最大化按钮的位置。所以如果 help_btn=true 且 maximize_btn=true，程序会自动禁用最大化按钮，只保留帮助按钮。

if help_btn:
    if minimize_btn:
        flags |= Qt.WindowMinimizeButtonHint
    if close_btn or close_btn_close:
        flags |= Qt.WindowCloseButtonHint
    flags |= Qt.WindowContextHelpButtonHint
    # 注意：没有加 WindowMaximizeButtonHint

这是 Qt 的设计——标题栏右侧的位置有限，帮助按钮和最大化按钮二选一。

6.3 全部按钮为 false 的特殊处理

如果模类数据里 minimize_btn / maximize_btn / close_btn 全部为 false，程序会用 Qt.CustomizeWindowHint | Qt.WindowTitleHint 创建窗口。

效果是：标题栏还在，但不显示任何系统按钮。同时程序会禁用系统菜单——右键标题栏不会弹出「移动 / 大小 / 关闭」菜单。

这个设计适合做「假窗口」——看起来像一个真窗口，但用户点不到任何系统按钮，只能看你设计的控件。

6.4 模类框不支持工具窗的哪些配置？

选了工具窗后，这些配置会被忽略：

  • 最大化按钮配参（maximize_btn）—— 工具窗只有关闭按钮。
  • 最小化按钮配参（minimize_btn）—— 同上。
  • 帮助按钮配参（help_btn）—— 工具窗不支持帮助按钮。

只有关闭按钮配参（close_btn / close_btn_close）还生效——但即使 close_btn=false，工具窗还是会显示一个关闭按钮（系统强制），只是点它会不会真的关闭由 close_btn_close 决定。

七、模类框的关闭流程：六步走

模类框的关闭流程和其他窗口不一样。普通弹窗走的是 close_window()，模类框走的是 _close_class_window_with_animation()。这个函数做了六件事：

7.1 第一步：防重入

设置 _is_closing = True。如果已经设置了，直接 return，防止重复关闭（比如用户连点两次关闭按钮）。

7.2 第二步：释放阵列槽位

如果模类框的编组被阵列接管（_array_group_name 非空），调用 array_runtime.release_slot(id(class_window)) 释放槽位。

为什么放在最前面？因为释放槽位是「原子操作」，无论后面有没有动画、有没有异常，槽位都必须释放。放在前面最安全。

7.3 第三步：处理 hard_flash 出场

如果出场动画是 hard_flash，先设置 _hard_flash_active = True。

这一步很关键。因为 hard_flash 的实现方式是 hide() / show() 切换，而 show() 会触发 showEvent。如果 showEvent 里又播入场动画，就和 hard_flash 叠加了，节奏乱套。

设置 _hard_flash_active 后，showEvent 会检查这个标志，如果为 True 就跳过入场动画。

7.4 第四步：播放出场动画

如果配置了 transition.exit，调用 transition_manager.play_exit_animation。动画完成后执行回调 on_exit_complete。

如果没有配置 transition，直接走第五步。

7.5 第五步：清理注册信息

动画完成后，清理窗口在 Itoc 窗口系统里的所有注册信息：

  • 从 command_executor.window_classes[window_class] 里移除
  • 从 named_windows[window_class] 里删除
  • 从 command_executor.window_groups[window_group] 里移除，如果编组空了就删掉整个编组
  • 从 current_windows 里移除

这一步是必须的——不清理的话，全局命令会继续「找到」这个已经关闭的窗口，操作会报错或者产生诡异行为。

7.6 第六步：真正 close

清理完注册信息后，调用 class_window.close()。这会触发 Qt 的 closeEvent。

但注意：closeEvent 被重写过了（custom_close_event）。它先检查 _is_closing： - 如果为 True，直接 event.accept()，正常关闭。 - 如果为 False，event.ignore()，然后调用 _close_class_window_with_animation。

所以第一次点关闭按钮时，_is_closing 是 False，触发动画流程；动画完成后 _is_closing 是 True，再 close 就是正常关闭。这个递归设计保证了「点关闭按钮 = 播动画 + 关闭」，而不是「点关闭按钮 = 直接关闭」。

7.7 关闭流程的完整时序图

用户点关闭按钮
  ↓
closeEvent 被触发
  ↓
检查 _is_closing
  ├─ False → event.ignore() → _close_class_window_with_animation()
  │           ├─ _is_closing = True
  │           ├─ 释放阵列槽位
  │           ├─ 处理 hard_flash 标记
  │           ├─ 播出场动画
  │           ├─ 动画完成 → 清理注册信息
  │           └─ class_window.close()
  │                 ↓
  │               closeEvent 再次触发
  │                 ↓
  │               检查 _is_closing = True
  │                 ↓
  │               event.accept() → 真正关闭
  │
  └─ True → event.accept() → 真正关闭

八、模类框与阵列 / 编组 / 镜像克隆

模类框虽然结构特殊，但它仍然是一个「真实窗口」，所以它能参与 Itoc 的窗口管理系统。这一节讲模类框和这几个系统的联动。

8.1 阵列接管

如果模类框的编组被阵列接管了（array_runtime.is_group_captured(window_group) 返回 True），程序会在创建窗口前先分配一个槽位：

  1. 调用 array_runtime.allocate_slot(window_group, 临时 popup_id) 拿槽位和绿点坐标。
  2. 用绿点坐标覆盖 window_position 计算出的位置。
  3. 窗口创建后，用实际尺寸重新计算左上角（绿点是中心点，要减去宽高的一半）。
  4. 把临时 popup_id 换成真实 id（id(class_window)），重新登记到 popup_slot_map。
  5. 给窗口打上 _array_group_name 和 _array_slot_index 标记。

关闭时会调用 release_slot 释放槽位（第七节讲过）。

💡 模类框的阵列位置补偿：
普通弹窗有「标题栏补偿」（因为窗口位置是内容区左上角，实际窗口位置要往下偏一个标题栏高度）。模类框也有这个补偿，但补偿逻辑在 create_class_popup 里：_real_y = int(_slot_point[1] - window_height / 2) 之后，没有额外加标题栏高度——因为模类框的 height 是从模类数据里读的，已经包含了标题栏。

8.2 编组

模类框会注册到 window_group 指定的编组里。这意味着它可以被「按编组关闭弹窗」和「按编组位移动画」操作。

编组注册的时机是在窗口创建后、显示前：

if window_group:
    self.command_executor.register_window_group(class_window, window_group)

8.3 镜像克隆

模类框也参与镜像克隆。当源编组弹出一个模类框时，_trigger_mirror_clone_followers 会被调用，为每个监听器创建一个克隆体。

克隆体也是一个模类框，但它的 window_class 会变成 {原类名}@{目标编组}#{计数器}，避免和源冲突。位置会根据 note_offset 偏移，保持源编组的相对形状。

模类框的克隆体同样需要点「应用」保存到音符，不会自动写回。

8.4 销毁即脱壳

模类框支持「销毁即脱壳」模式。如果类名的销毁模式设为 shell，窗口关闭前会把几何信息（位置、宽高）存到 _class_geometry_cache。之后如果有别的窗口「链接」到这个类名，即使它已经关闭，也能用缓存里的坐标算链接位置。

脱壳几何信息的保存时机在 _close_class_window_with_animation 里，但它不是直接存，而是通过 transition_manager._save_geometry_for_shell_mode(class_window) 间接保存——这样代码逻辑统一。

九、模类框和 CZEmaker 其他控件的交互

模类框除了禁用一堆控件，还和其他控件有联动。这一节讲清楚。

9.1 透明度

模类框的透明度由 window_opacity 字段控制。在面板里填 0-100，运行时用 class_window.setWindowOpacity(window_opacity / 100) 应用。

注意：透明度作用在整个窗口上，包括模类里的所有控件。所以设 50% 的话，模类里的按钮、标签、图片都会变成半透明。

9.2 窗口寿命

模类框支持 window_life。如果勾了寿命，窗口创建后会用 QTimer.singleShot(life_ms, close_func) 定时关闭。

但这里有个特殊处理：模类框的寿命定时器会在入场动画完成后才启动（QTimer.singleShot(int(window_life_ms), lambda: self._close_class_window_with_animation(...))）。如果入场动画还没播完就到寿命，动画会被打断，窗口直接关闭。

9.3 位置模式

模类框支持全部四种位置模式（屏幕坐标、屏幕对齐、窗口链接、屏幕随机）。位置计算走 calculate_position，和普通弹窗一致。

但有一点不同：模类框的位置计算会传入 actual_size=(window_width, window_height)，其中宽高是从模类数据里读的。这样「屏幕对齐」的居中计算会以模类的实际尺寸为准，而不是普通弹窗的默认尺寸。

9.4 过渡动画

模类框支持全部过渡动画类型。展开类动画（expand_*）需要目标矩形，程序会从模类数据的 width / height 算出来，所以展开动画在模类框上也能正常工作。

入场动画的触发时机是 class_window.show() 之后，通过 QTimer.singleShot(50, play_anim) 延迟 50ms 播放——这是为了让窗口先完成布局，动画的起点位置才准确。

9.5 类名

模类框支持 window_class。如果配置了类名，窗口会注册到 window_classes 和 named_windows 里，可以按类名查找、关闭、移动。

但注意：模类框的 window_class 和模类名称（selected_class_name）是两个不同的东西。前者是「窗口类名」（用于窗口链接、全局命令），后者是「模类名称」（用于选择模板）。别搞混了。

十、配置文件字段一览

模类框在音符的 cze_makers 里保存这些字段：

字段名类型说明备注
window_type string UIclass / class / 模类框 三种写法都兼容
selected_class_name string 选中的模类名称 对应下拉框选中的值
window_title string 窗口标题 从模类数据的 name 字段读
window_group string 所在编组 用于编组管理、阵列接管
window_class string 窗口类名 用于窗口链接、全局命令
window_class_destroy_mode string 销毁模式 destroy / shell
window_life dict 窗口寿命 从模类数据读，可能被覆盖
window_position dict 窗口位置 四种模式之一
window_opacity string 透明度 0-100 作用在整个窗口上
window_sound string 效果音 default / info / …
window_icon string 图标风格 模类框下被禁用，不生效
window_control / window_control_detail string / dict 控制钮配置 模类框下被禁用，不生效
window_button / window_button_detail string / dict 按钮区配置 模类框下被禁用，不生效
custom_size_enabled / custom_width / custom_height bool / int / int 自定义尺寸 模类框强制禁用，不保存
window_content string 窗口内容 模类框不保存（内容就是控件列表）
window_style string 窗口样式 以模类数据为准，CZEmakers 侧不参与决策

window_opacity string 透明度 0-100 以模类数据为准，作用在整个窗口上

表格里用「以模类数据为准」标记的这几行，意思是：外观相关的字段（样式 / 背景 / 亚克力 / 置顶 / 透明度）读的是模类文件 .UIclass 的顶层字段，不是音符的 cze_makers。CZEmakers 面板里对应的控件在模类框下也会被禁用（和图标 / 控制钮 / 按钮区一样）。

用「不生效也不保存」标记的最后几行（window_content / custom_size_*），是彻底不用管——就算你手写了也不会被用到。模类数据里从来没有这些字段。

十二、模类框的完整工作流

这里给你一个「从零开始做一个模类框弹窗」的完整流程，可以作为实操指南：

  1. 做模类（在模类设计器里）
    新建 → 拖控件 → 调属性 → 预览 → 保存到工程内置（或「以上两者都保存」）
    详见 初识模类 和 模类设计器详解
  2. 选中音符，切到模类框
    在时间轴上选中一个音符 → CZEmaker 面板 → 窗口类型选「模类框」
  3. 选模类
    「选择模类」下拉框 → 选中你刚做的模类 → 等待加载完成（状态标签显示「已加载模类: xxx」）
  4. 配外围配置
    位置（四种模式）、寿命、透明度、效果音、编组、类名、销毁模式
  5. 点应用
    点「应用 (Insert)」保存到音符。多选时走智能更新，只更新你改过的字段。
  6. 测试运行
    按 F5 测试运行，看弹窗效果对不对。不满意就回模类设计器改，改完重新加载。
  7. 批量复用（可选）
    如果多个音符要挂同一个模类配参，可以「另存为配参文件」→「使用 czemaker(配参)赋值」批量挂。
  8. 编译 exe
    一切正常后编译成 exe，模类数据会跟着工程一起打包。

十三、常见问题（CZEmaker 视角）

Q1：切到模类框后，图标/控制钮/按钮区全灰了，是坏了吗？

A：不是坏了，是设计如此。这些配置项在模类框下不生效，程序主动禁用了它们。详见第三节「切换成模类框后，面板发生了哪些变化」。

Q2：我选了模类，但弹窗没出现？

A：按顺序检查：

  1. 是否点了「应用 (Insert)」？选择模类不会自动保存，必须点应用。
  2. 模类数据里的 width / height 是否有效（大于 0）？
  3. 模类数据是否损坏（JSON 解析失败）？看控制台有没有「未找到模类数据」。
  4. 如果选的是全局模类，复制到工程是否成功？看进度条有没有跑到 100%。
  5. 运行时是不是只读工程内置模类？如果模类只在全局文件夹里，运行时会找不到。

Q3：选了全局模类，复制进度条卡住了？

A：复制超时是 300 秒（大文件时会比较久）。如果超过 300 秒还没完成，会放弃复制，走兜底：尝试加载原始全局模类（只读预览），并标记已修改。你可以手动去模类管理器里用「克隆到工程内置」重新导入。

Q4：模类框的内容框为什么不能编辑？

A：正常。模类框的内容是控件列表，只读展示。想改控件，去模类设计器里改，改完重新加载模类。

Q5：模类框的自定义尺寸为什么是灰的？

A：模类框强制禁用自定义尺寸，因为窗口大小由模类数据的 width / height 决定。想改大小，去模类设计器里改。

Q6：模类的关闭按钮点了没反应？

A：检查模类数据里的 close_btn_close 字段。如果它是 false，点关闭按钮不会关闭窗口，只会触发 closeEvent。这是模类设计器的一个选项，可能是故意设的（比如让用户必须点某个「确定」按钮才能关）。

Q7：模类框的窗口标题为什么改不了？

A：模类框的窗口标题输入框是禁用的，标题从模类数据的 name 字段读。想改标题，去模类设计器里改模类的 name。

Q8：模类框能参与阵列吗？

A：能。如果编组被阵列接管，模类框会分配槽位、按绿点定位。关闭时释放槽位。详见第八节「模类框与阵列 / 编组 / 镜像克隆」。

Q9：模类框能镜像克隆吗？

A：能。源编组弹出一个模类框时，会触发镜像克隆监听器，为每个监听器创建一个克隆体。克隆体的类名会加后缀避免冲突。

Q10：模类框的过渡动画正常吗？

A：正常。入场动画在 show() 之后延迟 50ms 播放，出场动画在 _close_class_window_with_animation 里播放。展开类动画会从模类数据的宽高算目标矩形，所以也能正常工作。

Q11：模类框能不能用亚克力？

A：能，但要看模类数据的背景色设置。如果模类数据里 bg_color 是不透明的颜色，亚克力会在背景之上叠加，效果可能不太理想。如果 bg_color 是透明的，亚克力就能正常显示。详见 亚克力与云母。

Q12：模类框能镂空吗？

A：支持「窗口背景镂空」，不支持「图片镂空」。这两种镂空在 Itoc 里是两回事：

  • 窗口背景镂空（模类框 ✅ 支持）：把 window_background 设成假、window_style 设成 borderless，窗口背景就是真透明（WA_TranslucentBackground）；如果 window_style 不是 borderless，会走色键透明（paintEvent 填 (1,2,3) + SetLayeredWindowAttributes）。两种方式都只让「窗口背景」透明，窗口里的控件本身不透明。
  • 图片镂空（模类框 ❌ 不支持）：那是图片框专属的「图片色度抠图 / 透明通道」功能，模类框里的图片控件是 QLabel，不支持色度抠图。

所以如果你想让模类框「窗口本身透明，只显示控件」，用第一种就行。详见 镂空窗口 的「窗口背景镂空」小节。

Q13：模类框支持工具窗样式吗？

A：支持，但会限制按钮显示（只保留关闭按钮）。详见第六节「模类框 + 样式钮：谁说了算」。

Q14：模类框的窗口内容会保存到配置文件吗？

A：不会。模类框不保存 window_content——因为内容就是控件列表，不需要额外存文字。如果你在配置里手写了 window_content，运行时会忽略它。

这篇文档从 CZEmaker 面板的视角，把模类框这个窗口类型讲了一遍。核心要点：

  • 前置阅读：模类是什么、怎么做模类，看 初识模类 / 模类设计器详解 / 模类进阶与生态。
  • 面板变化：图标 / 控制钮 / 按钮区 / 窗口标题 / 窗口内容 / 自定义尺寸被禁用，选择模类下拉框插在窗口标题行第一位。
  • 选择流程：全局模类会自动复制到工程（带进度条、哈希去重、后台线程），工程内置模类直接加载。选择不会自动保存，必须点「应用」。
  • 内容框：显示控件列表，格式是「序号 + 类型 + 名称 + 文本」，只读展示。
  • 样式钮优先级：borderless 忽略所有按钮配参，tool_fixed 只保留关闭按钮，normal_fixed 按模类数据 + 面板配置组合。
  • 关闭流程：六步走（防重入 → 释放阵列槽位 → 处理 hard_flash → 播出场动画 → 清理注册 → 真正 close）。
  • 阵列 / 编组 / 镜像克隆：模类框都支持，因为它是真实窗口。
  • 不生效字段：window_content、custom_size_enabled、window_icon、window_control、window_button 在模类框下不生效。
  • 外观以模类数据为准：window_style / window_background / window_material / window_topmost / window_opacity 这五个字段，CZEmakers 侧不参与决策，改要去模类设计器的窗口属性面板改。
  • 支持窗口背景镂空：把 window_background 关掉即可（borderless 走真透明，其他样式走色键透明）。但不支持图片镂空（那是图片框专属的色度抠图 / 透明通道功能）。

模类框是 Itoc 里最自由、也最复杂的窗口类型。它的复杂性不在于「用法难」，而在于「它和模类设计器、模类管理器、CZEmaker 面板、全局命令系统都有交叉」。搞清楚了这些交叉关系，你就能把模类框玩得飞起喵 ( ⓛ ω ⓛ *)
