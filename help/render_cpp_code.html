🧱 渲染为 C++ 代码

「渲染为 C++ 代码」是 Itoc 提供给开发者的一个数据导出功能：把工程里的音符、全局命令、BPM 等信息，转换成一份 C++ 源码文件（.cpp）。这份源码里嵌入了一个巨大的 JSON 字符串，C++ 程序运行时用 QJsonDocument::fromJson 解析它，就能拿到工程数据。

💡 一句话理解：
它和「渲染为 Python 代码」是兄弟功能，只是输出的不是 .py，而是 .cpp。
生成的文件本身不是可执行程序，只是一份带数据的 C++ 源码。
⚠️ 2.0 版本的重要限制：
Itoc 2.0 暂不支持直接把 C++ 代码编译成可执行文件（exe）。
菜单里的「渲染为 C++ 代码」只负责生成 .cpp 源码，不会像「编译为 exe」那样自动调用编译器。
想得到能跑的 exe，需要你自己准备 MSYS2 UCRT64 + Qt5 环境，手动编译。具体依赖管理请配合阅读 《C++ 运行库》。

一、这个功能是干嘛的？

Itoc 工程文件（.czemidi）本质上是 JSON 数据。渲染为 C++ 代码，就是把这堆 JSON 数据“塞进”一份 C++ 模板里，生成一个可以直接用 C++ 编译器编译的源文件。

生成的 .cpp 文件大致长这样：

// ============================================================================
// CzePlayer - runCZE.py的C++版本
// ============================================================================
#include <QApplication>
#include <QWidget>
#include <QJsonDocument>
#include <QJsonObject>
#include <QJsonArray>
// ...其它 Qt 头文件...

const char* CZEDATA_CONTENT = R"ITOC_JSON({
    "version": "2.0",
    "source_project": "我的工程.czemidi",
    "render_time": "2026-10-22 13:00:00",
    "render_bpm": 120,
    "notes": [
        {
            "note_value": 60,
            "start_s": 0.0,
            "duration_s": 0.5,
            "end_s": 0.5,
            "cze_makers": { ... }
        }
    ],
    "global_commands": [ ... ]
})ITOC_JSON";

int main(int argc, char *argv[]) {
    QApplication a(argc, argv);
    QJsonDocument doc = QJsonDocument::fromJson(QByteArray(CZEDATA_CONTENT));
    if (doc.isNull() || !doc.isObject()) {
        return 1;
    }
    // TODO: 创建播放器窗口并加载数据
    return a.exec();
}

注意这里用了 C++11 的原始字符串字面量 R"ITOC_JSON(...)ITOC_JSON"，目的是避免 JSON 里的引号、反斜杠、换行被 C++ 编译器当成转义字符处理。这是这个功能最核心的实现细节。

二、从哪里打开？

菜单位置：「渲染(R)」 → 「渲染为C++代码」。

目前没有默认快捷键，建议从菜单打开。

💡 别和「渲染为 Python 代码」搞混：
· 「渲染为 Python 代码」→ 生成 .py，可以配合 Python 解释器或 PyInstaller 使用。
· 「渲染为 C++ 代码」→ 生成 .cpp，需要 C++ 编译器和 Qt5 环境。
两个入口都在「渲染(R)」菜单里，但输出目标完全不同。

前置条件

检查项不满足时的提示怎么解决
是否有打开的工程“请先打开或保存一个工程文件”先新建或打开一个工程
工程里是否有音符“当前工程没有音符数据”先在时间轴上画几个音符
模板文件是否存在“无法加载模板文件”检查 runCZE/runCZEcpp.cpp 是否存在

如果工程已经改过（标题栏工程名带 *），会先弹确认框，建议先保存再渲染，避免导出的数据不是最新的。

三、窗口界面

窗口是左右分栏布局：

区域内容
左栏工程信息、BPM 设置、选项、底部按钮
右栏上部数据预览表格（音符、命令列表）
右栏下部C++ 代码预览（深色背景，带简单语法高亮）

3.1 工程信息

显示当前工程的文件名、音符数量、命令数量、目标 BPM。这些信息是只读的，帮你确认打开的是正确的工程。

3.2 BPM 设置

一个输入框，让你设置渲染时使用的 BPM。默认是工程当前的 target_bpm。旁边会实时显示“每拍多少秒”。

BPM 决定了节拍到秒的换算关系。修改 BPM 后，音符和命令的时间都会按新 BPM 重新换算。

3.3 选项

选项默认说明
包含CZEmaker勾选是否把音符的 CZEmaker 配置（弹窗参数）一起写进 C++ 代码
包含全局命令勾选是否把全局命令一起写进 C++ 代码
💡 选项怎么选：
· 如果你只是想要一份能用的数据，保持默认即可。
· 如果你不需要弹窗配置，可以取消“包含CZEmaker”，代码会更小。
· 如果你不需要全局命令，可以取消“包含全局命令”。

3.4 数据预览

右栏上部是一个表格，显示转换后的音符和命令数据。表格列包括：序号、类型、音高/描述、时间(s)、时长(s)、结束(s)。

点击「刷新预览」按钮可以重新生成预览。修改 BPM 或选项后，预览不会自动刷新，需要手动点一下「刷新预览」。

3.5 代码预览

右栏下部是生成的 C++ 代码预览，深色背景，关键字、字符串、数字、注释有简单的颜色区分。

代码预览显示的是最终会保存的内容。如果你修改了 BPM 或选项，点「刷新预览」后代码预览也会更新。

3.6 底部按钮

按钮作用
开始渲染生成最终 C++ 代码，并弹出保存对话框
取消关闭窗口，不生成文件
刷新预览用当前设置重新生成预览

四、操作步骤

  1. 打开一个包含音符的工程。
  2. 点击菜单「渲染(R)」→「渲染为C++代码」。
  3. 如果工程已修改，按提示选择是否保存。
  4. 在窗口里调整 BPM 和选项（一般保持默认即可）。
  5. 点「刷新预览」查看转换后的数据和代码。
  6. 确认无误后，点「开始渲染」。
  7. 在弹出的保存对话框里选择保存位置，默认文件名是 工程名_render.cpp。
  8. 保存成功后，轮播图会显示「C++代码已成功生成！」。

五、生成结果

生成的 .cpp 文件是一个完整的 C++ 源码，里面包含一个 CZEDATA_CONTENT 变量，存储了工程的所有数据。

具体内容取决于你勾选的选项：

  • 勾选「包含CZEmaker」→ 每个音符里会有 cze_makers 字段
  • 勾选「包含全局命令」→ 会有 global_commands 字段
📌 数据格式说明：
嵌入的 JSON 是标准 JSON，不是 C++ 字面量。之所以用 R"ITOC_JSON(...)ITOC_JSON" 包住，是为了让 C++ 编译器把里面的引号、反斜杠、换行原样保留，运行时再由 QJsonDocument::fromJson 解析。

六、重要：2.0 版本不支持直接编译为 exe

这是这篇文档最需要强调的一点：

⚠️ Itoc 2.0 的「渲染为 C++ 代码」只生成源码，不生成可执行文件。
它不会自动调用 g++ / qmake / CMake，也不会帮你打包 Qt5 运行库。
想得到能双击运行的 .exe，需要你自己准备编译环境并手动编译。

6.1 手动编译需要什么？

组件推荐说明
编译环境MSYS2 UCRT64提供 g++、pacman、Qt5 等工具链
GUI 框架Qt5（mingw-w64-ucrt-x86_64-qt5）模板里用到了 QApplication、QWidget、QJsonDocument 等
其它依赖opencv / SDL2 / boost（按需）取决于模板里 #include 了哪些头文件

依赖的安装和管理，请配合阅读 《C++ 运行库》。那里有「安装C++运行库」「浏览已安装的C++运行库」「检查未安装的C++运行库」三个工具，能帮你把缺的包补上。

6.2 大致编译流程

下面只是一个示意流程，实际编译命令取决于你的模板和项目结构：

# 1. 打开 MSYS2 UCRT64 终端
# 2. 安装 Qt5 和编译工具
pacman -S --noconfirm mingw-w64-ucrt-x86_64-qt5
pacman -S --noconfirm mingw-w64-ucrt-x86_64-gcc

# 3. 进入你保存 .cpp 的目录
cd /d/你的工程目录

# 4. 编译（示意，具体参数以模板为准）
g++ 我的工程_render.cpp -o MyPlayer.exe \
    -IC:/msys64/ucrt64/include \
    -LC:/msys64/ucrt64/lib \
    -lQt5Core -lQt5Gui -lQt5Widgets

# 5. 运行
./MyPlayer.exe
⚠️ 上面的命令只是示意：
Qt 项目通常推荐用 qmake 或 CMake 管理，而不是手写 g++ 命令。
另外，编译出来的 exe 运行时还需要 Qt5 的 DLL（Qt5Core.dll、Qt5Gui.dll、Qt5Widgets.dll 等），需要用 windeployqt 或手动拷贝到 exe 同目录。
这些都属于 C++/Qt 的通用知识，不在 Itoc 文档范围内，建议查阅 Qt 官方文档或 MSYS2 文档。

6.3 为什么 2.0 不直接支持？

简单说：C++ 编译比 Python 打包复杂得多。Python 有 PyInstaller 这种“一键打包”工具，而 C++ 需要处理编译器、链接器、Qt 版本、运行库、DLL 依赖等一整套环境。Itoc 2.0 目前只做到“生成源码”，把编译交给用户自己控制，避免把环境问题绑死在程序里。

七、模板文件

生成的 C++ 代码是基于模板文件 runCZEcpp.cpp 替换占位符得到的。程序会按这个顺序查找模板：

  1. runCZEcpp.cpp（当前目录）
  2. runCZE/runCZEcpp.cpp
  3. 程序目录下的 runCZEcpp.cpp
  4. 程序目录下的 runCZE/runCZEcpp.cpp

如果都找不到，程序会用一个内置的占位模板，里面只有一个空的 CZEDATA_CONTENT 和简单的 main 函数。这个占位模板只能保证“能生成代码”，不能保证“能编译出完整播放器”。

💡 模板里的占位符：
程序会尝试替换以下三种占位符之一：
· // =CzeData=
· =CzeData=
· CZEDATA_CONTENT =
如果你的模板是自己改的，记得保留其中一种占位符，否则数据可能插不进去。

八、常见问题

Q1：生成的 .cpp 能直接双击运行吗？

A：不能。它只是源码，需要编译成 exe 才能运行。而且 2.0 版本 Itoc 不会帮你编译。

Q2：为什么菜单里没有“编译 C++ 为 exe”？

A：2.0 版本暂不支持。目前只有「渲染为 C++ 代码」，编译需要你手动完成。

Q3：生成的代码里没有 CZEmaker 配置？

A：检查「包含CZEmaker」选项有没有勾选。如果没勾选，生成的代码里就不会有 cze_makers 字段。

Q4：BPM 改了，但预览没变？

A：需要手动点一下「刷新预览」按钮。BPM 输入框修改后不会自动刷新预览。

Q5：保存时提示“无法加载模板文件”？

A：说明程序目录下缺少 runCZEcpp.cpp。检查一下 runCZE/ 文件夹里有没有这个文件。如果确实丢了，可以先用内置占位模板生成，但那个模板功能很有限。

Q6：编译时报“找不到 Qt5Core”怎么办？

A：说明 Qt5 没装好，或者编译命令里的 include / lib 路径不对。用 《C++ 运行库》 里的「检查未安装的C++运行库」先看看缺什么，再用 MSYS2 的 pacman 补上。

Q7：编译出来的 exe 双击没反应 / 缺 DLL？

A：Qt 程序运行时需要 Qt5 的 DLL。用 windeployqt 工具把依赖拷到 exe 同目录，或者手动把 Qt5Core.dll、Qt5Gui.dll、Qt5Widgets.dll 等放到 exe 旁边。

Q8：这个功能和“渲染为 CZE 数据文件”有什么区别？

A：

  • .CzeData：给 Itoc 解释器（runCZE）直接读取的数据文件，秒单位。
  • .cpp：给 C++ 开发者用的源码，里面嵌入了 JSON 数据，需要自己编译和实现播放逻辑。

Q9：我可以自己改模板吗？

A：可以。模板就是普通的 .cpp 文件，你可以按自己的播放器结构改。只要保留占位符（// =CzeData= / =CzeData= / CZEDATA_CONTENT = ）之一，生成时数据就会被替换进去。

Q10：为什么生成的 JSON 用 R"ITOC_JSON(...)ITOC_JSON" 包着？

A：因为 JSON 里有大量双引号、反斜杠和换行。如果直接写成普通 C++ 字符串，需要疯狂转义。用 C++11 原始字符串字面量可以原样保留内容，运行时再交给 QJsonDocument::fromJson 解析，最省事也最不容易出错。

九、小结

「渲染为 C++ 代码」是 Itoc 给 C++ 开发者的数据出口：

  • 入口：菜单「渲染(R)」→「渲染为C++代码」
  • 前置条件：有打开的工程 + 有音符数据 + 模板文件存在
  • 把工程数据转成 JSON，嵌入 .cpp 源码
  • 支持包含/排除 CZEmaker、全局命令
  • 生成 .cpp 文件，内含 CZEDATA_CONTENT 变量
  • 2.0 版本不直接编译为 exe，需要 MSYS2 UCRT64 + Qt5 手动编译
  • 依赖管理请配合 《C++ 运行库》

如果你只是想做弹窗演出、分发成品，建议优先用「编译为 exe」或「组装打包模式」；「渲染为 C++ 代码」更适合想用 C++ 二次开发播放器的人喵 ( ⓛ ω ⓛ *)
