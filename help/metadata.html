📇 作品元数据

你辛辛苦苦做了一个弹窗作品，发出去之后，观众看到的是弹窗——但弹窗背后是谁做的、叫什么名字、能不能二创、能不能商用，观众不知道。

「作品元数据」就是干这个的。它是一张作品身份证：把作品名称、作者、头像、个人主页、版权协议、二创/商用授权、附加链接、作品简介全写进去，然后跟着工程一起走。观众在解释器里点「关于该作品」，就能看到这些信息。

这篇把元数据窗口里每个字段、保存机制、运行时展示逻辑全讲清楚。

💡 一句话理解：
作品元数据 = 作品的「署名信息 + 授权协议 + 自我介绍」。
它不影响弹窗怎么弹，只影响观众怎么认识你这个作者。

一、从哪打开

元数据窗口的入口在主程序里。打开方式：

  1. 先打开或新建一个工程——没工程的时候元数据没地方存，程序会弹提示拦住你。
  2. 在菜单栏里找到「作品元数据」相关入口（不同版本菜单位置可能略有差异，一般在「工程」或「文件」菜单下）。
  3. 点开，弹出「作品元数据」窗口。

窗口默认大小 850×680，可以拉伸，最小 760×580。布局是响应式的，你把窗口拉大，左边的输入框和右边的授权区会跟着变宽，下面的「作品简介」会吃满剩余高度。

⚠️ 没打开工程时打不开：
元数据是存在工程文件里的，没工程就没地方存。程序会弹一个「请先打开或新建一个工程，再编辑作品元数据」的提示，这是正常的。

二、界面长什么样

窗口从上到下分四块：

区域内容说明
顶部左栏 作者信息 作品名称、作者、个人主页、头像设置（预览框 + 三种模式）
顶部右栏 作品授权 版权、制作时间、是否允许二创、是否允许商用
中部 附加链接 可增删的「名称 + URL」列表，带滚动条，链接多了不会撑爆窗口
下部 作品简介 多行文本框，带垂直滚动条，吃满剩余高度
底部按钮 导入 JSON / 导出 JSON / 重置为空 / 取消 / 确定并保存到工程 左边三个是工具按钮，右边两个是主操作

三、作者信息

3.1 作品名称

输入框，填作品的名字。比如「我的第一个弹窗作品」「2026 新年快乐」。

默认值： 如果你没填，程序会拿当前工程的文件名（去掉 .czemidi 后缀）当默认值。比如工程叫 demo.czemidi，作品名称就默认是 demo。

这个默认值只在窗口打开时显示，不会自动写进工程——你点了「确定并保存」才算数。

3.2 作者

输入框，填你的名字或昵称。比如「小小电子xxdz」「你的 B 站 ID」。

建议和你的个人主页、头像保持一致，方便观众认出是你。

3.3 个人主页

输入框，填你的主页链接。比如 B 站空间、GitHub、个人博客。

这里有个自动补全机制：点「确定并保存」时，如果填的内容不是以 http:// 或 https:// 开头，程序会弹一个询问框：

个人主页不是以 http(s):// 开头，是否自动补 https://？

你点「是」，程序就自动在前面加 https://；点「否」，就原样保存。

在「关于该作品」窗口里，这个字段是可点击的蓝色链接，观众点一下就能跳过去。

3.4 头像

头像有三种模式，用单选按钮切换：

不设置（none）

不显示头像。预览框显示「无头像」占位文字，浅灰底。

适合「不想露脸 / 不想用头像」的场景。运行时「关于该作品」窗口的头像区也会显示「无头像」。

本地文件（local）

从本地选一张图当头像。点「选择...」按钮，打开文件对话框，支持这些格式：

PNG / JPG / JPEG / GIF / BMP / WEBP。

选完之后，程序会做三件事：

  1. 把图片复制到工程目录的 media/avatar/ 文件夹（目录不存在会自动创建）。
  2. 复制前先算 MD5 哈希，和文件夹里已有的文件比对——内容相同就直接复用，不重复存。
  3. 文件名冲突时自动加数字后缀，比如 avatar_1.png、avatar_2.png，不覆盖旧图。

保存到元数据里的值是相对工程目录的路径，比如 media/avatar/avatar.png。

💡 为什么要复制进工程？
因为工程是要分享/打包的。如果只记一个绝对路径（比如 D:\图片\头像.png），换个电脑就失效了。复制到工程里，头像跟着工程走，观众拿到 exe 也能看到。

预览逻辑： 选完文件后，预览框会立刻加载这张图（缩放到 96×96，保持比例）。如果图片损坏或路径丢失，预览框会显示「预览失败」或「文件丢失」。

网络直链（url）

填一个图片 URL，比如 https://example.com/avatar.png。

输入框有实时预览 + 防抖：你每敲一个字，程序不会立刻去下载，而是等你停止输入 800ms 后才发起请求。这样避免你打一半网址就触发一堆无效请求。

下载时：

  • 限制最大 2MB，超过就显示「文件过大」。
  • 超时 5 秒，超时就显示错误信息。
  • 下载成功后缩放到 96×96 显示在预览框，状态显示「已从网络加载」。

保存到元数据里的值就是完整的 URL。

⚠️ 网络头像的显示依赖网络：
解释器运行时，如果观众的电脑没网、或者图片服务器挂了，「关于该作品」窗口的头像区会显示「加载失败」。这是正常现象，不是 bug。

3.5 头像模式切换的联动

三种模式之间有联动：

  • 切到「不设置」：本地文件路径会被清空，网络 URL 输入框变灰。
  • 切到「本地文件」：网络 URL 输入框变灰，本地文件路径保留。
  • 切到「网络直链」：本地文件路径保留（但预览框切到网络预览），URL 输入框启用。

如果你选了「本地文件」但没选文件，或者选了「网络直链」但没填 URL，保存时程序会自动降级成「不设置」，不会存一个半残的状态。

四、作品授权

4.1 版权

下拉框，可选值：

选项含义
保留所有权利默认。别人要用得找你授权。
CC0公共领域，随便用，不用署名。
CC BY署名即可商用/二创。
CC BY-NC署名 + 非商用。
CC BY-NC-SA署名 + 非商用 + 相同方式共享。
CC BY-SA署名 + 相同方式共享。
CC BY-NC-ND署名 + 非商用 + 禁止演绎。
CC BY-ND署名 + 禁止演绎。

下拉框是可编辑的（state="normal"），也就是说你可以不选预设，直接输入自定义的版权声明，比如「版权所有 © 2026 小小电子xxdz，未经许可禁止转载」。

4.2 制作时间

输入框 + 「现在」按钮。

「现在」按钮点一下，自动填入当前系统时间，格式是 YYYY-MM-DD HH:MM:SS，比如 2026-05-20 14:30:00。

这个字段是纯文本，你可以手动改成「2026 年春节」「去年夏天」这种非标准格式，程序不会校验。

4.3 是否允许二创

三个单选按钮：待定 / 是 / 否。

  • 待定（pending）：默认。没说死，留个活口。
  • 是（yes）：允许别人拿你的作品二次创作。
  • 否（no）：不允许二创。

在「关于该作品」窗口里，这个字段会显示成中文标签（「待定」「是」「否」），不会显示英文键名。

4.4 是否允许商用

同样的三选一：待定 / 是 / 否。

建议和「版权」字段保持一致——比如你选了 CC BY-NC，那商用这里应该选「否」，别自相矛盾。

💡 二创和商用是两件事：
二创 = 别人能不能改你的作品；商用 = 别人能不能拿你的作品赚钱。
两个都选「否」是最保守的；两个都选「是」是最开放的；「待定」适合还在犹豫的情况。

五、附加链接

这是一组「名称 + URL」的列表，用来放作品相关的其他链接。比如：

  • 名称：「B 站视频」 URL：https://www.bilibili.com/video/BV1tD4y1q76D
  • 名称：「源码仓库」 URL：https://github.com/xxdz-Official/xxdz-Itoc
  • 名称：「素材来源」 URL：https://example.com/assets

点「+ 添加一条」会增加一行，每行有三个东西：

  • 名称输入框：宽度 18 字符。
  • URL 输入框：自适应宽度，吃满剩余空间。
  • ✕ 删除按钮：点一下删掉这一行。

链接多了会出现垂直滚动条，不会把窗口撑爆。

保存时：

  • 名称和 URL 都为空的行会被自动丢弃，不会存进元数据。
  • URL 如果不是 http(s):// 开头，和「个人主页」一样，会弹询问框问你要不要补 https://。

在「关于该作品」窗口里，附加链接会显示成一个「附加链接」分组框，每个链接都是可点击的蓝色文字。如果名称没填，就直接显示 URL 本身。

六、作品简介

多行文本框，带垂直滚动条。想写多长写多长，窗口会自动滚动。

内容会原样保存到元数据的 description 字段，在「关于该作品」窗口里显示成一个可滚动的「作品简介」分组框（高度限制在 60~120 像素之间，内容多了滚动查看）。

建议写什么：

  • 作品是干什么的、灵感来源。
  • 用了哪些素材、感谢谁。
  • 操作说明、注意事项。
  • 更新日志、版本号。

七、导入 / 导出 / 重置

7.1 导出 JSON

点「导出 JSON...」，选保存位置，程序会把当前窗口里的所有字段（包括还没点「确定」的修改）写成一个 JSON 文件。

导出的 JSON 是标准格式，ensure_ascii=False，中文直接显示，indent=2，缩进好看。

{
  "work_name": "我的桌面即时表演程序作品",
  "author": "小小电子xxdz",
  "homepage": "https://space.bilibili.com/3461569935575626",
  "avatar_mode": "local",
  "avatar_value": "https://i0.hdslb.com/bfs/face/87e609940c74ed2e7dcf6b2b19b3029f8e1566e1.jpg",
  "extra_links": [
    {"name": "B 站视频", "url": "https://www.bilibili.com/video/BV1tD4y1q76D"}
  ],
  "copyright": "CC BY-NC-SA",
  "created_time": "2026-05-20 14:30:00",
  "allow_second_creation": "yes",
  "allow_commercial": "no",
  "description": "这是我的第一个弹窗作品喵，用了 3 天时间做的",
  "work_intro": ""
}

7.2 导入 JSON

点「导入 JSON...」，选一个 JSON 文件，程序会：

  1. 读文件。
  2. 用 normalize_metadata 洗一遍——缺的字段补默认值、多的字段丢掉、类型不对的强制转成合法值。
  3. 把洗好的数据填进窗口。

所以哪怕你导入一个只有 {"author": "xxx"} 的残缺 JSON，也能正常导入，其他字段用默认值。

💡 导入不自动保存：
导入只是把数据填进窗口，你还需要点「确定并保存到工程」才会写进工程文件。这样你可以先导入看看，不满意再取消。

7.3 重置为空

点「重置为空」，会弹确认框「确定要清空当前所有元数据吗？」。点「是」之后：

  • 所有输入框清空。
  • 头像模式回到「不设置」。
  • 附加链接全部删掉。
  • 二创/商用回到「待定」。
  • 作品名称重置成工程文件名（不是完全空）。

注意：重置只是清空窗口里的内容，不会立刻写进工程。你还需要点「确定并保存到工程」才会真正生效。

八、保存机制

点「确定并保存到工程」时，程序按这个顺序干活：

  1. 从窗口里收集所有字段，拼成一个字典。
  2. 检查「个人主页」和「附加链接」的 URL，不是 http(s):// 开头的弹询问框。
  3. 用 normalize_metadata 洗一遍，保证字段完整、类型正确。
  4. 先保存撤销快照（save_undo_snapshot_before_modify("编辑作品元数据")）。
  5. 把新元数据写进 app.project_metadata。
  6. 标记工程已修改（标题栏的「已编辑*」亮起来）。
  7. 在轮播图上弹一个「作品元数据已保存」的通知（2 秒）。
  8. 控制台打印一行日志：[MetaData] 元数据已写回工程：work_name=... author=...
💡 撤销快照的时机：
先存快照、再写新值——这样撤销的时候能回到「改之前」的状态。顺序反了的话，撤销会撤到「改之后」，等于没撤。

8.1 元数据存在工程文件的哪

存在工程文件的 project_metadata 字段里。渲染 CzeData 时，它会原样搬到 CzeData 的 metadata 字段。

解释器（runCZE）启动时，从 CzeData 的 metadata 字段读到 self.metadata，然后在两个地方用：

  1. 启动日志（控制台打印作品信息）。
  2. 系统托盘菜单 →「关于该作品」窗口。

九、运行时：观众看到什么

9.1 启动日志

解释器启动时，如果 CzeData 里带 metadata，控制台会打印：

==================================================
[作品信息] 作品名称: 我的作品
[作品信息] 作者: 小小电子xxdz
[作品信息] 制作时间: 2026-05-20 14:30:00
[作品信息] 版权: CC BY-NC-SA
==================================================

如果没设置元数据，会打印「该作品未设置元数据」。

这些日志只在有控制台的时候能看到（测试运行、编译时保留控制台的 exe）。普通用户双击 exe 是看不到的，所以别指望用日志做「给观众看」的信息展示。

9.2 「关于该作品」窗口

这是观众真正能看到的东西。入口在系统托盘图标上：

  1. 右键托盘图标，弹出菜单。
  2. 菜单里有「本程序使用 xxdz Itoc 编写」「关于该作品」「退出」三项。
  3. 点「关于该作品」，弹出窗口。

窗口长这样：

  • 左上角：96×96 的头像框。本地头像直接加载；网络头像异步下载，下载中显示「加载中...」，失败显示「加载失败」。
  • 右上区域：作品名称、作者、个人主页（蓝色可点击）、是否允许二创、是否允许商用、版权、制作时间。
  • 中部：附加链接分组框（如果有链接）。每个链接都是可点击的蓝色文字。
  • 下部：作品简介分组框，可滚动查看。
  • 底部：一个「关闭」按钮。
  • 标题栏右上角：有一个 ? 按钮，点它或者按 Shift+F1，会显示「本软件使用 xxdz_Itoc 开发~」的提示。

窗口是置顶的（WindowStaysOnTopHint），不会被其他窗口挡住。

💡 关于该作品窗口的字体：
整个窗口用的是「Microsoft YaHei」9 号字。如果你的系统没装这个字体，Qt 会自动回退到系统默认字体，不会乱码。

9.3 头像加载的细节

本地头像：

  • 用 player.find_image_file(avatar_value) 查找。
  • 查找顺序：直接路径 → <exe目录>/img/文件名 → <cwd>/img/文件名 → <exe目录>/文件名 → <cwd>/文件名 → 文件名本身。
  • 找不到就显示「文件丢失」。

网络头像：

  • 异步下载，不阻塞 UI。
  • 有缓存（_AVATAR_CACHE），同一个 URL 只下载一次。
  • 如果 URL 以 .avif 结尾，会自动把后缀改成 .jpg 再请求（因为 Qt 默认不带 AVIF 解码器）。
  • 如果 URL 是 http://，会自动升级成 https://。
  • 带 User-Agent 和 Referer: https://www.bilibili.com/，方便拉 B 站头像。

十一、常见问题

Q1：元数据窗口打不开，提示「请先打开或新建工程」？

A：正常。元数据存在工程文件里，没工程就没地方存。先 Ctrl+N 新建一个，或者打开一个已有的 .czemidi。

Q2：本地头像选完了，预览框显示「文件丢失」？

A：可能原因：① 图片被手动删了；② 工程被移动后，media/avatar/ 目录没跟着走；③ 路径解析出错。检查工程目录下有没有 media/avatar/ 文件夹，里面有没有那张图。

Q3：网络头像一直显示「加载中...」？

A：可能原因：① 网络慢/超时（5 秒超时）；② 图片服务器挂了；③ URL 写错了；④ 图片大于 2MB 被拒绝。看控制台有没有下载失败的日志。

Q4：作品名称不填会怎样？

A：窗口打开时默认填工程文件名（去掉扩展名）。如果你手动清空，保存后就是空字符串——「关于该作品」窗口里会显示空白，不影响运行。

Q5：个人主页填了「space.bilibili.com/xxx」没带 https，会怎样？

A：点「确定并保存」时会弹询问框「是否自动补 https://？」，点「是」就自动补全，点「否」就原样保存（但「关于该作品」窗口里点它可能跳转失败）。

Q6：附加链接的「名称」可以不填吗？

A：可以。名称空着，URL 填了，「关于该作品」窗口里就直接显示 URL 本身当链接文字。如果名称和 URL 都空着，这一行保存时会被丢弃。

Q7：二创和商用选「待定」是什么意思？

A：「待定」就是「还没想好」。观众看到的是「待定」，知道你还没决定。适合还在犹豫、或者想之后再改的情况。

Q8：元数据会跟着工程一起被撤销吗？

A：会。保存元数据时会先存撤销快照，按 Ctrl+Z 可以撤回到修改前的状态。

Q9：导出的 JSON 能直接给别人用吗？

A：能。别人打开自己的工程，点「导入 JSON...」选你给的文件，就能把元数据搬过去。注意本地头像的路径是相对路径，如果对方工程里没有 media/avatar/ 那张图，导入后会显示「文件丢失」——需要把图片一起给对方。

Q10：编译成 exe 后，元数据还在吗？

A：在。元数据存在 CzeData 的 metadata 字段里，编译时会被打包进去。但本地头像文件需要你手动确保它在 exe 同级目录的 media/avatar/ 下，否则「关于该作品」窗口会显示「文件丢失」。

Q11：「关于该作品」窗口的 ? 按钮是干嘛的？

A：点它（或者按 Shift+F1）会弹一个「这是什么」提示，内容是「本软件使用 xxdz_Itoc 开发~」。这是给观众看的开发工具署名。

Q12：为什么启动日志里打印了作品信息，但观众看不到？

A：启动日志打在控制台上。普通用户双击 exe 时没有控制台，所以看不到。观众能看到的只有托盘菜单里的「关于该作品」窗口。

Q13：作品简介写太长会怎样？

A：不会怎样。保存时原样存，运行时「关于该作品」窗口里会显示成一个高度 60~120 像素的滚动区域，内容多了滚动查看。

Q14：元数据里的 work_intro 是什么？

A：旧版字段，现在 UI 已经不显示了。程序会把它保留在数据结构里（默认空字符串），但不会读取、不会展示。你不需要管它。

十二、小结

作品元数据的五件事：

  1. 是什么：作品的身份证——名称、作者、头像、版权、授权、链接、简介。
  2. 怎么填：打开元数据窗口，逐项填写，点「确定并保存到工程」。
  3. 存哪：工程文件的 project_metadata 字段 → 渲染到 CzeData 的 metadata 字段。
  4. 谁看：观众右键托盘图标 →「关于该作品」，看到头像、作者信息、授权、链接、简介。
  5. 注意：本地头像会复制进工程 media/avatar/；网络头像运行时异步下载；URL 没写协议会询问补 https://。

记住几个关键点：元数据不影响弹窗怎么弹，只影响观众怎么认识你；本地头像跟着工程走，网络头像依赖网络；保存有撤销快照，改错了能撤回。把这些填好，你的作品就有了正式的「署名」了喵 ( ⓛ ω ⓛ *)
