🎵 渲染为音频文件

前面我们讲了 CZEmaker 弹窗、全局命令、音符块、调整图层、过渡动画、批量赋音效。现在讲一个输出环节的重头戏——渲染为音频文件。它能把整份 Itoc 工程"弹奏"成一个音频文件（WAV / FLAC / MP3 / OGG），供你播放、分享、上传，或者作为视频渲染的音频轨。

📌 本篇的范围：
讲的是音频渲染窗口的入口、前置条件、参数、音源、范围、波形预览、进度日志，以及它对工程文件的使用方式。关于视频渲染的完整流程（含音频渲染 + 视频合成），请参考《渲染视频文件》；关于音效怎么批量挂在音符上，请参考《根据窗口类型赋予自定义音效》。

一、这个功能是干嘛的？

简单说，就是把工程"跑一遍"，把所有音符在时间轴上该响的声音合成为一段音频波形，然后编码成一个音频文件。

举个例子：

  • 你在工程里画了一堆音符，每个音符代表一个弹窗弹出的时刻，并带一个音高
  • 你在某几个音符上挂了自定义音效（比如"叮"的一声）
  • 你还导入了一段背景音乐

点"开始渲染"之后，程序会按时间轴把所有音符的声音叠加在一起，混入背景音乐，输出成一个完整音频。

它跟"弹窗播放器"是两条独立的路径：

弹窗播放器音频渲染
输出屏幕上的弹窗 + 声音一个音频文件
用途实时预览、演出成品、分享、视频音轨
是否可暂停不可可随时取消

二、从哪里打开？

菜单位置：「渲染(R)」 → 「渲染为音频文件」。

快捷键：Ctrl + Alt + E。

💡 别找错了：
「渲染(R)」菜单里有好几项，音频渲染是第三项（前两项分别是"渲染为CZE数据文件"和"渲染为Python代码"）。
旁边还有一个「渲染视频文件」，Ctrl + Alt + V，那个走的是视频流程，最终会调用视频渲染器。
两个窗口长得有点像（都是左右分栏），但视频模式多了一列"视频渲染"设置，左栏按钮文字也是"开始渲染视频"。

三、前置条件

打开渲染窗口前，程序会先检查三件事。任何一条不满足都会弹提示，窗口不会打开。

检查项不满足时的提示怎么解决
是否有打开的工程"请先打开或保存一个工程文件"用「文件 → 新建空白工程」或「文件 → 打开工程文件」先弄一个工程
工程里是否有音符"当前工程没有音符数据，无法导出音频"先在时间轴上画几个音符，或者加载一个 MIDI
音频引擎是否初始化成功"音频引擎未初始化，无法导出音频"一般是 pygame 没装好或声卡被独占，重启程序试试

如果工程已经改过（标题栏工程名带 *），还会先弹一个确认框：

  • 是：先保存工程，再打开渲染窗口（保存期间会等异步写盘完成）
  • 否：再弹一个"工程未保存，是否继续导出"，确认后才打开渲染窗口

这里之所以强制先保存，是因为渲染过程读的是磁盘上的工程文件，如果你在编辑器里改了但没保存，渲染出来的会是旧数据。

四、界面布局

渲染窗口是左右分栏布局：

区域内容
左栏（窄）参数配置：输出设置、音源设置、范围设置、输出路径、开始/取消按钮
右栏（宽）预览与反馈：波形显示器、渲染进度、渲染日志

窗口打开时会自动相对主窗口居中（主窗口还没渲染完时退化为屏幕居中），并短暂置顶。所有控件就位后才会显示，避免"闪一下"。

五、左栏详解

5.1 输出设置

这一组决定输出文件的"物理规格"。

格式

格式说明推荐场景
WAV无损未压缩，体积大后期剪辑、视频渲染的音频源
FLAC无损压缩，体积约为 WAV 的一半归档、分享无损音频
MP3有损压缩，兼容性最好日常分享、上传平台
OGG有损压缩，体积比 MP3 更小网页、游戏
💡 格式决定显示哪些参数：
选 WAV / FLAC 时，界面显示"位深"一行；选 MP3 / OGG 时，界面显示"码率"一行。切换格式会自动切换显示。输出路径的扩展名也会自动跟着变。

采样率

可选：22050 / 32000 / 44100 / 48000 / 96000 Hz。

常规分享用 44100（CD 标准）就够了。做高清素材可以用 48000 或 96000，但体积会明显变大。

位深（仅 WAV / FLAC）

可选：16-bit / 24-bit / 32-bit float。

16-bit 是 CD 标准，够用。做后期处理保留更多动态范围可以用 24-bit。

⚠️ 32-bit float 需要 soundfile：
32-bit float 的输出依赖 Python 的 soundfile 库。如果没有安装，程序会报错。

码率（仅 MP3 / OGG）

可选：128 / 192 / 256 / 320 kbps。

320 kbps 是 MP3 的最高常规码率，听感接近无损。128 kbps 体积小但明显有损。

声道

可选：立体声 / 单声道。

音频本身是基于单声道波形合成的，所以选立体声时会左右声道完全相同。单声道文件体积减半，适合播报类内容。

5.2 音源设置

这一组决定"每个音符用什么声音"。

音源

音源说明
自动（跟随预览乐器）用主程序当前预览时选的乐器，保持预览和渲染一致
Windows DingWindows 系统自带的"叮"提示音（wav/WindowsDing.wav）
默认波形（音调绝对准确）纯正弦波合成，按音符音高算出频率，音高绝对准确但听感"电子味"
钢琴采样（88键真实）用 wav/Piano/ 里的 88 个钢琴采样，按音高近似匹配后变调
自定义音效用 wav/textwav.wav 这个文件作为统一音源
工程内嵌音效（按音符配置）只渲染有 sound_path 的音符，其它音符静音
📌 关于"自动"：
主程序在弹窗预览时会播放声音，用的是一个"预览乐器"设置。选"自动"就是拿这个设置原封不动地用于渲染，保证"听到什么，就渲染出什么"。

应用工程内嵌音效配置

这是一个复选框，默认勾选。

勾选时：如果某个音符的 cze_makers 里定义了 sound_path，那么这个音符就优先用这段内嵌音效，而不用统一音源。

不勾选时：所有音符都用统一音源，忽略内嵌音效。

💡 与"工程内嵌音效"音源的区别：
· 音源选"工程内嵌音效"：只渲染有 sound_path 的音符，其它全静音；
· 音源选其它 + 勾选"应用内嵌音效"：有 sound_path 的用内嵌，没有的用统一音源。
一般做法是选一个统一音源（比如钢琴），再勾上"应用内嵌音效"，这样"有专属音效的用专属，没的用统一"。

包含载入的音频轨道（背景音乐）

这是一个复选框。

如果工程里加载过一段音频文件（比如背景音乐），勾选它就会把这段音频混入渲染结果。默认值取决于工程里有没有加载音频：

  • 有加载音频 → 默认勾选，旁边会显示音频文件名
  • 没加载音频 → 默认不勾选，且复选框是灰的（不可点），旁边会显示"（当前工程未加载音频）"

音调强度

滑块，范围 0.5x ~ 4.0x。它影响音符音高偏移的"夸张程度"。

1.0x 时音符按标准音高播放；数值越大，音高偏移越明显。这个跟主程序预览时的音调强度是同一个参数，在渲染窗口里也可以单独调。

总音量 / MIDI音量 / 音频音量

三个独立的音量滑块，都是 0 ~ 100%。

音量作用于
总音量整体增益，影响所有声音
MIDI音量只影响音符产生的合成声音
音频音量只影响背景音频

它们的关系是：MIDI音量 × 总音量 是音符的最终音量，音频音量 × 总音量 是背景音频的最终音量。

5.3 范围设置

决定"渲染哪一段"。

选项说明
全部音符渲染从第一个音符到最后一个音符的完整时间轴
仅时间选区范围只渲染时间轴上有选区的那一段。如果没有选区，这个选项灰掉不可选，且后面标"（当前无选区）"
自定义范围手动填起止秒数，只渲染这一段
💡 默认值很聪明：
打开渲染窗口时，如果检测到时间轴上有选区，会默认勾选"仅时间选区范围"，并把起止秒数预填到"自定义范围"的输入框里。如果没有选区，默认"全部音符"，自定义范围默认填 0.00 ~ 全部音符真实结束秒数。

"自定义范围"的单位是秒。输入框下方会实时显示换算结果，比如 ≈ 3.500s ~ 12.800s（时长 9.300s）。如果结束 ≤ 开始，会显示成红色警告色。

5.4 输出路径

一个输入框 + 「浏览」 按钮。默认路径是：

工程目录/export/工程名_日期时间.扩展名

比如 D:\MyProject\export\song_20260108_153020.wav。

下面两个复选框：

  • 渲染后打开文件夹 —— 渲染完成后自动打开输出目录，并选中刚生成的文件
  • 渲染后播放音频 —— 渲染完成后用系统默认播放器打开刚生成的文件

5.5 开始 / 取消按钮

右下角两个按钮：

  • 开始渲染 —— 校验参数，启动渲染
  • 取消 —— 未渲染时关闭窗口；渲染中则弹出确认框，确认后中断渲染并丢弃半成品

六、右栏详解

6.1 波形显示器

一块黑色画布，实时显示当前渲染的音频波形。

  • 渲染开始前显示"已就绪 ing......"
  • 渲染过程中，每处理一批音符就会把当前的混音缓冲降采样成波形画上去
  • 选择"立体声"时，会上下分两行显示左右声道（其实内容相同）
  • 选择"单声道"时，只有中间一行

它不是精确的最终结果，而是"渲染过程中的即时快照"，主要给你一个视觉反馈。渲染结束后显示的波形就是最终结果的近似（以当前音频缓冲为准）。

6.2 渲染进度

这里有四个信息点：

区域内容
阶段标签显示当前处于哪个阶段（见下方"渲染流程"）
进度条0 ~ 100% 的进度
已用时 / 剩余时间MM:SS 格式。剩余时间在渲染初期可能不准，越到后面越准
计数标签比如"已处理: 3,456 / 8,920 音符"

下面还有一行蓝色的"预计信息"，会随着参数变化实时刷新：

预计时长：1 分 23.45 秒    预计大小：14.23 MB

预计大小是根据格式、采样率、位深/码率、声道、时长估算出来的，跟实际大小可能略有偏差。

6.3 渲染日志

一块带滚动条的深色区域，按时间顺序打印渲染过程中的所有事件。

日志按等级用不同颜色显示：

颜色等级典型内容
浅灰info常规信息，比如"共 8920 个音符待渲染"
绿色success"音符渲染完成，用时 2.34 秒"、"文件已写入: xxx.wav (14.2 MB)"
黄色warning"加载钢琴采样失败 xxx"、"未安装 soundfile"
红色error渲染失败时的错误信息和堆栈
蓝色stage阶段切换信息，比如"渲染音符 0-8920..."

如果渲染失败，日志里会留下完整错误堆栈，方便排查问题。

七、渲染流程

点"开始渲染"后，程序在后台线程里依次执行以下阶段：

阶段进度做什么
加载音源0% ~ 5%按你选的音源类型，预加载钢琴采样 / Ding / 自定义音效
筛选音符5%按范围条件筛出需要渲染的音符
渲染音符5% ~ 75%逐个音符合成波形，叠加到混音缓冲
混音78%如果勾选了"包含音频轨道"，把背景音频混进来
归一化82%如果峰值超过 0.95，按比例压低整体音量，防止爆音
编码并写入文件85% ~ 100%把混音缓冲按格式编码，写盘

整个过程中，进度条、时间标签、计数标签、波形显示器都会实时更新。渲染日志里会打印每个阶段的开始/结束。

八、渲染结果

渲染成功后会：

  1. 日志里打印"文件已写入: xxx (14.2 MB)"
  2. 进度条到 100%，阶段标签显示"渲染完成！"
  3. 如果勾选了"渲染后打开文件夹"，自动弹出资源管理器并选中文件
  4. 如果勾选了"渲染后播放音频"，自动用系统默认播放器打开文件
  5. 主界面右下角的轮播图弹出通知：✅ 音频渲染成功！\n文件: xxx.wav\n大小: 14.20 MB

渲染窗口不自动关闭，让你有时间查看日志。关闭窗口时，参数会自动保存到 shezhi.txt，下次打开时自动恢复。

十一、常见问题

Q1：找不到"渲染为音频文件"菜单项？

它在 「渲染(R)」 菜单里。别去"文件"或"导出"菜单找，那里没有。也可以直接按 Ctrl + Alt + E。

Q2：为什么点菜单没反应？

看下前置条件：

  • 有没有打开工程？没打开会提示"请先打开或保存一个工程文件"
  • 工程里有没有音符？没有会提示"当前工程没有音符数据"
  • pygame 有没有初始化成功？失败会提示"音频引擎未初始化"

Q3：渲染出来的音频和预览听到的不一样？

可能的原因：

  • 音源选了跟预览不同的（比如预览用钢琴，渲染选了默认波形）
  • 音调强度不一样（预览时是一个值，渲染窗口里改成了另一个）
  • "应用工程内嵌音效配置"没勾选，导致某些音符没走专属音效
  • 背景音乐没勾选"包含载入的音频轨道"

想保持完全一致，就选音源"自动（跟随预览乐器）"，并把三个音量调到跟主程序一致。

Q4：为什么渲染出的音频开头/结尾有静音？

开头静音是因为第一个音符的时间点不在 0 秒。结尾静音是因为渲染会给末尾预留 1 秒尾音，让最后几个音符的自然衰减能完整收录。

Q5：为什么渲染日志里出现了"加载钢琴采样失败"？

说明 wav/Piano/ 目录不存在，或者某个采样文件损坏了。程序会跳过失败的采样，对找不到采样的音符回退到默认波形。如果嫌吵，把 wav/Piano/ 目录准备好就行。

Q6：进度条卡在 5% 不动了？

5% 是"筛选音符"阶段结束、"渲染音符"阶段开始的位置。如果卡住不动，说明当前正在处理一批音符但还没到更新进度的时间点。如果长时间不动（比如超过 30 秒），可能是某个音符渲染出错进入了死循环，可以点"取消"退出。

Q7：渲染中途取消会留下残破文件吗？

不会。程序在检测到取消后会清理掉半成品文件。如果目录里有残留，多半是写入过程中被强杀导致的，手动删掉就行。

Q8：自定义范围填的是秒还是节拍？

秒。跟音频渲染窗口里的其它时间参数一样，统一使用秒为单位。界面下方会实时预览换算结果。

Q9：能不能只渲染某几个音符？

不能。渲染范围只有三种粒度：全部、时间选区、自定义秒数。如果你只想渲染一小段，用时间选区或者自定义秒数圈出那一段即可。

Q10：渲染很慢，能不能加速？

渲染速度主要取决于三个因素：

  • 音符数量（越多越慢）
  • 音源类型（钢琴采样比正弦波慢，因为要加载和重采样）
  • 范围时长（越长越慢）

如果只是想快速出个 demo，可以先用默认波形音源试试。

Q11：为什么渲染结果里有"咔咔"的杂音？

一般是采样被重复拼接时接缝处不连续导致的。程序已经在每个音符的首尾做了淡入淡出（5ms 级别），但极端情况（超短音符、超强变调）仍可能听到。遇到这种情况，可以：

  • 把音符时长拉长一点
  • 把音调强度调小一点
  • 换一个音源试试

Q12：输出的 MP3 是不是真 MP3？

是的。MP3 编码用的是 pydub，底层调用 ffmpeg 的 MP3 编码器。如果你电脑里没装 ffmpeg，程序在渲染前会弹窗提示，让你改用 WAV。

十二、小结

「渲染为音频文件」是 Itoc 输出环节的核心功能，让你把工程变成可以直接播放、分享的音频。

  • 入口：菜单「渲染(R)」→「渲染为音频文件」，或 Ctrl+Alt+E
  • 前置条件：有打开的工程 + 有音符数据 + pygame 初始化成功
  • 支持 WAV / FLAC / MP3 / OGG 四种格式
  • 支持多种音源：自动 / Ding / 默认波形 / 钢琴采样 / 自定义音效 / 工程内嵌音效
  • 支持全部 / 时间选区 / 自定义三种范围
  • 实时波形预览 + 进度反馈 + 彩色日志
  • 可混入工程里加载的背景音频
  • 参数自动记忆到 shezhi.txt，下次打开时恢复
  • 渲染过程中可随时取消，自动清理半成品
