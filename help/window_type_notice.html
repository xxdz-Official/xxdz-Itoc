💬 气泡 / 通知

气泡/通知是 Itoc 里最"低调"的窗口类型——因为它压根就不是一个窗口。它不弹 Qt 窗口，而是调用 Windows 系统的通知中心，从右下角（或者你设置的位置）弹一个小卡片出来，几秒后自动消失。

如果你想让弹窗"不打扰用户"，只是"顺手提醒一下"，那气泡/通知就是你要的。

它和普通弹窗的区别

先看一张对比表：

能力普通弹窗气泡/通知
自定义标题✅✅（用 window_title）
自定义内容✅✅（用 notice_content）
自定义图标✅❌（系统通知用应用图标）
自定义位置✅❌（系统通知固定右下角，可被系统设置改）
自定义尺寸✅❌（系统决定）
自定义按钮区✅❌（系统通知没有按钮）
自定义控制钮✅❌（系统通知没有标题栏）
自定义样式✅❌（系统通知样式固定）
类名 / 编组✅❌（不是一个窗口）
窗口寿命✅（毫秒）✅（秒，系统通知的超时时间）
镂空 / 亚克力✅❌（系统通知不受程序控制）

所以选气泡/通知之前，先想清楚：你是要一个「能看到、能点、能拖」的弹窗，还是只要一个「一闪而过的小提醒」？前者用普通弹窗，后者用气泡/通知。

配置：只有一个内容框

切到「气泡/通知」之后，CZEmaker 面板会发生这些变化：

  • 顶部右侧功能区：整个隐藏。图标、效果音、样式钮、按钮区、透明度都不见了。
  • 位置配置区域：整个隐藏。四种位置模式都不可用。
  • 窗口标题行 / 窗口内容行：整个隐藏。
  • 特殊功能区：出现一个暗色配色的多行文本框，标题是「气泡内容」。

所以你在气泡/通知模式下，能配置的只有：

  1. 气泡内容：文本框里写你要通知的内容。
  2. 窗口寿命：虽然 UI 上没显示，但系统通知的超时时间是从 window_life 算的（秒为单位，最大 30 秒）。

窗口标题在「气泡内容」模式下不能直接编辑，因为窗口标题行被隐藏了。但配置文件里如果有 window_title，系统通知还是会用它作为通知标题。默认标题是「xxdz_itoc ♪(^∇^*)」——这是程序兜底的默认值。

💡 暗色文本框： 气泡内容的文本框用的是 PyCharm 暗色配色（背景 #2B2B2B，文字 #A9B7C6），和「执行代码」的编辑器是同款。写长文本不刺眼。

通知是怎么发出去的

程序调的是 create_windows_notification，它会依次尝试三种方式，直到成功：

第一种：plyer

如果你装了 plyer 库（pip install plyer），程序会优先用它：

from plyer import notification
notification.notify(
    title=title,
    message=message,
    app_name="小小电子xxdz_itoc",
    timeout=timeout
)

plyer 在 Windows 上会调用系统的 Toast 通知 API，效果最好看，是 Windows 10/11 原生那种右下角卡片。

第二种：win10toast

如果 plyer 不可用，程序会试 win10toast：

from win10toast import ToastNotifier
toaster = ToastNotifier()
toaster.show_toast(title, message, duration=timeout, threaded=True)

win10toast 也是调系统 Toast API，但库比较老，在 Windows 11 上偶尔会失效。

第三种：MessageBox 兜底

如果前两种都失败，程序会用 Win32 的 MessageBox 兜底：

import win32api
import win32con
win32api.MessageBox(0, message, title,
    win32con.MB_OK | win32con.MB_ICONINFORMATION | win32con.MB_SETFOREGROUND)

这是一个模态对话框，会阻塞在屏幕中央，直到用户点确定。虽然不好看，但至少「通知」这个动作不会丢。

第四种：控制台打印

如果连 MessageBox 都失败了（比如 pywin32 没装），程序会把通知内容打印到控制台：

print(f"通知: {title} - {message}")

这是最后的兜底，相当于「通知失败但不崩溃」。

⚠️ 通知不一定能弹出来： Windows 的「通知和操作」设置里，如果关闭了「获取来自应用和其他发送者的通知」，或者开了「专注助手」，系统通知会被静默丢弃，程序是收不到错误提示的。所以如果你点了测试运行但没看到通知，先去系统设置里检查一下。

寿命怎么算

气泡/通知的寿命不是「窗口显示多久」，而是「通知卡片停留多久」。计算公式是：

timeout = min(int(window_life_ms / 1000), 30)

也就是说：

  • 寿命 3000ms → 通知停留 3 秒。
  • 寿命 60000ms → 通知停留 30 秒（上限）。
  • 没配寿命 → 默认 5 秒。

Windows 的通知卡片本身还有自己的显示时长（一般是 5-10 秒），所以即使你设了 30 秒，也可能被系统提前收进通知中心。这个程序控制不了，是系统行为。

配置文件字段

字段名类型含义
window_typestring固定 notice
window_titlestring通知标题（可选）
notice_contentstring通知内容
window_lifedict超时时间（毫秒，会转成秒）

注意：气泡/通知不会保存 window_position、window_class、window_group、window_control_detail、window_button_detail、window_opacity、custom_size_enabled 这些字段，因为系统通知不需要它们。即使你在配置里手写了这些字段，解释器也会忽略。

为什么气泡/通知不参与阵列、编组、镜像克隆

这几个功能都需要「一个真实的窗口对象」才能工作：

  • 阵列：需要给窗口分配槽位、计算坐标、移动窗口。气泡没有窗口，移动不了。
  • 编组：编组是一组窗口的集合，用来批量关闭/移动。气泡没有窗口，进不了编组。
  • 镜像克隆：克隆体是真实窗口。气泡没有窗口，克隆不了。

所以如果你在 _do_create_window 里给气泡分配了阵列槽位，程序会立刻释放掉（不会报错，只是槽位空转一下）。

常见问题

Q：通知弹出来了，但是标题是「python」？

A：说明程序没有拿到 window_title，用了默认值。检查配置里的 window_title 字段是否为空。默认标题是「xxdz_itoc ♪(^∇^*)」，如果看到的是别的，说明系统层把应用名显示成了 python。

Q：通知一闪而过，根本看不清？

A：系统的通知显示时长由「通知和操作」设置决定，一般是 5 秒。程序设置的 timeout 只是"请求"，系统可以忽略。想看得久一点，去系统设置里调「通知显示时长」。

Q：能不能指定通知出现在屏幕的哪个位置？

A：不能。Windows 系统通知固定从右下角弹出（如果任务栏在底部），位置由系统控制。想自定义位置，请用普通弹窗。

Q：通知能不能带按钮？

A：不能。Itoc 用的是简单 Toast API，不支持自定义按钮。如果需要「点击通知执行某个动作」，目前只能靠用户点通知本体打开应用，程序没法拦截。

Q：气泡/通知支持中文吗？

A：支持。plyer / win10toast / MessageBox 都支持中文。但如果系统字体缺失，可能显示成方块，这个是系统问题，程序解决不了。

小结

气泡/通知的三件事：

  1. 不是窗口：没有位置、没有尺寸、没有样式，只有一个内容框。
  2. 三级降级：plyer → win10toast → MessageBox → 控制台打印。
  3. 寿命变超时：window_life 毫秒转秒，最大 30 秒，但最终由系统决定。

气泡/通知适合做「轻量提醒」——比如"这一段开始啦"、"注意这里有个坑"。想要真正的弹窗效果，还是回去用普通弹窗吧喵 ( ⓛ ω ⓛ *)
