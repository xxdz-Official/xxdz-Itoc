🧰 C++ 运行库

「C++ 运行库」是配合 《渲染为 C++ 代码》 使用的一套依赖管理工具。它管的是你电脑上 MSYS2 UCRT64 环境里的 C++ 包（比如 Qt5、OpenCV、SDL2、Boost），帮你检查缺了什么、已经装了什么、去哪里装。

💡 一句话理解：
它和 《Python 运行库》 是兄弟功能：
· Python 运行库管 pip 包；
· C++ 运行库管 pacman 包（MSYS2）。
都是“编译前的体检”，只是生态不同。
⚠️ 2.0 版本的重要说明：
Itoc 2.0 暂不支持直接把 C++ 代码编译成 exe。
「渲染为 C++ 代码」只生成 .cpp 源码；「C++ 运行库」只帮你检查/安装编译依赖。
最终的编译需要你在 MSYS2 UCRT64 终端里手动完成。

一、这个功能是干嘛的？

它做三件事：

  • 检查：解析 runCZEcpp.cpp 里的 #include，映射成 MSYS2 包名，再和 pacman -Q 对比，告诉你缺了哪些包。
  • 浏览：列出当前 MSYS2 UCRT64 环境里所有已安装的包，支持搜索、保存成 txt。
  • 安装：打开一个 MSYS2 UCRT64 终端，让你手动执行 pacman -S 安装缺失的包。

它不会自动编译代码，也不会自动生成 exe。它只负责“把编译环境准备好”。

二、前置条件：MSYS2 UCRT64

这套工具依赖 MSYS2 UCRT64 环境。你需要先安装 MSYS2，并确保它里面有 pacman.exe。

项目说明
推荐安装路径C:\msys64
需要存在的文件C:\msys64\usr\bin\pacman.exe
终端环境MSYS2 UCRT64（不是 MINGW64，也不是 MSYS）

如果程序找不到 MSYS2，会弹窗让你手动选择 MSYS2 根目录（就是包含 usr\bin\pacman.exe 的那个文件夹）。

三、环境路径配置

MSYS2 的路径保存在 shezhi.txt 里，字段名是：

cpp_env_path=C:\msys64

程序读取路径的顺序是：

  1. 先读 shezhi.txt 里的 cpp_env_path。
  2. 如果没配置或路径无效，尝试默认路径 C:\msys64。
  3. 如果默认路径也无效，弹窗让你手动选择。
💡 路径有效性怎么判断？
程序会检查目录下是否存在以下任意一个文件：
· bash.exe
· pacman.exe
· usr\bin\pacman.exe
只要有一个存在，就认为路径有效。

四、三个功能入口

三个功能对应 to_exe.py 的 --lib-tool 模式，分别传入不同的参数：

功能命令行参数作用
安装 C++ 运行库--lib-tool cpp-install打开 MSYS2 UCRT64 终端
浏览已安装的 C++ 运行库--lib-tool cpp-browse列出 pacman -Q 的结果
检查未安装的 C++ 运行库--lib-tool cpp-check解析模板 #include，对比已安装包

在 Itoc 主程序里，这些功能通常挂在「编译(C)」菜单下，和 Python 运行库并列。

五、检查未安装的 C++ 运行库

这是最常用的功能。它会：

  1. 读取 runCZE/runCZEcpp.cpp（或其它候选路径）。
  2. 用正则提取所有 #include <xxx> 和 #include "xxx"。
  3. 取头文件的第一段（比如 QApplication、opencv2、SDL2），查映射表，得到 MSYS2 包名。
  4. 调用 pacman -Q 拿到已安装包列表。
  5. 逐个对比，列出缺失的包。

5.1 头文件到 MSYS2 包的映射

程序内置了一张映射表（来自 to_exe.py 的 CPP_HEADER_TO_PACKAGE）：

头文件前缀MSYS2 包名
QApplicationmingw-w64-ucrt-x86_64-qt5
QWidgetmingw-w64-ucrt-x86_64-qt5
QJsonDocumentmingw-w64-ucrt-x86_64-qt5
QJsonObjectmingw-w64-ucrt-x86_64-qt5
QJsonArraymingw-w64-ucrt-x86_64-qt5
QFilemingw-w64-ucrt-x86_64-qt5
QTimermingw-w64-ucrt-x86_64-qt5
QThreadmingw-w64-ucrt-x86_64-qt5
QProcessmingw-w64-ucrt-x86_64-qt5
QScreenmingw-w64-ucrt-x86_64-qt5
QSystemTrayIconmingw-w64-ucrt-x86_64-qt5

📌 为什么 Qt 相关头文件都映射到 qt5？
因为 QApplication、QWidget、QJsonDocument 这些都属于 Qt5 核心模块，在 MSYS2 里通常由同一个 mingw-w64-ucrt-x86_64-qt5 包提供。程序按“头文件前缀”匹配，不是按单个文件精确匹配。

5.2 检查结果窗口

检查完成后会弹出一个窗口，包含：

  • 顶部标题：✅ 已安装完整 / ❌ 发现 N 个未安装的库
  • 摘要区：缺失包名列表 + 一行可复制的 pacman -S --noconfirm ... 命令
  • 详细列表：包名、状态（✅ 已安装 / ❌ 未安装）、已安装版本
  • 未映射头文件：如果某些 #include 不在映射表里，会单独列出来，提醒你手动检查
  • 底部按钮：📦 一键安装缺失库、关闭
💡 未映射头文件是什么？
如果模板里 #include 了映射表没有覆盖的头文件（比如某个小众库），程序不会猜，而是把它列在“未映射的头文件”里，让你自己判断该装哪个包。

六、浏览已安装的 C++ 运行库

这个功能会调用：

pacman.exe -Q

把当前 MSYS2 UCRT64 环境里所有已安装的包列出来。窗口里支持：

  • 搜索过滤：输入关键字实时过滤包名。
  • 保存列表：把完整列表存成 .txt。
  • 统计信息：显示“共 N 个包（已安装 M 个）”。

这个功能适合排查“我到底装没装某个包”。

七、安装 C++ 运行库

点「安装 C++ 运行库」不会自动帮你装，而是打开一个 MSYS2 UCRT64 终端，让你自己敲 pacman 命令。

7.1 终端里会显示什么？

==========================================
OK喵！已进入 C++ 运行库管理环境 (UCRT64)
可用命令:
  pacman -S 包名 (安装)
  pacman -Q (已安装)
  pacman -Ss 关键字 (搜索)
==========================================

7.2 常用 pacman 命令

命令作用
pacman -Q列出已安装的包
pacman -S 包名安装一个包
pacman -Ss 关键字搜索包
pacman -R 包名卸载一个包
pacman -Syu更新所有包

比如安装 Qt5：

pacman -S --noconfirm mingw-w64-ucrt-x86_64-qt5
💡 为什么不做成自动安装？
和 Python 运行库一样：不同机器可能需要不同的包版本、不同的镜像源、不同的权限，自动化反而容易出问题。直接给一个终端，让你自己控制，最稳。

八、和“渲染为 C++ 代码”的配合

完整流程大致是：

  1. 用 《渲染为 C++ 代码》 生成 .cpp 源码。
  2. 用「检查未安装的 C++ 运行库」看看模板里的 #include 缺哪些包。
  3. 用「安装 C++ 运行库」打开 MSYS2 终端，pacman -S 补齐缺失包。
  4. 在 MSYS2 UCRT64 终端里手动编译 .cpp（g++ / qmake / CMake，取决于你的模板）。
  5. 用 windeployqt 或手动拷贝 Qt5 DLL 到 exe 同目录。
  6. 运行 exe。
⚠️ 再次提醒：
Itoc 2.0 不会自动完成第 4、5 步。它只负责“生成源码”和“检查依赖”，编译和打包需要你手动做。
如果你想要“一键生成 exe”，请用「编译为 exe」或「组装打包模式」（那是 Python 路线，不是 C++ 路线）。

九、常见问题

Q1：提示“未找到 MSYS2 环境”怎么办？

A：先确认你装了 MSYS2，并且路径下有 usr\bin\pacman.exe。如果装在非默认路径，程序会让你手动选目录。选对之后路径会写进 shezhi.txt 的 cpp_env_path。

Q2：检查说缺 Qt5，但我明明装了？

A：可能的原因：

  • 你装的是 MINGW64 的 Qt5，不是 UCRT64 的。本工具默认用 UCRT64。
  • 包名不完全匹配。检查一下 pacman -Q | grep qt5 的实际包名。
  • cpp_env_path 指向了另一个 MSYS2 安装。

Q3：pacman 安装很慢？

A：可以换 MSYS2 镜像源。编辑 /etc/pacman.d/mirrorlist，把国内镜像（比如清华、中科大）放到前面。

Q4：为什么只映射了 Qt5 / OpenCV / SDL2 / Boost？

A：映射表是根据 runCZEcpp.cpp 模板的常见依赖整理的。如果模板里用了别的库，会显示在“未映射的头文件”里，需要你自己判断该装哪个包。

Q5：这个工具能帮我编译 C++ 吗？

A：不能。2.0 版本只做到依赖检查/安装，编译需要你在 MSYS2 终端里手动完成。

Q6：编译出来的 exe 缺 DLL？

A：Qt 程序运行时需要 Qt5 的 DLL。用 windeployqt 把依赖拷到 exe 同目录，或者手动复制 Qt5Core.dll、Qt5Gui.dll、Qt5Widgets.dll 等。

Q7：C++ 运行库和 Python 运行库有什么区别？

A：

  • Python 运行库：管 pip 包，服务 Python 解释器 / PyInstaller 打包。
  • C++ 运行库：管 pacman 包，服务 MSYS2 UCRT64 下的 C++ 编译。

十、小结

「C++ 运行库」是 C++ 路线的依赖管理工具：

  • 依赖环境：MSYS2 UCRT64
  • 路径配置：shezhi.txt 的 cpp_env_path
  • 三个功能：安装（打开终端）、浏览（pacman -Q）、检查（解析 #include 对比已安装）
  • 映射表覆盖 Qt5 / OpenCV / SDL2 / Boost 等常见依赖
  • 2.0 版本不自动编译 exe，编译需要手动完成
  • 配合 《渲染为 C++ 代码》 使用

如果你只是想分发弹窗作品，建议走「编译为 exe」或「组装打包模式」；C++ 路线更适合想用 Qt5 二次开发播放器的开发者喵 ( ⓛ ω ⓛ *)
