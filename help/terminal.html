💻 终端（Itoc 终端）

前面我们讲了音符块、调整图层、过渡动画、CZEmaker 弹窗、全局命令、阵列、编译为 exe、组装打包模式……这些功能大多靠鼠标点来点去。但 Itoc 里还藏着一个"用键盘说话"的地方——终端。

终端能让你用一行行命令去操作工程：批量删音符、批量改音高、批量设过渡、查看工程统计、导入素材、跑协作工具……鼠标要点半天的活儿，敲一行字就干完了。而且终端还兼当"日志窗口"，程序运行时的 print() 输出、报错信息，都会自动滚进终端里。

在 Itoc 主界面里，终端位于底部选项卡区域，和 CZEmakers、过渡配置、调整图层、媒体浏览器、音频音谱、代码视图并排。点一下底部的「终端」标签页，就能切到终端面板。

📌 本篇的范围：
讲的是 Itoc 内置终端窗口的界面、输入方式、输出重定向、历史记录、日志导出，以及它支持的全部命令。关于命令背后对应的具体功能（比如过渡动画怎么配置），请参考各自的专门文档。
关于底部选项卡的整体布局，请参考《界面概览》文档。

一、终端是什么？

终端本质上是主界面底部选项卡里的一个面板。它干三件事：

  • 接收输出： 程序里所有 print()、报错信息，都会被重定向到终端窗口里显示（黑底绿字，报错是红色）。
  • 接收输入： 底部有个输入框，敲命令回车就执行。
  • 导出日志： 终端里的全部内容可以一键存成 txt 文件。

对于喜欢键盘操作的用户，终端可以取代大量菜单点击。对于排查问题的用户，终端是唯一能看到完整运行日志的地方。

二、终端窗口长什么样？

终端窗口从上到下分成三块：

区域内容
顶部控制栏状态标签（"终端已激活" / "终端已睡眠"）、"清空终端"按钮、"导出日志"按钮
中部文本区深色背景（#1e1e1e）的日志显示区，绿色文字，错误红色，右侧有滚动条
底部输入框提示符标签（显示工程路径或 >）+ 命令输入框

2.1 状态标签

显示终端当前是"激活"还是"睡眠"状态：

状态含义
终端已激活程序输出会实时写入终端文本区
终端已睡眠程序输出先攒在队列里，等激活后再一次性刷出来

睡眠状态是为了避免终端在后台时拖慢主线程。当终端重新获得焦点或切到前台，会自动刷新队列。

2.2 提示符

底部输入框前面的提示符会显示当前工程路径，比如：

C:/Projects/MySong.czemidi>

如果还没打开工程，就只显示一个 >。提示符跟着工程走，换工程后会自动更新。

三、怎么用？

3.1 单行命令

在输入框里敲一行，按 Enter，命令就执行了。比如：

> info
> bpm 140
> select track=0
> delete selected

3.2 多行命令（批量执行）

输入框支持粘贴多行文本。如果你粘贴了一大段（含换行符），终端会自动进入"多行模式"：

  • 逐行执行，每行前面显示 [序号/总数] ▶。
  • 空行和以 # 开头的注释行会被跳过，显示 (跳过)。
  • 全部执行完后，显示 ✅ 多行执行完成 (N 行)。

比如你粘贴这么一段：

# 批量操作示例
select track=0
replace 60 62
select clear
bpm 150

终端会依次执行 select、replace、select clear、bpm 150，跳过那行注释。

💡 多行命令的妙用：
你可以把常用的一批操作写成几行命令，存到一个 txt 里。要用的时候整段复制粘贴进终端，一次性执行完。相当于"命令脚本"。

3.3 历史记录

按 ↑ 和 ↓ 可以翻阅之前输入过的命令：

按键作用
↑往上翻，调出更早的命令
↓往下翻，调出更晚的命令；翻到最底下会清空输入框
Enter执行当前输入框里的命令，并存入历史

历史记录是整段保存的，也就是说你粘贴的多行命令也会被当成一条历史记下来，再按 ↑ 能原样调出来。

3.4 清空与导出

按钮作用
清空终端清空文本区显示，并重置内部缓冲区。清空后会打印一行"终端已清空"
导出日志把终端里的全部内容保存成 txt 文件，默认文件名形如 xxdz_Itoc日志文件_20250101_120000.txt

导出日志是排查问题的利器。程序跑出问题了，把终端导出成 txt 发给开发者，对方就能看到完整现场。

四、输出重定向是怎么工作的？

终端做了一件挺"黑魔法"的事：它把 Python 的 sys.stdout 和 sys.stderr 换成了自己的代理对象。这样程序里任何 print() 都会经过终端，终端再把文字同时写到两个地方：

  1. 真正的控制台（如果程序带控制台窗口）——所以你在 cmd 里照样能看到输出。
  2. 终端文本框——所以 Itoc 界面里也能看到。

两边同时写，不会丢信息。程序退出时，终端会把 sys.stdout/sys.stderr 恢复成原始对象，避免影响后续代码。

⚠️ 一个注意点：
因为重定向是全局的，如果同时开了多个终端实例（正常情况只有一个），输出会被写到最后一个重定向的终端里。

6.1 import 命令

把外部文件导入到当前工程目录里。用法：

import <源文件路径> [目标子目录]

目标子目录可选：audio、img、video、srt、midi。如果不指定，程序会根据扩展名自动归类。

扩展名自动归入
.mp3 / .wav / .flac / .m4aaudio
.png / .jpg / .jpeg / .gif / .bmp / .ico / .webpimg
.mp4 / .avi / .mov / .mkv / .wmv / .flvvideo
.srtsrt
.mid / .midimidi
其它工程根目录

导入时的行为：

  • 目标目录不存在会自动创建。
  • 如果目标文件已存在且内容相同（MD5 一致），跳过。
  • 如果目标文件已存在但内容不同，自动加 _1、_2 后缀重命名，不覆盖。
  • 导入到 img 时，会尝试刷新 CZEmaker 的图片列表。
  • 导入成功后会标记工程已修改。

十七、多行命令实战示例

下面这段可以整段复制粘贴进终端，一次性执行：

# 1. 选中 0 号轨道
select track=0

# 2. 把音高 60 全换成 62
replace 60 62

# 3. 把这批音符颜色设成红色
color #FF0000

# 4. 清除选中
deselect

# 5. 把 BPM 改成 150
bpm 150

# 6. 看一眼统计
stats

终端会逐行执行，每行前面显示 [序号/总数] ▶，注释行显示 (跳过)，最后显示 ✅ 多行执行完成。

十八、注意事项

  • 命令不区分大小写： HELP 和 help 一样。
  • 命令与参数用空格分隔： 带空格的参数（比如轨道名）目前会被拆成多个参数，建议用下划线代替空格。
  • 带引号的路径： import 等命令支持用引号包住含空格的路径，如 import "C:/My Songs/a.mp3"。
  • 多数修改类命令会自动记录撤销快照： 改错了可以按 Ctrl+Z 撤销。
  • 修改后不会自动保存： 需要手动 save 或按 Ctrl+S。
  • 未加载工程时部分命令不可用： 会提示"未加载工程"。
  • 终端输出不影响真正的控制台： 两边同时写，程序日志不会丢。
  • 导出日志前建议先清空一次： 免得把旧会话的日志也导进去。

十九、常见问题

Q1：为什么终端里出现一堆红色文字？

红色表示 sys.stderr 的输出，也就是报错或警告。看到红色不用慌，往上翻翻看具体是什么错误。

Q2：我敲了命令但没反应？

检查三点：命令拼写是否正确、命令是否需要先打开工程、命令参数是否齐全。终端一般会给出提示。

Q3：多行粘贴后只执行了一部分？

可能是中间某行报错中断了。看终端输出，找到红色那行，改完再重试。空行和 # 开头的注释行不会执行，这是正常的。

Q4：怎么看到命令的详细用法？

输入 help 看总表，或 help <命令> 看某条命令的详情。比如 help collab、help import。

Q5：历史记录能保存到下次启动吗？

不能。历史记录只在当前会话内有效，关掉程序就没了。如果想把常用命令留下来，可以存到一个 txt 里，用的时候粘贴进来。

Q6：终端卡住不动了怎么办？

一般不会。如果某个命令执行时间较长（比如批量生成 2000 个事件点），终端可能短暂没响应，等一会儿就好。实在不行可以点"清空终端"重置显示。

二十、小结

终端是 Itoc 里的"键盘派"工作台：

  • 黑底绿字的日志窗口，程序输出自动重定向进来
  • 底部输入框支持单行命令、多行批量执行、上下键翻历史
  • 支持清空、导出日志
  • 命令覆盖工程、MIDI、音频、字幕、音符、图层、标记、阵列、过渡、渲染、协作等几乎所有模块
  • 多行粘贴可以当"命令脚本"用，一次执行一批操作
  • 修改类命令会自动记撤销快照，改错了能 Ctrl+Z
  • 输入 help 查看全部命令，help <命令> 查看详情

如果你想深入了解某条命令背后对应的具体功能，请参考对应的专门文档：过渡动画看《过渡动画》，阵列看《阵列》，协作导入看《协作》相关文档，渲染看《渲染为音频文件》《渲染视频文件》《渲染为 Python 代码》《渲染为 CZE 数据文件》等。
