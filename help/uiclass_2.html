🔧 模类设计器详解

上一篇我们认识了模类，搭了一个最简单的"你好，Itoc！"窗口，还搞懂了怎么保存、怎么用模类管理器、怎么在工程里用。但那时候我们只用了"标签"一个控件——模类设计器真正的威力，在于它支持 10 种控件、几十个属性、链接系统、Base64 图片嵌入、字体定制等等。这一篇我们就来把这些全部讲透。

内容比较多，建议边看边打开模类设计器实操。准备好了吗？走起！

一、模类文件的顶层结构

每个 .UIclass 文件的最外层都是一个 JSON 对象，我们叫它顶层对象。它描述了窗口本身的各种属性：

{
    "name": "登录对话框",
    "width": 800,
    "height": 600,
    "bg_color": "#F0F0F0",
    "minimize_btn": true,
    "maximize_btn": true,
    "close_btn": true,
    "help_btn": false,
    "esc_close": true,
    "close_btn_close": true,
    "taskbar_show": true,
    "resizable": true,
    "components": [ ... ],
    "icon_data_base64": "...",
    "icon_filename": "app.ico"
}

1.1 顶层字段详解

字段名 类型 必填 默认值 说明
name字符串是-模类名称，显示在窗口标题栏
width整数否800窗口内容区宽度（像素）
height整数否600窗口内容区高度（像素）
bg_color字符串否#FFFFFF窗口背景颜色（Hex RGB）
minimize_btn布尔值否true是否显示最小化按钮
maximize_btn布尔值否true是否显示最大化按钮
close_btn布尔值否true是否显示关闭按钮（控制钮）
help_btn布尔值否false是否显示帮助按钮（启用后自动禁用最大化）
esc_close布尔值否true是否允许 ESC 键关闭窗口
close_btn_close布尔值否true是否允许点击关闭按钮关闭窗口
taskbar_show布尔值否true是否在任务栏显示
resizable布尔值否true窗口是否可调整大小
components数组否[]控件列表
icon_data_base64字符串否""窗口图标 Base64 编码数据
icon_filename字符串否""图标原始文件名（仅用于显示）
💡 控制钮的联动关系：
在模类设计器里，如果 close_btn 被设为 false，minimize_btn 和 maximize_btn 会自动也被设为 false。因为"控制钮"（关闭按钮）是标题栏上所有按钮的"总开关"，关掉它就没有按钮区了。
⚠️ 顶层不要包含 id 和 _saved：
这两个字段是运行时内部使用的标记，id 用于模类管理器里的临时标识，_saved 用于判断模类是否已保存。保存到文件时模类设计器会自动移除它们。

二、通用控件字段

不管是哪种控件，都共享下面这些基础字段：

字段名 类型 必填 默认值 说明
id整数是-控件唯一标识符（正整数，不可重复）
type字符串是-控件类型（见下表）
name字符串是-控件显示名称（需在同类中唯一）
x整数是50左上角 X 坐标（相对于父容器）
y整数是50左上角 Y 坐标（相对于父容器）
width整数是100控件宽度（像素）
height整数是30控件高度（像素）
text字符串否""显示文本内容
default_focus布尔值否false是否为默认焦点控件
📌 坐标始终相对于父容器：
如果控件直接放在顶层窗口里，x/y 就是相对于窗口左上角。如果控件链接到了选项卡页面或编组框里，x/y 就是相对于那个容器的左上角。这一点在设计器里拖动控件时是自动处理的，你不用担心。

三、10 种控件全解

3.1 标签（type: "label"）

描述：用于显示静态文本，可以链接到进度条显示百分比值。

专用字段：

字段名 类型 默认值 说明
font对象{"family":"宋体","size":11,"color":"#000000"}字体设置
linked_progress_id整数 / nullnull链接的进度条 ID（非空时显示进度百分比）
hover_text字符串""鼠标悬浮时显示的文本（预览时生效）
pressed_text字符串""鼠标按下时显示的文本（预览时生效）

font 对象结构：

字段名类型默认值说明
family字符串"宋体"字体名称（如 宋体、微软雅黑、Arial）
size整数11字号（6-72）
color字符串"#000000"文本颜色（Hex RGB）

示例：

{
    "id": 1,
    "type": "label",
    "name": "状态标签",
    "x": 20,
    "y": 20,
    "width": 120,
    "height": 30,
    "text": "当前状态: 就绪",
    "font": {"family": "微软雅黑", "size": 12, "color": "#0066CC"},
    "linked_progress_id": 7,
    "hover_text": "点击更新状态",
    "pressed_text": "更新中...",
    "default_focus": false
}
💡 标签链接进度条的妙用：
把 linked_progress_id 设成某个进度条的 id，标签就会每 100ms 自动更新为进度条的当前值（显示成 "50%" 这样的格式）。这在做"文件复制进度框"的时候特别有用——一个进度条 + 一个百分比标签，完美还原 Windows 文件复制界面。

3.2 编辑框（type: "entry"）

描述：单行文本输入框（在预览和设计器中均为只读状态）。

专用字段：

字段名类型默认值说明
font对象同上字体设置
use_placeholder布尔值true是否将 text 用作虚占位符（输入框为空时显示）

示例：

{
    "id": 2,
    "type": "entry",
    "name": "用户名输入框",
    "x": 100,
    "y": 60,
    "width": 200,
    "height": 32,
    "text": "请输入用户名",
    "font": {"family": "宋体", "size": 11, "color": "#333333"},
    "use_placeholder": true,
    "default_focus": true
}
📌 虚占位符是什么意思？
当 use_placeholder 为 true 时，text 字段的内容会作为灰色占位文字显示（输入框为空时可见），输入框本身是空的。当它为 false 时，text 会作为实际内容填进输入框。

3.3 图片框（type: "image"）

描述：显示图片的控件，支持 Base64 嵌入式图片数据。

专用字段：

字段名类型默认值说明
image_data_base64字符串""图片的 Base64 编码数据
image_filename字符串""原始图片文件名（仅显示用）
display_mode字符串"填充"显示模式：填充 | 适应 | 拉伸 | 平铺 | 居中
show_border布尔值false是否显示边框
transparent布尔值true是否透明背景

display_mode 说明：

模式行为
填充填满控件区域，保持比例，可能裁剪
适应完整显示图片，保持比例，可能有留白
拉伸拉伸图片填满控件，不保持比例
平铺重复平铺图片
居中居中显示，不缩放

示例：

{
    "id": 3,
    "type": "image",
    "name": "LOGO图片",
    "x": 50,
    "y": 50,
    "width": 300,
    "height": 285,
    "text": "",
    "image_data_base64": "iVBORw0KGgoAAAANS...",
    "image_filename": "logo.png",
    "display_mode": "适应",
    "show_border": true,
    "transparent": false
}
💡 图片是"嵌"进文件里的：
图片控件的图片数据直接以 Base64 编码存在 JSON 里，不需要外部文件依赖。这意味着你把 .UIclass 文件发给朋友，图片会一起带过去，不会出现"图片找不到"的情况。代价是文件会变大——大图片的 Base64 数据可能有好几 MB，所以建议压缩后再导入。

3.4 按钮（type: "button"）

描述：标准命令按钮，使用系统原生样式。

专用字段：

字段名类型默认值说明
font对象同上字体设置

示例：

{
    "id": 4,
    "type": "button",
    "name": "确定按钮",
    "x": 200,
    "y": 300,
    "width": 100,
    "height": 35,
    "text": "确定",
    "font": {"family": "微软雅黑", "size": 11, "color": "#000000"},
    "default_focus": true
}
📌 按钮在模类里是"只读"的：
模类没有代码逻辑，所以按钮点击后不会执行任何操作。按钮主要是用来"还原视觉"——比如做假 UAC 窗口时，放两个按钮让窗口看起来更像真的。真正的"点击行为"由 Itoc 全局命令的"鼠标移动 + 点击"来模拟。

3.7 进度条（type: "progress"）

描述：进度指示控件，支持动画效果。

专用字段：

字段名类型默认值说明
initial_value整数50初始进度值（0-100）
end_value整数100结束进度值（0-100）
duration整数5动画持续时间（秒）

示例：

{
    "id": 7,
    "type": "progress",
    "name": "加载进度条",
    "x": 50,
    "y": 250,
    "width": 300,
    "height": 25,
    "text": "",
    "initial_value": 0,
    "end_value": 100,

}
💡 进度条是"会自动跑"的：
运行时，每个进度条都会独立按 duration 秒从 initial_value 平滑过渡到 end_value。所以你不需要写任何代码，进度条自己就会动起来。

3.8 编组框（type: "groupbox"）

4.4 链接坐标规则

当控件链接到容器（选项卡页面或编组框）时，x 和 y 坐标是相对于容器左上角的偏移量，而非相对于顶层窗口。这一点在设计器里拖拽时是自动处理的，你只需要关注最终视觉效果。

⚠️ 链接系统可靠性警告（来自文档）：
不建议使用与编组框、选项卡的链接功能……在某些情况下，链接到编组框或选项卡的控件可能会出现以下问题：

1. 坐标偏移：链接后控件位置可能与设计器中的显示位置不一致
2. 链接丢失：在编辑过程中，链接关系可能意外丢失
3. 预览异常：预览时嵌套控件可能无法正确显示
4. 保存损坏：链接信息在保存/加载循环中可能被错误修改

建议：
· 对于编组框，尽量把子控件直接放在编组框的坐标范围内（靠调整坐标的方式简单粗暴地实现，不依赖链接字段）
· 对于选项卡，尽量把控件放在选项卡页面的坐标范围内
· 如必须使用链接功能，请在保存后重新打开验证效果。有时在编辑器窗口可能看着控件错位，但是点击"运行"按钮后实际效果是正确的

📌 怎么导入图片？
选中图片控件后，属性面板里有一项「图片资源」，点击右侧的 ⇗ 按钮，会打开文件选择框。选择图片后，设计器会自动读取文件内容并转成 Base64 存进 JSON 里，同时把文件名记到 image_filename 字段用于显示。

七、图层面板与控件顺序

在模类设计器里，components 数组的顺序决定了控件的渲染层级（Z-order）：数组末尾的元素在最上层。

选中控件后，可以通过右键菜单或工具栏进行四种图层操作：

操作效果
置于顶层把控件移到数组末尾，渲染在最上层
置于底层把控件移到数组开头，渲染在最下层
上移一层与后一个元素交换位置
下移一层与前一个元素交换位置

八、多选与批量编辑

按住 Ctrl 或 Shift 点击多个控件，可以进入多选模式。在多选模式下：

  • 拖动任意一个选中的控件，整个选区一起移动
  • 属性面板只显示"X 坐标、Y 坐标、宽度、高度"四项
  • 修改其中任意一项时，会对所有选中控件应用偏移量（而不是强制统一值）
  • 右键菜单可以批量复制、删除、上移下移
  • 多选时"置于顶层/置于底层"不可用（只有单选时才能用）
💡 多选偏移的原理：
假设你选中了 3 个控件，它们的 X 坐标分别是 50、100、150。你把属性面板里的 X 改成 80（比第一个控件的 50 多了 30），那么三个控件会分别变成 80、130、180——每个都偏移了 +30，相对位置保持不变。这就是"偏移编辑"。

九、撤销 / 重做

模类设计器的撤销/重做采用 JSON 全文本快照方式：每次修改都会把当前模类的 JSON 序列化成字符串，压入撤销栈。最多保留 200 步。

操作快捷键
撤销Ctrl+Z
重做Ctrl+Shift+Z

撤销/重做是整个模类级别的——也就是说，它会恢复模类的完整状态，包括所有控件、窗口属性、JSON 数据。所以在模类设计器里你可以放心大胆地改，改坏了按 Ctrl+Z 就行。

十、点阵与自动对齐

10.1 显示点阵

在「视图」菜单里勾选「显示点阵」，设计区背景会显示等距的网格点。点阵间距默认 10 像素，可以在「视图」→「点阵规模...」里改成 2~50 之间的任意值。

10.2 自动对齐

勾选「视图」→「自动对齐」后，拖动控件和缩放控件时会自动吸附到网格上。缩放时，位置和尺寸都会吸附到网格，保证控件永远对齐。

💡 点阵和自动对齐可以独立使用：
你可以只显示点阵但不开启自动对齐（作为视觉参考），也可以只开启自动对齐但不显示点阵（视野更干净）。当然两个都开也完全没问题。

十一、JSON 源数据视图

JSON 视图是模类设计器最强大的功能之一。它位于窗口底部，实时显示当前模类的 JSON 数据。

11.1 查看与编辑

JSON 视图是可编辑的。你可以直接在里面修改 JSON，然后按 Insert 键或点「应用」按钮，修改会立刻反映到设计区。这对于批量修改、精确调整非常方便。

11.2 语法高亮

JSON 视图带语法高亮：

元素颜色
关键字（true / false / null）蓝色
字符串绿色
数字橙色
键名紫色
注释灰色

11.3 三个按钮

按钮作用
应用 (Insert + Space)把 JSON 内容应用到设计区
格式化自动美化 JSON（缩进对齐），如果 JSON 有语法错误会弹出带复制按钮的错误提示
了解模类语法打开内置的帮助文档（Markdown 阅读器）

十二、运行预览

点工具栏「▶ 运行」按钮，会弹出一个真正的窗口来展示模类效果。预览窗口会：

  • 根据顶层字段设置窗口标题、尺寸、背景色、控制钮、透明度、任务栏显示等
  • 根据 components 数组创建所有控件
  • 处理编组框、选项卡的嵌套关系
  • 启动进度条动画
  • 启动链接进度标签的定时更新
  • 处理 ESC 键关闭、关闭按钮关闭
  • 应用模类图标（如果设置了的话）

预览窗口的效果和运行时创建出来的窗口几乎完全一致，所以你可以放心地用预览来调试外观。

十三、常见问题

Q1：模类里的控件能响应点击吗？

不能。模类没有代码逻辑，按钮、单选框、复选框在模类里都是"只读"的。它们的作用是还原视觉，而不是真的接受用户交互。如果你想模拟点击，需要用 Itoc 全局命令的"鼠标移动 + 点击"命令。

Q2：图片能贴外链吗？

不能。模类的图片是 Base64 嵌入的，必须把图片数据写进 JSON 里。设计器会自动帮你做转换，你只需要在文件选择框里选图片就行。

Q3：模类能嵌套模类吗？

不能。模类里只能放 10 种基础控件，不能放另一个模类。如果你需要复杂的分层结构，可以用选项卡 + 编组框来组织。

Q4：链接系统为什么老是出问题？

这是链接系统本身的设计限制，文档也明确给出了警告。最稳妥的做法是：不用链接字段，直接把子控件放在容器的坐标范围内。比如你想把一个标签放进编组框，就把标签的 X/Y 设成编组框内部的坐标（相对于顶层窗口），让它的位置正好落在编组框区域内。这样看起来就像"塞进编组框"了，而且不会遇到链接系统的各种坑。

Q5：模类文件太大了怎么办？

如果图片数据太大，可以：

  • 用图片压缩工具压缩后再导入
  • 降低图片分辨率（模类窗口一般不需要 4K 图）
  • 尽量用 PNG 而不是 BMP（BMP 体积大）
  • 建议单文件不超过 10MB

Q6：模类支持 GIF 动图吗？

支持。图片控件的 image_data_base64 里可以存 GIF 数据，运行时会自动播放 GIF 动画。不过要注意 GIF 的 Base64 数据通常比较大。

  • 10 种控件：label、entry、image、button、radio、checkbox、progress、groupbox、tabwidget、rectangle

  • 链接系统：linked_tab_id、linked_tab_page、linked_tab_info、linked_groupbox_id、linked_groupbox_info
  • 字体系统、图片 Base64 嵌入、图层顺序、多选偏移编辑、撤销重做、点阵、自动对齐
