🤖 AI 协作（小電AI）

「AI 协作」是 Itoc 中一个“让 AI 帮你改工程”的功能。你用自然语言描述想改什么，AI 读完当前工程的完整 JSON 和 Itoc 语法文档后，会给出若干组精确查找/替换方案（【Search】 / 【Replace】），程序按方案对 .czemidi 文件做字符串级替换，替换完校验 JSON，合法就写回并重新加载。

💡 一句话理解：
它不是“AI 直接操作工程对象”，而是“AI 给你一段 Search 和一段 Replace，程序帮你做 replace(search, replace, 1)”。
所以它比“AI 重写整个 JSON”更可控，但也更依赖 AI 给出的 Search 是否和工程文件里的内容一字不差。
⚠️ 使用前必须保存工程：
AI 协作读取的是磁盘上的工程文件，不是内存里的未保存修改。
如果工程有未保存修改，程序会要求你先保存；选“否”会被拒绝，并提示“AI 协作需要基于最新的工程内容，请先保存工程。”
这既是为了让 AI 看到最新内容，也是为了避免改完重新加载时把未保存修改冲掉。

一、这个功能能干嘛？

它解决的是“不想手动翻 JSON、但又想批量改工程”的场景。比如：

  • 把所有 window_type 为 info 的弹窗改成 warning
  • 把某个编组名统一改掉
  • 批量调整某些字段的值
  • 让 AI 帮你找“哪里写了某个类名”，然后替换

它的工作方式不是“AI 直接操作工程对象”，而是：

  1. 把当前工程的完整 JSON 发给 AI。
  2. 把 Itoc 的工程语法说明文档（根据知识库模式选择）发给 AI。
  3. AI 返回一组 【Search】 / 【Replace】 对。
  4. 程序在工程文件里做精确字符串替换（每对只替换第一次出现）。
  5. 替换完校验 JSON；合法就写回并重新加载工程，不合法就恢复备份。

二、从哪里打开？

入口在「协作(B)」菜单里，菜单项通常叫「使用小電AI协作当前工程」或类似名称。

打开后会弹出一个独立的 AI 协作对话框。它是单例的：如果已经打开，再点菜单不会新建第二个，而是把已有窗口提到最前面（deiconify + lift + focus_force）。

四、知识库模式

知识库模式决定发给 AI 的语法文档是哪一份。三选一：

模式发给 AI 的语法文档适合场景
无知识库不发送语法文档，替换成“（未启用知识库）”占位只想让 AI 基于工程 JSON 猜，token 最省，但准确率最低
Itoc知识库（简单）CZEmidiMarkdown_S.md默认，内容精简，适合大多数简单修改
Itoc知识库（专家）CZEmidiMarkdown.md完整语法文档，token 消耗大，适合复杂修改

两份 .md 都放在程序根目录（os.path.dirname(__file__)）。如果文件不存在，程序会显示“（{filename} 文件未找到，请确保该文件存在于程序根目录）”，AI 拿到的就是这段占位文字，效果会变差。

💡 怎么选？
· 第一次用、改简单字段 → 选「Itoc知识库（简单）」。
· 改复杂结构、AI 老是给错 Search → 选「Itoc知识库（专家）」。
· 只是想让 AI 看看工程、不打算真改 → 选「无知识库」省 token。

五、AI 模型选择

对话框里有一个「AI 模型」下拉框，列出 orcarouterAI.json 里的 models。默认配置通常包含：

  • 免费模型 Deepseek (OrcaRouter)：orcarouter/free
  • 自动路由 (OrcaRouter)：orcarouter/auto

切换模型会立刻调用 save_ai_config() 写回 orcarouterAI.json 的 current_model 字段，下次打开时沿用。模型配置和「電籽 AI 助手」共用同一份文件。

想添加/编辑/删除模型、修改 API Key/Base URL，请参考 《如何调用高级 AI 模型》。

六、完整工作流程

6.1 发送指令

在输入框里写你想改什么，比如：

把工程里所有 window_type 为 info 的弹窗改成 warning

点「发送」后：

  1. _is_processing 置 True，「发送」和「应用修改」按钮被禁用。
  2. 状态栏显示“正在请求 AI...”，progress_label 显示“AI 思考中...”，进度条 indeterminate 模式开始滚动。
  3. 清空上一次的响应区。
  4. 启动后台线程 _ai_request(user_input)。

6.2 请求是怎么构造的

后台线程里调用 _build_user_message()，把三部分拼成一条用户消息：

  1. 当前工程完整 JSON（从磁盘读取的 .czemidi 全文，用 ```json 包住）
  2. 语法说明文档（根据知识库模式选择，用 ```markdown 包住）
  3. 你的指令（放在“用户指令：”下面）

然后调用 OpenAI 兼容接口：

from openai import OpenAI
client = OpenAI(api_key=..., base_url=...)
response = client.chat.completions.create(
    model=...,
    messages=[
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user",   "content": user_message}
    ],
    stream=False,
    timeout=90
)

SYSTEM_PROMPT 硬编码在 Cooperation_AI.py 里，明确要求 AI 按这个格式输出：

【Search】
精确的原始字符串（必须与工程文件中的内容完全一致，包括空格和换行）
【Replace】
替换后的新字符串

可以有多组 Search/Replace。如果 AI 判断无法执行，应该输出 【Error】: 原因。

6.3 AI 返回与打字机

AI 返回后，主线程会调用 _on_ai_response(reply)：

  • 停止进度条并隐藏。
  • 恢复「发送」按钮，状态栏显示“AI 响应完成”。
  • 把回复内容放进 _typewriter_queue，启动打字机：每 15ms 打一个字。
  • 如果回复里同时包含 【Search】 和 【Replace】，「应用修改」按钮亮起。
  • 如果只有 【Error】，状态栏显示错误原因，按钮不亮。
  • 如果既没有 Search/Replace 也没有 Error，状态栏显示“未检测到有效的 Search/Replace 对”。

不想等打字机，可以点「》」按钮直接跳过动画，把剩余内容一次性显示出来。

七、Search / Replace 格式

AI 必须按这个格式给方案，程序才认得：

【Search】
"window_type": "info"
【Replace】
"window_type": "warning"

【Search】
"window_title": "旧标题"
【Replace】
"window_title": "新标题"

7.1 解析规则

_parse_modifications() 做了两层解析：

  1. 正则匹配（优先）：【Search】\s*(.*?)\s*【Replace】\s*(.*?)(?=【Search】|$)，re.DOTALL 模式，支持多组、支持跨行。
  2. 按行解析（兜底）：如果正则没匹配到，就逐行扫描 【Search】 和 【Replace】 标记。

两条路都会调用 _clean_search_content() 清理内容：

  • 去掉首尾空白。
  • 去掉开头的 json、```json、``` 标记。
  • 去掉结尾的 ``` 标记。
  • 清理后 Search 为空的对会被丢弃。

7.2 关键：Search 必须一字不差

⚠️ Search 是精确字符串匹配：
程序只做 content.replace(search, replace, 1)，不做模糊匹配、不做 JSON 结构比对。
如果 AI 给的 Search 和工程文件里的内容差一个空格、差一个换行、差一个引号，就匹配不到，这一条修改会被跳过，并在控制台打印“⚠️ 未找到搜索串，跳过此条修改”。
所以 AI 返回后，最好自己先看一眼 Search 是不是和工程里的写法一致。

八、应用修改的机制与安全措施

点「应用修改」后，_apply_modifications() 按这个顺序干活：

  1. 解析：从响应文本里解析出所有 Search/Replace 对。没有有效对就提示“未找到有效的 Search/Replace 对”。
  2. 备份：把当前 .czemidi 复制成 .czemidi.bak。备份失败就中止并提示“无法创建备份文件”。
  3. 读取：读取工程文件全文。
  4. 逐个替换：按顺序执行 content.replace(search, replace, 1)。匹配不到就跳过，并在控制台打印警告和前 100 字符的搜索串预览。
  5. JSON 校验：用 json.loads(content) 验证替换后的内容。不合法就恢复备份，弹错误框“替换后 JSON 无效，已恢复备份。”，中止。
  6. 写回：合法就写回工程文件。
  7. 删除备份：成功后删除 .bak。
  8. 重新加载工程：调用主程序的 open_cze_project_from_path() 重新加载（期间 loading_project=True），让修改生效。
  9. 关闭对话框。

整个过程如果抛异常，也会自动恢复备份，并弹“修改应用失败：... 已恢复备份。”

💡 为什么先备份？
因为 AI 给的 Search/Replace 不一定靠谱。万一替换完 JSON 坏了，备份就是最后的保险。程序会在 JSON 校验失败、写入异常等情况下自动恢复 .bak。
📌 替换是“只替换第一处”：
replace(search, replace, 1) 里的 1 表示只替换第一次出现的位置。如果同一个 Search 在工程里出现多次，AI 需要为每一处分别给出 Search/Replace，或者给出足够长的上下文让 Search 唯一。

九、常见问题

Q1：点了发送，一直显示“AI 思考中...”？

A：请求超时是 90 秒。检查网络、API Key、Base URL 是否正确。免费模型可能排队或限流，等一会儿再试。超时会报“AI 请求失败：...”。

Q2：AI 返回了内容，但「应用修改」是灰的？

A：说明回复里没有同时包含 【Search】 和 【Replace】。可能 AI 只给了说明，或者格式写错了。可以让 AI 重新按格式输出。

Q3：应用后提示“未找到有效的 Search/Replace 对”？

A：AI 的格式不对，或者 Search 内容被清理后为空。检查 AI 回复里是否有完整的 【Search】 和 【Replace】。

Q4：应用后 JSON 损坏，弹“已恢复备份”？

A：说明 AI 给的 Replace 破坏了 JSON 结构（比如少逗号、少引号、括号不匹配）。程序已经自动恢复备份，工程没坏。可以让 AI 重新给方案，或者改用「Itoc知识库（专家）」让它更了解语法。

Q5：某条修改被跳过了？

A：说明 Search 在工程文件里没找到。常见原因：① AI 记错了字段名；② 空格/换行/引号和实际不一致；③ 这个 Search 已经被前一条替换改掉了。看控制台日志里“未找到搜索串”的提示。

Q6：为什么强制先保存工程？

A：因为 AI 协作改的是磁盘文件。不保存的话，AI 看到的是旧内容，改完重新加载会把你的未保存修改冲掉。

Q7：免费模型和付费模型有什么区别？

A：免费模型无需登录、无限使用，但智商较低、单次 token 少，复杂工程容易给错方案。付费模型由第三方 OrcaRouter 提供，能力更强，但需要你自己注册/充值，和 Itoc 作者无关。详见 《如何调用高级 AI 模型》。

Q8：可以把 AI 协作当成“结构化 JSON 编辑器”吗？

A：不建议。它本质是精确字符串替换，不是结构化编辑。复杂修改（比如增删数组元素、调整嵌套结构）很容易因为 Search 不唯一或 Replace 破坏 JSON 而失败。复杂改动建议手动改，或者用代码视图。

Q9：备份文件 .bak 还在，能手动恢复吗？

A：能。把 工程名.czemidi.bak 改回 工程名.czemidi 即可。正常情况下程序成功后会自动删除备份，只有失败或异常时才可能残留。

Q10：重新加载工程后，我的撤销历史还在吗？

A：AI 协作是直接改磁盘文件再重新加载，不走主程序的撤销栈。所以这次修改不能用 Ctrl+Z 撤销。改之前想清楚，或者先手动备份工程。

十、小结

AI 协作（小電AI）是一个“自然语言 → Search/Replace → 精确替换”的工具：

  • 入口：「协作(B)」菜单 → 使用小電AI协作当前工程
  • 前置：必须打开工程、必须保存、文件必须存在
  • 三种知识库模式：无 / 简单 / 专家
  • 模型配置保存在 orcarouterAI.json
  • AI 返回 【Search】 / 【Replace】 对，程序做精确字符串替换（每对只替换第一处）
  • 应用前自动备份 .bak，JSON 校验失败会自动恢复
  • Search 必须一字不差
  • 改完重新加载工程，不能用 Ctrl+Z 撤销
  • 想调用更强的模型，看 《如何调用高级 AI 模型》

它适合“简单、明确、可精确描述”的批量修改；复杂改动还是手动来更稳。玩得开心喵 ( ⓛ ω ⓛ *)
