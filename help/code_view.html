💻 代码视图

Itoc 平时是靠鼠标点来点去的——点音符、拖滑块、拉面板。但有时候，你偏偏想直接看工程文件到底长什么样，甚至直接用键盘改数据。这时候，就该「代码视图」出场了。

代码视图是底部选项卡里的一个面板，把整个工程的内容以 PyCharm 风格的 JSON 代码展示出来。带行号、带语法高亮、带查找替换、带撤销重做——就像一个迷你版 IDE，专门用来读和改工程数据。

📌 本篇的范围：
讲的是「代码视图」面板的界面布局、工具栏按钮、行号栏用法、查找替换面板、跳转行:列、快捷键、撤销重做保护机制、应用修改的流程、主题和语言支持。关于工程文件本身的字段含义，请参考《音符块自身属性》《调整图层》《CZEmaker 弹窗编排》等文档。

一、这个功能是干嘛的？

代码视图本质上是一个「工程数据的文本编辑器」。它做的事：

  1. 读取：把当前工程的所有数据（音符、标记、命令、图层、编组、阵列等）整理成一份 JSON。
  2. 展示：用 PyCharm 风格的代码编辑器呈现出来，带行号、语法高亮、滚动同步。
  3. 编辑：你可以直接在文本框里改内容，像写代码一样。
  4. 应用：改完之后点「应用」，程序会重新加载工程，让修改生效。

它最大的价值是：批量修改、精确查找、结构对照。

💡 什么时候用代码视图？
· 想一次性把所有某字段的值改掉（比如把所有音符的某个配参字段统一改一个值）
· 想看清楚工程 JSON 的嵌套结构，检查字段名拼写
· 想快速统计某个字段出现了多少次（配合查找）
· 想手动调一下 JSON 缩进、格式化一下看结构
· 想复制整个工程的 JSON 出来，做备份或发给别人参考

二、从哪里打开？

代码视图不是独立窗口，它就在底部选项卡栏里，选项卡标题是「代码视图」。它和「CZEmakers」「过渡配置」「调整图层」「媒体浏览器」「音频音谱」「终端」这些选项卡并排在一起。

如果底部选项卡栏当前没有显示，先通过菜单「视图(V)」→「显示底部选项卡」把它显示出来，然后点「代码视图」选项卡即可。

三、界面布局

代码视图从上到下分成四部分：

区域内容
顶部工具栏刷新、应用、格式化、复制全部、撤销、重做、查找、替换、跳转行:列、状态标签
中部编辑区左侧行号栏 + 中间代码编辑区 + 右侧垂直滚动条
底部横向滚动条长行横向滚动
底部状态栏左侧显示行数/字符数，右侧显示光标行列位置

当查找/替换面板打开时，编辑区右侧会挤出一块查找替换面板，编辑区自动收窄。

四、工具栏按钮详解

按钮作用

应用把编辑区的内容解析成 JSON，写回工程。会先保存撤销快照，再重新加载工程
格式化把编辑区的 JSON 重新排版（缩进对齐）。如果 JSON 格式有错，会弹错误提示
复制全部把编辑区的内容整体复制到剪贴板
↺ 撤销撤销代码视图编辑区内的修改（不是主程序的撤销）
↻ 重做重做代码视图编辑区内的修改
🔍 查找打开/关闭查找面板（也可用 Ctrl+F）
🔁 替换打开/切换替换面板（也可用 Ctrl+H）
🧭 跳转行:列打开跳转对话框，输入行号或 行:列（也可用 Ctrl+G）
💡 状态标签（右上角）：
显示当前代码视图的状态，比如「已同步 12:34:56」「● 已修改未应用」「JSON 格式错误」等。
橙色文字通常表示"有未应用修改"，红色表示"出错了"，蓝色表示"已同步"。

4.1 撤销/重做按钮 vs 主程序撤销

这两个按钮只管代码视图里的编辑，跟主程序（Ctrl+Z 撤销音符、命令那个）完全是两套系统。

操作撤销的是什么
主界面按 Ctrl+Z撤销对工程的修改（音符移动、删除等）
代码视图里按 Ctrl+Z 或点工具栏「↺ 撤销」撤销代码视图编辑区内的文字修改
⚠️ 代码视图的撤销/重做不会影响到主程序，主程序也不会影响到代码视图。
你在代码视图里改了很多，撤回时也是撤代码视图的文字，不会触发主程序去改数据。应用之前，工程本身还没变。

五、行号栏的用法

左侧的行号栏不只是"显示行号"这么简单，它还有几个很好用的功能：

操作效果
鼠标悬停行号整行淡蓝色高亮，方便看清光标在哪一行
单击行号选中整行（从行首到行尾）
Shift + 单击从上一次点击的行到当前行，整段选中
按住拖拽从按下行到当前行，整段选中
滚轮滚动编辑区（和编辑区同步）
💡 行号栏宽度自适应：
行号栏的宽度会根据最大行号的位数自动调整。工程很大（比如上万行）时，行号栏会自动变宽一点，保证行号不会显示不全。

六、查找替换面板

按 Ctrl+F 打开查找面板，按 Ctrl+H 打开替换面板。面板出现在编辑区右侧，占大概 480 像素宽。

6.1 面板结构

区域内容
顶部标题行「查找」和「替换」两个标题（替换模式才显示）
输入区左边是查找输入框，右边是替换输入框（查找模式只显示左边的）
按钮区左边「上一个」「下一个」，右边「替换」「全部替换」
选项区区分大小写、全字匹配、正则表达式、多行模式、循环查找
状态区「找到 N 个匹配（第 M 个）」或「未找到匹配」等提示
底部按钮「关闭替换」和「关闭 ✕」

6.2 查找 / 替换输入框

两个输入框都是多行文本框（高度 3 行左右），支持多行关键词查找。这意味着你可以查找跨行的字符串。

💡 自动填入选中文本：
打开查找面板时，如果编辑区里有选中的文本（且不超过 500 字符），会自动填到查找框里，省得你手动复制。

6.3 查找选项

选项说明
区分大小写勾选后，"Note" 和 "note" 是两回事
全字匹配只匹配完整的单词（前后是词边界）。跟「正则表达式」互斥
正则表达式把查找词当作正则表达式来解析。勾选后会自动取消「全字匹配」
多行模式勾选（默认）：查找内容里的换行符原样匹配。不勾：把换行符替换成空格再匹配（位置映射是 1:1 的）
循环查找勾选（默认）：查到头会绕回开头。不勾：查到头就停

6.4 查找高亮

找到的匹配会以两种颜色显示：

类型浅色主题深色主题
全部匹配淡黄色背景（#FFEB99）深褐色背景（#5C4A1E）
当前匹配橙黄色背景（#FFC800）+ 蓝色边框琥珀色背景（#7A5C10）+ 蓝色边框

「当前匹配」就是你按「下一个 / 上一个」时跳到的那一个，会显眼得多。

6.5 查找的快捷键

快捷键作用
Ctrl+F打开查找面板
Ctrl+H打开替换面板
F3查找下一个
Shift+F3查找上一个
Ctrl+G跳转行:列
Enter（查找框里）查找下一个
Esc关闭查找/替换面板

6.6 查找面板的「查找 / 替换」按钮行为

工具栏上的「🔍 查找」和「🔁 替换」按钮，行为有点讲究：

当前状态点「🔍 查找」点「🔁 替换」
面板未打开打开查找模式面板打开替换模式面板（查找+替换都显示）
面板已开（查找模式）关闭整个面板展开替换栏（切到替换模式）
面板已开（替换模式）收起替换栏（切回查找模式）收起替换栏（切回查找模式）
💡 一句话记忆：
· 点「查找」→ 找东西；如果再点一次就关。
· 点「替换」→ 打开替换；如果再点一次，只把替换那一栏收起来，保留查找栏。
· 想彻底关掉面板，点「查找」关掉，或者直接按 Esc。

6.7 替换操作

  • 替换：把当前选中的匹配替换成替换框里的内容，然后自动跳到下一个匹配。
  • 全部替换：把工程里所有匹配都替换掉。如果匹配数超过 1 个，会弹确认框，提醒「全部替换可能破坏 JSON 结构」。
⚠️ 全部替换要小心：
因为 JSON 里可能出现大量重复的字段名（比如每个音符都有 "note_value"），如果你只想着改某一个字段的某一处，但用了「全部替换」，就会全改掉。
建议：先用「查找」定位，确认范围后，再用「替换」逐个换，或者用「全部替换」前先保存一份工程。

七、跳转到 行:列

点工具栏的「🧭 跳转行:列」按钮，或按 Ctrl+G，会弹出一个小对话框。

输入格式效果
42跳到第 42 行第 1 列
42:10跳到第 42 行第 10 列

对话框打开时，输入框里会预填当前光标的行:列，光标全选，方便直接输入新值。

跳转时，如果输入的行号/列号超出范围，程序会自动夹到合法范围内（比如工程只有 100 行，你输了 200，会跳到第 100 行）。

📌 为什么这些快捷键要"拦截"？
因为主程序本身也用 Ctrl+C / Ctrl+V 这些快捷键来复制粘贴音符。代码视图里如果直接用，就会"串味"——你想复制代码视图里的文本，结果主程序把选中的音符复制走了。
所以代码视图专门拦截了这些快捷键，把它们"锁"在编辑区里。

九、撤销 / 重做的保护机制

代码视图的撤销有一个很贴心的设计：防止编辑区被撤销成空。

普通的 tk.Text 组件，如果一直按 Ctrl+Z，最终会撤销到一个空内容（所有输入都被撤回了）。这在代码视图里是不好的——用户会看到一片空白，还以为工程没了。

所以代码视图做了一个保护：

  1. 每次从工程刷新内容时，会把当前内容存一份「最早状态快照」（_editor_initial_snapshot）。
  2. 当你一直撤销，撤到内容变成空、但撤销前不是空时，说明"撤销触底"了。
  3. 程序会自动把编辑区内容恢复成「最早状态快照」，而不是留一个空框。
  4. 状态栏会显示「已是最早状态」。

这样，你随便按 Ctrl+Z 都不会把编辑区搞空，最多回到"刚刷新时"的样子。

💡 什么时候"最早状态"会被重置？
· 点「刷新」后，最早状态 = 刷新后的内容。
· 点「格式化」后，最早状态 = 格式化后的内容。
· 点「应用」后，会重新刷新，最早状态自然也是最新的。

十、应用修改的流程

改完代码视图的内容，点「应用」之后，程序会做这一系列操作：

  1. 解析 JSON：把你编辑的内容解析成 JSON 对象。如果格式错了，会弹「JSON 格式错误」的提示，不会继续。
  2. 比对变化：把新数据跟工程当前的数据对比。如果没变化，会提示「内容没有变化，无需应用」。
  3. 保存撤销快照：调用主程序的 save_undo_snapshot_before_modify，让这次应用可以被 Ctrl+Z 撤销。
  4. 写临时文件：把 JSON 写到一个 .czemidi 临时文件。
  5. 重新加载工程：调用主程序的 open_cze_project_from_path 加载临时文件，让改动生效。
  6. 恢复工程路径：因为加载的是临时文件，所以要把工程路径改回原路径。
  7. 标记已修改：让标题栏出现 *，提醒你保存。
  8. 刷新代码视图：用最新的工程数据重新填一遍编辑区。
  9. 轮播图通知：主界面右下角弹一个通知「代码视图已应用到工程」。
⚠️ 应用前会先弹确认框：
「确定要把代码视图中的内容应用到工程吗？应用后主工程会被重新加载，旧状态会保留在撤销栈中。」
确认之后才会真正执行。所以万一点错了，可以点取消。

十一、自动同步

代码视图会跟主工程自动同步，但有几条规则：

时机行为
切换到代码视图选项卡时自动从工程刷新内容（如果之前有未应用的修改，会弹窗问你是丢弃还是保留）
在主界面做了修改（比如拖了个音符）延迟 500ms 后，如果代码视图没有未应用修改，会自动刷新
代码视图有未应用修改时不自动刷新（避免覆盖你的编辑）
💡 自动刷新是"防抖"的：
如果你在主界面连续做了很多操作，代码视图不会每一下都刷新。它会等 500ms 内的操作都做完，然后一次性刷新。这样不会拖慢主程序。

12.1 主题

代码视图会自动检测主程序当前用的是浅色还是深色主题，并切换配色。当前支持两套配色：

配色背景文字关键字字符串数字
浅色（默认）白黑紫绿蓝

12.2 语言

切换语言包后，代码视图里的按钮、标签、菜单文字都会跟着翻译。状态栏里动态显示的文本（如「共 N 行 / M 字符」「第 X 行, 第 Y 列」）也会重新翻译。

十三、常见问题

Q1：代码视图里改的内容，什么时候生效？

点「应用」之后才生效。 编辑区里的内容只是"草稿"，改了不会立刻影响工程。想生效必须点「应用」。

Q2：我改了一半，切走选项卡，回来发现内容没了？

切换选项卡时，如果有未应用的修改，会弹窗问你：「点击『是』：丢弃这些修改，显示最新的工程内容；点击『否』：保留修改，不刷新」。如果你点「是」，就会丢弃；点「否」就能保留。

Q3：按 Ctrl+Z 撤销，为什么撤着撤着回到"初始状态"就不动了？

因为已经撤到"最早状态"了（也就是你打开代码视图、或者上次点刷新/格式化时的内容）。再撤销就没有历史了。程序会显示「已是最早状态」。

Q4：为什么 Ctrl+C / Ctrl+V 在代码视图里"不管用"？

不是不管用，而是只作用于代码视图内部。代码视图拦截了这几个快捷键，把它们的操作范围"锁"在编辑区里，不触发主程序的复制粘贴音符。
想复制代码视图里的文本，直接在编辑区里用 Ctrl+C 就行。想复制整个编辑区内容，用工具栏的「复制全部」按钮。

Q5：应用之后发现改错了，怎么办？

按主程序的 Ctrl+Z 就能撤销。因为应用前保存了撤销快照，所以整个"应用"操作是可以一键撤销的。

Q6：代码视图能改哪些内容？

理论上所有工程数据都能改：音符、标记、命令、调整图层、编组、阵列、模类、时间选区等等。但改的时候要小心，因为代码视图不做字段校验——你写错了字段名，程序认不出来，可能加载时会丢数据或报错。

💡 建议的工作流：
1. 先用主界面正常操作，让工程处于正确状态。
2. 打开代码视图，看看 JSON 长什么样，熟悉字段名。
3. 想做批量修改时，先备份工程，再在代码视图里改。
4. 改完点「格式化」检查一下 JSON 是否合法。
5. 点「应用」，然后 Ctrl+S 保存工程。

Q7：为什么有时候应用后工程看起来"没变"？

可能的原因：

  • 你改的字段是程序内部使用的，不直接影响显示（比如某些元数据）。
  • 你改的值跟原来的值等价（比如 1 改成 1.0）。
  • 主程序里有缓存，需要切一下选项卡或者刷新一下画布才能看到变化。

Q8：代码视图能一键清空工程吗？

能，但不建议。如果你把内容改成 {} 或 {"notes": []} 然后应用，就会得到一份"空工程"。这个操作是可撤销的（Ctrl+Z），但应用前最好想想清楚。

Q9：行号栏能用鼠标滚轮滚吗？

能。行号栏和编辑区是同步滚动的。在行号栏上滚轮，编辑区也会一起滚。

Q10：为什么状态栏里有时候显示"已同步"，有时候显示"已修改未应用"？

  • 已同步（蓝色）：代码视图内容和工程一致，没有未应用的修改。
  • 已修改未应用（橙色）：你在代码视图里改了东西，但还没点「应用」。
  • 已应用到工程（绿色）：应用成功。
  • JSON 格式错误（红色）：JSON 解析失败，不能应用。

十四、小结

「代码视图」是 Itoc 里的"底层编辑器"，把工程 JSON 摊开给你看、给你改。

  • 位置：底部选项卡 →「代码视图」
  • 工具栏：刷新、应用、格式化、复制全部、撤销、重做、查找、替换、跳转行:列
  • 编辑区：PyCharm 风格，带行号、语法高亮、撤销重做
  • 行号栏：悬停高亮、单击选行、Shift+单击选范围、拖拽选范围
  • 查找替换：Ctrl+F / Ctrl+H，支持正则、多行、全字、循环
  • 跳转：Ctrl+G，输入 42 或 42:10
  • 撤销保护：撤到底会回到"最早状态"，不会清空
  • 快捷键拦截：代码视图内的 Ctrl+C/V/X/A/Z/Y 都只作用于编辑区
  • 应用流程：解析 JSON → 保存撤销快照 → 写临时文件 → 重新加载工程
  • 自动同步：切到选项卡时刷新；主程序修改后延迟 500ms 刷新（有未应用修改时不刷）
