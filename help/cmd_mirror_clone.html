🪞 全局命令 · 镜像克隆编组

镜像克隆编组是「把一个编组整个复制一份，放到别的位置」。听起来像复制粘贴，但它牛的地方在于：

  • 不是一次性复制，而是跟随源编组一起出生的
  • 克隆出来的编组可以整体镜像翻转（水平/垂直/全反）
  • 克隆出来的弹窗的入场/出场动画也会跟着反转
  源编组"你好"                镜像克隆编组"你好_镜像克隆版"
  ┌─────────┐                 ┌─────────┐
  │ ① ② ③   │  ──克隆──▶     │ ③ ② ①   │
  └─────────┘                 └─────────┘
      左边                        右边（整体水平翻转）

一、什么时候用？

场景说明
左右对称弹窗左边一组弹窗往右飞，右边一组弹窗往左飞，形成对称冲击
上下镜像上面一组往下，下面一组往上，做「夹击」效果
补一份备用源编组弹窗比较多，直接镜像一份不用重新编排
鬼畜镜像鬼畜视频里经常用「多份镜像」制造满屏弹窗的效果

二、核心配置

2.1 源编组 → 目标编组

字段说明
源编组要克隆的源编组，从当前工程所有编组里选
目标编组克隆出来的新编组名，默认「源编组名 + _镜像克隆版」
💡 目标编组名可以改：
默认会自动填「源编组名 + _镜像克隆版」，但你可以改成任何名字。
一旦你手动改过，切换源编组时就不会再自动覆盖了（避免打断你的思路）。

2.2 从当前状态开始

值行为
勾选（默认）克隆「命令触发那一刻，源编组里还活着的弹窗」
不勾把源编组从头到尾「重演」一遍——按原始相对节拍，一个个克隆出来
💡 怎么选？
· 「我现在就想看右边也有一组」→ 勾「从当前状态开始」
· 「我要完整复刻源编组的节奏，从头到尾同步」→ 不勾

三、两种工作模式

程序会根据「命令触发的时间点」和「源编组第一个弹窗出生的时间点」自动判断用哪种模式：

3.1 跟随模式（命令触发 ≤ 源编组开始）

  时间轴：   │  命令触发      源编组第一个弹窗
             ▼                 ▼
             ────────────────────▶

  效果：源编组每弹出一个弹窗，克隆编组立刻跟着弹一个。
        完全同步，一个不多一个不少。

3.2 快照模式（命令触发 > 源编组开始）

  时间轴：   │ 源编组第一个弹窗   命令触发
             ▼                    ▼
             ────────────────────▶

  效果：命令触发的那一刻，源编组已经弹了一部分。
        · 勾「从当前状态开始」：只克隆还活着的
        · 不勾：按原始相对节拍，从头重演一遍
📌 你不用手动选模式。
程序会根据命令的时间点自动判断。你只要决定「从当前状态开始」这个复选框就行。

四、位置选择器

位置选择器决定「克隆出来的第一个弹窗出现在哪里」。四种模式：

4.1 屏幕坐标系

模式说明
绝对坐标填像素值，例如 800 / 400
相对坐标填百分比，例如 50 / 50 表示屏幕正中

4.2 屏幕对齐

3×3 方向按钮矩阵 + 偏移量。比如点「↘」再填偏移 (30, 30)，克隆弹窗会出现在屏幕右下角，距离边缘 30 像素。

  ┌───────────────────────┐
  │ ↖  ↑  ↗               │
  │                       │
  │ ←  •  →    ● ← 点这个 |
  │                       │
  │ ↙  ↓  ↘               │
  └───────────────────────┘

  • = 屏幕中心
  ← = 左侧居中，偏移可调
  其他方向同理

4.3 与窗口链接

克隆弹窗会出现在源编组里某个带类名的窗口旁边。

字段说明
链接目标从源编组里所有带类名的窗口里选一个
系统 / 相加系统：用默认偏移；相加：指定偏移量
单位px / rpx

4.4 屏幕随机

在屏幕范围内随机选一个位置。无额外参数，直接执行。

五、重编排：翻一翻

重编排决定克隆出来的弹窗顺序和方向怎么变：

模式字段值效果
原样original顺序不变，方向不变
全面反转full_reverse顺序和方向都反
水平反转horizontal_reverse左右镜像，上下不变
垂直反转vertical_reverse上下镜像，左右不变

5.1 位置偏移也会被翻转

  源编组位置偏移： (100, 0)  ← 从基准往右 100px

  水平反转后：     (-100, 0) ← 从基准往左 100px
  垂直反转后：     (100, 0)  ← 不变
  全面反转后：     (-100, 0) ← 往左 100px

5.2 入场 / 出场动画也会被翻转

  源动画：slide_left  （从左滑入）
  水平反转 → slide_right（从右滑入）
  垂直反转 → slide_left  （不变）
  全面反转 → slide_right（从右滑入）

  源动画：slide_topleft  （从左上滑入）
  水平反转 → slide_topright （从右上滑入）
  垂直反转 → slide_bottomleft（从左下滑入）
  全面反转 → slide_bottomright（从右下滑入）
📌 缓动曲线不会被反转。
重编排只反转「方向」和「动画类型」，缓动（线性/缓入/缓出/缓入缓出）保持原样。

六、镜像克隆 + 窗口位移动画

如果源编组有一条窗口位移动画在跑，克隆编组也会自动应用同一条动画——除非克隆编组自己有一条专属动画。

  源编组"你好"：有一条动画，往右飞
       ↓
  镜像克隆"你好_镜像克隆版"：
      · 没专属动画 → 自动应用源动画（如果开了重编排，动画方向会反转）
      · 有专属动画 → 用自己的
💡 做「左右对称飞」的标准做法：
① 建一条镜像克隆编组，重编排选「水平反转」
② 给源编组写一条「窗口位移动画」，往右飞
③ 克隆编组会自动应用同一条动画，但因为水平反转，方向变成往左飞
结果：一个往右飞，一个往左飞，完美对称，只需要写一条动画。

七、常见问题

Q1：源编组和目标编组能一样吗？

不能。程序会拒绝，因为会无限递归克隆。目标编组名必须和源编组不同。

Q2：克隆编组能再被镜像克隆吗？

技术上可以（复制一个编组，把它的克隆目标指向另一个新编组），但实际用不到，容易乱。建议只做一层。

Q3：克隆出来的弹窗能单独编辑吗？

不能。克隆是在运行时动态生成的，不在工程文件里。要改就到源编组改，改完克隆自动跟着变。

Q4：为什么「与窗口链接」模式下目标下拉框是灰的？

因为源编组里没有带类名的窗口。链接需要一个「锚点窗口」，源编组至少得有一个窗口有类名。

Q5：克隆编组的弹窗，时间轴上看不到？

对的。克隆是运行时行为，不会在工程的时间轴上出现。它的弹窗出现时间点完全由源编组决定（跟随模式），或由命令触发时间 + 原始相对节拍决定（快照模式）。

Q6：怎么让克隆编组最后一起消失？

写一条「关闭编组内的弹窗」，编组选克隆的目标编组名，放在合适的时机就行。

八、小结

  • 镜像克隆编组 = 把源编组整个复制一份，放到别的位置
  • 两种模式：跟随（源出生时同步克隆） / 快照（命令触发时立即克隆）
  • 位置选择器：屏幕坐标系 / 屏幕对齐 / 与窗口链接 / 屏幕随机
  • 重编排：原样 / 全面反转 / 水平反转 / 垂直反转
  • 重编排会反转位置偏移、入场动画、出场动画，但不反转缓动
  • 源编组有窗口位移动画时，克隆编组会自动应用（方向会被重编排修正）
  • 克隆的弹窗不在工程文件里，改要到源编组改
