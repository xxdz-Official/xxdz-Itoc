🎬 视频框

视频框就是「弹窗里放一个视频播放器」。听起来和图片框差不多，但实现上完全是两回事——图片是 Qt 自己画的，视频是 mpv 进程渲染的，程序要做的是「把 mpv 的窗口吸到 Qt 的容器里」。这个吸来吸去的过程，就是视频框最麻烦也最有意思的地方。

这篇把视频框从「选视频」到「全屏播放」的整个流程讲清楚。mpv 的查找、音量、进度条、右键菜单、透明拦截层，一个都不落。

视频框的播放原理

先讲原理，因为不理解原理，后面很多坑你会觉得莫名其妙。

视频框不是一个真正的「Qt 视频播放器」。它是这样的：

  1. 程序用 subprocess.Popen 启动一个 mpv 进程，让它播放视频。
  2. mpv 会创建一个自己的原生窗口（HWND）。
  3. 程序用 Win32 的 SetParent，把 mpv 窗口的父窗口设成 Qt 的 video_container。
  4. 再用 SetWindowPos / MoveWindow 把 mpv 窗口的尺寸铺满容器。
  5. 这样看起来就像是「视频被嵌在窗口里」了。

这个过程在代码里叫「吸入（suck）」。吸入之后，mpv 窗口就成了 Qt 窗口的子窗口，视觉上完全融合。

💡 为什么要用 mpv？ 因为 Qt 自带的视频播放（QMediaPlayer / QtMultimedia）在 Windows 上对格式支持一般，而且性能不如 mpv。mpv 是业界公认的「什么都能播」的播放器，用它做视频框最稳。

mpv 从哪来

程序不会自带 mpv，需要你自己下载。查找顺序是这样的：

  1. 先看 runCZE/mpv/ 目录。
  2. 再看 runCZE/ 目录本身。
  3. 再遍历 runCZE/ 的一级子目录，找 mpv.exe / mpv.com。

找到多个 mpv 时，优先级是：

  • mpv.com 优先于 mpv.exe（com 版本能正确回传退出码）。
  • 路径里带 v3 的优先（v3 是 mpv 的较新架构）。
  • 路径里带 x86_64 的优先（64 位版本性能更好）。

如果找不到 mpv，程序会弹一个错误框，提示你去 shinchiro 的 SourceForge 下载，解压后把整个文件夹放到 runCZE\ 目录下。

⚠️ 别用太老的 mpv： 有些参数（比如 --window-transparency）在新版 mpv 里被移除了，用了会直接退出。Itoc 目前用的是比较保守的参数集，兼容性还行，但建议用 2024 年之后的 mpv 版本。

选视频

和图片框一样，点「浏览...」选视频文件。支持的格式：

MP4 / WMV / AVI / MOV / MKV / FLV / WebM。

选完之后，程序会自动把视频复制到工程的 video/ 目录（后台线程，不卡 UI）。重名处理和图片一样：大小相同就复用，大小不同就加数字后缀。

保存字段是 video_path，值是相对路径，比如 video/xxx.mp4。

视频信息显示

选完视频后，左侧有一个只读文本框，显示视频的基本信息：

  • 大小：文件大小，MB 为单位。
  • 分辨率：宽 × 高，比如 1920x1080。
  • 帧率：FPS，比如 29.97 FPS。
  • 时长：格式化为 MM:SS。

这些信息是用 OpenCV（cv2.VideoCapture）读的，不是 mpv 读的。所以即使 mpv 没启动，信息也能显示。

同时，程序会把视频的原始宽高通知主面板，更新 W/H 输入框和缩放滑块。

mpv 启动参数

程序启动 mpv 时会带这些参数，这里列出来方便你排查问题：

mpv.exe
  --force-window=yes      # 强制创建窗口
  --no-border             # 无边框（吸入时用）
  --loop=inf              # 循环播放
  --keep-open=yes         # 播完不关闭
  --no-osc                # 不要 mpv 自带的进度条
  --no-input-default-bindings   # 不要 mpv 默认快捷键
  --no-input-cursor       # 不要鼠标光标
  --cursor-autohide=no    # 光标不自动隐藏
  --hwdec=auto            # 硬件解码
  --volume=100            # 音量
  --title=ItocCZEVideo    # 窗口标题（用于查找 hwnd）
  --geometry=-2000-2000   # 初始位置（屏幕外）
  --input-ipc-server=\\.\pipe\itoc_czevid_xxx   # IPC 管道
  --msg-level=all=info    # 日志级别
  video.mp4               # 视频路径

其中 --title=ItocCZEVideo 很关键——程序就是靠这个标题去枚举窗口找 mpv 的 HWND 的。

--input-ipc-server 是 IPC 管道的名字，程序通过这个管道给 mpv 发命令（暂停、seek、调音量）。

音量与静音

视频框的控制栏里有一排音量控件：

  • 音量图标按钮：🔇 / 🔈 / 🔉 / 🔊，根据当前音量自动切换。点击切换静音/取消静音。
  • 音量滑块：0-100，拖动时实时发送 IPC 命令给 mpv 调音量。

音量状态保存在 _video_mpv_volume 和 _video_mpv_muted 里，会写进配置文件：

  • video_volume：0-100 的整数。
  • video_muted：布尔。

加载工程时，程序会调用 apply_video_volume_from_config 恢复音量。如果 mpv 正在跑，会立即下发；如果没跑，会在启动时应用。

💡 加载时不误标修改： 恢复音量时会临时设置 _loading_video_volume = True，防止「设置滑块值」这个动作触发 _mark_video_volume_dirty，导致刚打开工程就被标记为「已修改」。

进度条

视频框的进度条不是轮询 mpv 的 time-pos，而是用本地计时驱动。原理是这样的：

  1. 启动播放时，记录 _video_local_time = 0.0 和 _video_local_last_tick = time.time()。
  2. 每 100ms 执行一次 _poll_video_progress。
  3. 计算 dt = now - last_tick，如果没暂停就把 dt 累加到 _video_local_time。
  4. 用 _video_local_time / duration * 100 算出百分比，设置进度条。
  5. 拖动进度条时，冻结计时（_video_progress_dragging = True），不推进也不覆盖。
  6. 松开进度条时，发送 seek 命令给 mpv，并把本地计时器对齐到目标时间。

时长只查一次，通过 IPC 的 get_property duration 获取，存在 _video_mpv_duration 里。

💡 全局鼠标松开监听： ttk.Scale 内部可能会吃掉鼠标松开事件，导致 _on_video_progress_release 不触发。所以程序额外在 toplevel 上绑了 <ButtonRelease-1>，只在拖动进度条时响应。

播放 / 暂停 / 停止

控制栏有三个按钮：

  • ▶ / ⏸：播放/暂停切换。如果 mpv 没跑，点它会启动 mpv 并自动播放；如果 mpv 在跑，点它会切换暂停状态。
  • ■：停止。发送 seek 0 absolute + set_property pause true，回到开头并暂停。同时重置本地计时器。

暂停时会重置 _video_local_last_tick，防止暂停期间时间继续累计。这是本地计时驱动的关键细节。

全屏播放

右键视频预览区域，菜单里有个「全屏播放」。点击后的流程是：

  1. 创建一个无边框、置顶的 Toplevel 窗口，铺满屏幕。
  2. 在里面放一个 Canvas 作为视频容器。
  3. 如果 mpv 已经在跑，直接把 mpv 窗口重新 SetParent 到全屏容器。
  4. 如果 mpv 没跑，先在全屏窗口里启动 mpv，启动完成后自动吸到全屏。
  5. 注册 ESC 低级键盘钩子（因为 mpv 会抢焦点，Tk 的 ESC 绑定收不到）。
  6. 按 ESC 退出全屏，把 mpv 吸回原来的 video_container。

全屏时，程序会做这些「重排」操作：

  • MoveWindow(hwnd, -100, -100, 1, 1)：先把 mpv 缩到 1×1，强制它重建交换链。
  • SetParent(hwnd, 0)：先脱离父窗口。
  • SetParent(hwnd, 新父窗口)：重新设置父窗口。
  • 多次延迟调用 _resize_video_mpv_window_fullscreen，确保 mpv 铺满全屏。
  • 发送 video-zoom / video-align-x / video-align-y 命令，强制 mpv 刷新画面（全屏后黑屏的修复）。
⚠️ ESC 钩子的坑： 低级键盘钩子运行在 Windows 钩子线程里，没有 GIL，绝对不能碰任何 Python 对象。所以回调里只设置一个 ctypes.c_int 标志位，主线程用 after(30, poll) 定期轮询。这个设计很重要，不然后台线程直接操作 Tk 会崩。

透明拦截层

mpv 被吸入之后，会覆盖整个 video_container，鼠标事件全被 mpv 吃掉了。这意味着你在视频区域点右键，Tk 收不到事件，右键菜单弹不出来。

解决办法：在 mpv 窗口之上再叠一个几乎全透明的 Tk Frame，用 place(relwidth=1, relheight=1) 铺满容器，专门接收右键事件。

这个拦截层是这么做的：

  1. 创建一个 tk.Frame，背景黑色，放在 video_container 里。
  2. place(x=0, y=0, relwidth=1, relheight=1) 铺满。
  3. 用 Win32 的 SetWindowPos(HWND_TOP) 把它置于 mpv 之上。
  4. 用 SetLayeredWindowAttributes(alpha=1) 把它的透明度设成 1/255（几乎全透明，但仍然接收鼠标）。
  5. 延迟多次执行「提升到顶层」，防止 mpv 重绘后把它盖住。

全屏模式也有一套对应的拦截层（_ensure_video_fullscreen_right_click_overlay）。

视频缩放

视频框的缩放百分比和图片框一样：滑块 → 通知主面板 W/H → 主面板更新自定义尺寸 → 弹窗按 W/H 显示。

区别在于：视频的原始宽高是 cv2.VideoCapture 读的，不是 PIL 读的。读完之后存到 _video_orig_width / _video_orig_height。

视频框的缩放滑块状态同样受主面板的「自定义尺寸」复选框控制。勾了自定义尺寸 → 滑块启用；没勾 → 滑块禁用。

视频框不支持的东西

因为视频框本质是 mpv 的窗口，有些东西它和普通弹窗不一样：

  • 工具窗样式：不支持。样式钮对话框里「Windows 工具窗」单选框会被禁用。如果你之前给视频框保存过 tool_fixed，打开对话框会自动回退到 normal_fixed。
  • 亚克力/云母：不支持。mpv 窗口不受 Qt 的透明背景控制。
  • 镂空：不支持。视频框没有「镂空」概念。
  • 按钮区：不生效。视频框没有「确定 / 取消」按钮。
  • 图标下拉框：禁用。视频框不显示标题栏图标（mpv 的窗口没有 Qt 图标）。

控制钮里只有「关闭」是有效的，「最大化」「最小化」会被 mpv 忽略。这是 mpv 自身的窗口样式决定的。

常见问题

Q：视频播放黑屏 / 无声？

A：按顺序检查：① mpv 是否正确启动（看控制台有没有「mpv 已启动，PID=xxx」）；② 视频文件是否真的存在（相对路径解析是否正确）；③ 音量是否被静音或设成 0；④ 是否处于暂停状态。如果日志里能看到 [CZE视频/进度] t=1.23s，说明 mpv 在跑，问题可能在画面渲染或音频输出。

Q：视频区域右键菜单弹不出来？

A：透明拦截层可能没创建成功。正常情况下 _suck_video_mpv_window 完成后 200ms 会调用 _ensure_video_right_click_overlay。如果没触发，检查日志里有没有「已创建透明拦截层」。

Q：全屏后黑屏？

A：这是 mpv 全屏后常见的现象。程序会发送 video-zoom / video-align-x / video-align-y 和暂停/播放命令来强制刷新画面。如果还是黑屏，可能是 mpv 版本太老或者显卡驱动问题，试试更新 mpv 或者关掉 --hwdec=auto（改成 --hwdec=no）。

Q：拖动进度条后画面和进度对不上？

A：本地计时器会在松开进度条时对齐到目标时间，但 mpv 的实际播放位置可能有几百毫秒的延迟。这是正常的，不影响使用。如果差得特别多，可能是 seek 命令没发出去（mpv 已经退出）。

Q：视频框能不能不显示任务栏图标？

A：可以。不勾「在任务栏显示」，程序会给 mpv 窗口加 WS_EX_TOOLWINDOW 并移除 WS_EX_APPWINDOW。但注意 mpv 有时候会重建窗口，样式可能被重置，程序会在窗口句柄拿到后多次重试应用样式。

小结

视频框的四件事：

  1. mpv 要自己下：放到 runCZE/mpv/，优先 mpv.com + v3 + x86_64。
  2. 吸入原理：SetParent + MoveWindow，把 mpv 窗口塞进 Qt 容器。
  3. 三件套：音量（IPC 实时下发）、进度（本地计时驱动）、全屏（ESC 钩子 + 重排）。
  4. 透明拦截层：mpv 会吃掉鼠标事件，需要叠一个透明 Tk Frame 接右键。

视频框是 Itoc 里技术含量最高、坑最多的窗口。但只要 mpv 放对位置、路径解析对，剩下的它自己会搞定。玩得开心喵 ( ⓛ ω ⓛ *)
