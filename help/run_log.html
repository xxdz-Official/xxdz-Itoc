📜 运行日志

「运行日志」是测试运行模块新增的独立面板。它用来显示解释器的控制台输出，尤其是当你使用控制台版解释器并开启内嵌控制台模式时，所有 stdout / stderr 都会被捕获到这里，方便排查弹窗、资源、命令执行等问题。

📌 本篇的范围：
讲运行日志选项卡的界面、按钮、内嵌控制台模式、查找、右键菜单、快捷键和常见问题。测试运行整体流程请阅读 《测试运行》；解释器路径配置请阅读 《解释器自定义配置》。

一、运行日志在哪里？

运行日志通常以主界面多标签区域中的一个选项卡出现，标题为「运行日志」。测试运行启动时，如果开启了内嵌控制台模式，程序会自动切换到该选项卡并开始写入输出。

它主要服务于这些场景：

  • 查看 runCZE 解释器的控制台打印、报错、调试信息
  • 确认测试运行到底用了哪个解释器、工作目录是什么
  • 观察资源复制、音频导出、阵列导出等过程的日志
  • 解释器闪退时，第一时间看到错误原因
  • 把日志复制或另存为 txt，发给别人排查

二、界面组成

2.1 顶部工具栏

按钮 / 控件作用
清空日志清空当前日志文本，不影响正在运行的进程
停止进程结束当前由运行日志启动的进程，并尝试结束整个进程树
自动滚动勾选后，新日志出现时自动滚动到底部
复制全部把当前日志全文复制到剪贴板
另存为...把当前日志保存为 .txt 文件，默认文件名类似 Itoc_RunLog_日期_时间.txt
🔍 查找打开右侧查找面板，支持高亮、上一个、下一个
内嵌控制台模式勾选后，测试运行会用管道捕获控制台解释器输出到本选项卡；不勾选则使用解释器自带的独立控制台窗口
内嵌控制台模式设置...打开「配置测试运行解释器」窗口，可同时设置解释器路径和内嵌控制台模式

2.2 状态栏

右上角会显示当前状态，例如：

  • 状态：未运行
  • 状态：启动中...
  • 状态：运行中 PID=xxxx
  • 状态：已结束 退出码=0
  • 状态：已停止
  • 状态：日志已复制
  • 状态：已保存到 xxx.txt

2.3 日志区

日志区是一个深色只读文本区域，使用微软雅黑字体，自动换行。它会自动保留最近约 5000 行，超出后自动裁剪旧行，避免长时间运行占用过多内存。

💡 日志区是只读的：
你不能直接在日志区输入文字，但可以选中、复制、全选。右键菜单只保留“复制”和“全选”。

2.4 查找面板

点击「🔍 查找」或按 Ctrl + F 会从右侧打开查找面板。它和代码视图的查找类似，但只用于日志。

功能说明
查找输入框支持多行输入，输入后自动高亮所有匹配
上一个 / 下一个在匹配项之间跳转
区分大小写开启后大小写敏感
全字匹配只匹配完整单词边界
正则表达式把查找内容当作正则表达式
多行模式允许查找内容跨行匹配
循环查找到末尾后自动回到开头，到开头后自动跳到末尾
关闭 ✕关闭查找面板并清除高亮

快捷键：

  • Ctrl + F：打开 / 关闭查找面板
  • F3：查找下一个
  • Shift + F3：查找上一个
  • Esc：关闭查找面板
  • Enter：在查找输入框中按，等于“下一个”

三、内嵌控制台模式

「内嵌控制台模式」决定测试运行时解释器的输出去哪里，以及你获得的是“IDE 式日志体验”还是“原生控制台实时体验”。

状态行为
关闭（默认）测试运行使用解释器自带的独立控制台窗口。运行日志选项卡不会显示该解释器输出，只会写一些提示。
开启如果解释器是控制台 exe，程序会用 subprocess.Popen 管道捕获 stdout / stderr，并逐行刷新到运行日志。
开启，但解释器是窗口模式窗口 exe 没有控制台输出可抓取。运行日志会提示“窗口模式（无输出）”，实际效果看桌面窗口。

3.1 内嵌控制台模式的利与弊

内嵌控制台模式不是“纯升级”，它是一次取舍：用一点点实时性，换取完整的 IDE 式日志体验。

方面说明
利：强化 IDE 体验 解释器输出不再是一个孤立的黑色控制台窗口，而是进入主界面的「运行日志」选项卡。你不用在多个窗口之间 Alt+Tab，调试时视线不用离开编辑器。
利：方便复制控制台 原生控制台窗口复制文字往往很别扭：要右键、标记、拖选、回车。运行日志里可以直接鼠标拖选，右键“复制”，或者一键「复制全部」，把整段日志丢进论坛、聊天窗口或文本编辑器。
利：方便查找控制台 原生控制台基本没有像样的查找功能。运行日志自带查找面板：Ctrl + F 打开，支持上一个 / 下一个、区分大小写、全字匹配、正则表达式、多行模式、循环查找，还能把所有匹配高亮出来。
利：日志可管理 解释器崩掉日志不丢失！且支持清空日志、自动滚动、复制全部、另存为 .txt。排查完一个问题，可以直接把日志存档或发给别人。
利：停止进程更方便 运行日志自带「停止进程」按钮，会用 taskkill /F /T /PID 结束整个进程树，不用手动去任务管理器找或者关掉控制台窗口（其实差不多）。
大弊：刷新不如原生控制台实时 因为输出是经过管道捕获的：解释器写入 stdout / stderr → 管道 → 后台读线程 → 队列 → 主线程定时刷新到 Text 控件。这条链路比“解释器直接写自己的控制台窗口”多绕了几步，所以日志刷新会有轻微延迟，不是逐字节即时显示。对于打印量很大、刷新极快的程序，体感上会不如原生控制台窗口那么“跟手”。
💡 怎么选？
· 需要实时盯输出、程序刷屏很快 → 关闭内嵌控制台模式，用解释器自带的独立控制台窗口。
· 需要复制、查找、存档、IDE 内调试 → 开启内嵌控制台模式，用「运行日志」选项卡。

3.2 如何判断控制台 exe？

程序会读取 PE 头，判断 Subsystem 是否为 IMAGE_SUBSYSTEM_WINDOWS_CUI（值为 3）。如果是，就按控制台程序处理。若 PE 解析失败，则根据文件名兜底：包含 window 视为窗口，包含 console 或 runcze 视为控制台。

3.3 设置保存在哪里？

内嵌控制台模式会保存到 shezhi.txt 的：

console_mode=True

或

console_mode=False

「运行日志」选项卡的复选框和「配置Itoc测试运行解释器」窗口里的复选框会互相同步。

3.4 管道捕获时做了什么？

  • 工作目录切换到 runCZE
  • 设置 PYTHONIOENCODING=utf-8、PYTHONUTF8=1
  • Windows 下使用 CREATE_NO_WINDOW | CREATE_NEW_PROCESS_GROUP
  • stdout 与 stderr 合并捕获
  • 后台线程逐行读取，尝试 utf-8、gbk、cp936、utf-16、latin-1 解码，尽量解决中文乱码
  • 主线程定时把队列内容刷新到日志区
  • 进程退出后写入退出码，并触发回调恢复“测试运行”按钮
💡 推荐：
排查问题时，使用 runCZEx64.exe 这类控制台解释器，并开启「内嵌控制台模式」。这样报错、堆栈、打印都会出现在运行日志里。

四、日志管理

4.1 清空日志

点击「清空日志」会清空当前显示内容，但不会停止正在运行的进程。新输出仍会继续追加。

4.2 停止进程

点击「停止进程」会结束当前由运行日志启动的进程。Windows 下使用：

taskkill /F /T /PID <pid>

/T 表示同时结束子进程树，适合解释器又启动了 mpv 等子进程的情况。

4.3 复制全部

把日志全文复制到剪贴板，方便粘贴到论坛、聊天窗口或文本编辑器。

4.4 另存为

把日志保存为 .txt 文件。默认文件名格式：

Itoc_RunLog_%Y%m%d_%H%M%S.txt

如果日志为空，会提示“日志内容为空，未保存”。

4.5 自动滚动

默认开启。新日志写入时自动滚动到底部。如果你想往上翻看旧日志，可以取消勾选，避免被新日志打断。

五、右键菜单与快捷键

5.1 日志区右键菜单

日志区是只读的，右键菜单只保留：

  • 复制
  • 全选

没有粘贴、剪切、删除等编辑项，因为日志区不允许直接修改。

5.2 查找框右键菜单

查找输入框是可编辑的，右键菜单包含：

  • 撤销、重做
  • 剪切、复制、粘贴、删除
  • 全选

5.3 快捷键拦截

运行日志会拦截 Ctrl + C、Ctrl + V、Ctrl + X、Ctrl + A，避免这些快捷键穿透到主程序，造成“选中整个界面”之类的异常。撤销 / 重做等快捷键不会被拦截。

六、常见问题

Q1：运行日志一直没有输出？

先确认是否勾选了「内嵌控制台模式」。如果没勾选，测试运行会使用解释器自带的独立控制台窗口，运行日志不捕获输出。

Q2：勾选了内嵌控制台模式，还是没有输出？

可能你用的解释器是窗口模式 exe，例如 runCZEx64window.exe。窗口程序没有控制台输出，运行日志只能提示“窗口模式（无输出）”。请改用 runCZEx64.exe 这类控制台解释器。

Q3：日志中文乱码怎么办？

程序已经尝试多种编码解码。如果仍然乱码，可能是解释器输出用了非常规编码。可以先把日志另存为 txt，再用其他工具查看。也可以在解释器侧统一输出 UTF-8。

Q4：为什么日志刷新感觉比原生控制台慢？

因为内嵌控制台模式走的是管道捕获：解释器写 stdout / stderr → 管道 → 后台线程读取 → 队列 → 主线程定时刷新。比原生控制台直接写自己的窗口多绕了几步，所以会有一点延迟。这是为复制、查找、存档等 IDE 式体验付出的代价。如果必须逐字实时，请关闭内嵌控制台模式。

Q5：为什么 Ctrl+A 不会选中整个主界面？

因为运行日志拦截了 Ctrl + A，只全选日志文本。这是为了避免快捷键穿透到主程序。

Q6：日志太长会卡吗？

不会。运行日志默认最多保留约 5000 行，超出会自动裁剪旧行。长时间运行也不会无限增长。

Q7：停止进程会杀掉 mpv 吗？

「停止进程」使用 taskkill /F /T /PID，会结束该进程树。测试运行启动前的旧进程清理还会额外扫描 runCZE 启动的 mpv。侧边栏参考媒体 / 显示器的 mpv 会被保护，不会被误杀。

Q8：运行日志和终端有什么区别？

「终端」更偏向通用命令行交互；「运行日志」专注显示测试运行解释器的控制台输出，并提供自动滚动、复制全部、另存为、查找、停止进程等专用按钮。

七、小结

  • 运行日志是测试运行的配套面板，用于查看解释器控制台输出
  • 核心开关是「内嵌控制台模式」
  • 不勾选：使用解释器自带独立控制台窗口，运行日志不捕获，但输出更实时
  • 勾选 + 控制台解释器：管道捕获输出到运行日志，强化 IDE 体验，方便复制、查找、存档，但刷新不如原生控制台实时
  • 勾选 + 窗口解释器：无控制台输出，只提示看桌面窗口
  • 支持清空、停止、自动滚动、复制全部、另存为、查找
  • 设置保存到 shezhi.txt 的 console_mode
  • 查找快捷键：Ctrl + F、F3、Shift + F3

配合 《测试运行》 一起看，基本就能覆盖“跑工程”和“看输出”两件事。玩得开心喵 ( ⓛ ω ⓛ *)
