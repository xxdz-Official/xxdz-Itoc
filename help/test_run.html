▶️ 测试运行

前面我们讲了 CZEmaker 弹窗、全局命令、音符块、调整图层、过渡动画、批量赋音效、渲染为音频文件、渲染视频文件、渲染为 Python 代码、渲染为 CZE 数据文件、编译为 exe、组装打包模式、解释器自定义配置。现在讲一个高频使用的功能——测试运行。它让你不用导出、不用编译，按一下 F5 就能立刻看到工程跑起来的样子。

本次测试运行模块还新增了更完整的运行日志与内嵌控制台模式支持。关于日志面板的详细用法，请配合阅读：《运行日志》。

📌 本篇的范围：
讲的是测试运行的入口、前置条件、完整流程、解释器选择、资源处理、内嵌控制台模式和常见问题。关于解释器配置本身，请参考《解释器自定义配置》文档；关于编译分发，请参考《编译为 exe》和《组装打包模式》文档；关于日志面板，请参考《运行日志》。

一、这个功能是干嘛的？

测试运行就是“把工程立刻跑一遍看看效果”。它会自动完成下面这些事：

  1. 把工程转换成 runCZE.CzeData 数据文件
  2. 把工程用到的图片、视频、音频、文档等资源复制到 runCZE 目录
  3. 把背景音频复制并重命名为 runCZE/Audio.mp3
  4. 结束掉已经运行的旧解释器进程，并额外清理 runCZE 启动的 mpv 残留进程
  5. 启动解释器，播放弹窗
  6. 如果开启「内嵌控制台模式」，还会把解释器控制台输出捕获到「运行日志」选项卡

整个过程一步到位，你只需要按一下 F5。适合在编辑过程中随时看效果。

二、从哪里打开？

菜单位置：「编译(C)」 → 「一键测试运行」。

快捷键：F5。

💡 工具栏也有入口：
主界面上方的“快捷操作栏²”里有一个测试运行按钮（图标是一个播放三角），点它和按 F5 效果一样。

前置条件

检查项不满足时的提示怎么解决
是否有打开的工程“请先打开或保存一个工程文件”先新建或打开一个工程
工程里是否有音符“当前工程没有音符数据”先在时间轴上画几个音符

如果工程已经改过（标题栏工程名带 *），会先弹一个确认框：

选项作用
是先保存工程，再测试运行
否不保存，用未保存的修改测试运行
取消取消本次测试运行
💡 建议选“是”：
因为测试运行读的是工程里的数据。如果你改了但没保存，测试出来的效果可能不是你最新的修改。而且保存后再测试运行，如果测试出问题，回滚时也有一个干净的起点。

三、完整流程

按 F5 后，程序会在后台依次执行下面的步骤。整个过程很快，通常一两秒就完成了。

3.1 导出 CzeData

把工程里的音符、命令、调整图层从“节拍”单位转换成“秒”单位，生成 runCZE/runCZE.CzeData 文件。

同时会导出这些数据：

  • 模类数据（ui_Class 和 class_data_project）
  • 阵列定义（工程内置 + Itoc 全局）
  • 全局随机种子（如果工程里设置过）
  • 音频文件路径信息
📌 另有“仅导出 CzeData 为 txt”：
部分界面中提供“导出 CzeData 为 txt”入口。它只生成 runCZE/runCZE.CzeData.txt，内容与 CzeData 一致，但不会复制资源，也不会启动解释器，适合只想查看数据文件的场景。

3.2 复制资源文件

程序会深度扫描工程数据里引用的所有文件路径，把存在的文件按类型复制到 runCZE 目录下的对应子目录：

文件类型目标目录
图片（png / jpg / jpeg / bmp / gif / webp / ico / svg）runCZE/img/
视频（mp4 / wmv / avi / mov / mkv / flv / webm）runCZE/video/
音频（mp3 / wav / ogg / flac / aac / m4a）runCZE/audio/
文档（txt / pdf / doc / docx / xls / xlsx / ppt / pptx）runCZE/docs/
其他文件runCZE/files/

复制时会检查目标文件是否已存在。如果内容相同（比较 MD5 或文件大小），会跳过；如果内容不同，会覆盖。

📌 相对路径解析：
如果工程里的文件路径是相对路径，程序会基于工程文件所在目录尝试多种组合来找到实际文件，包括直接在工程目录、在 img/ 子目录、在 srt/ 子目录等。

3.3 复制背景音频

如果工程关联了背景音频，程序会把它复制到 runCZE/Audio.mp3，解释器启动时会自动读取这个文件播放。

音频路径无论是相对路径还是绝对路径，都会被正确解析。如果工程里存的是相对路径 audio/xxx.mp3，程序会基于工程目录找到实际文件。

3.4 结束旧进程与清理 mpv

在启动新解释器之前，程序会先检查是否已经有一个同名解释器进程在运行（比如 runCZEx64window.exe 或 runCZEx64.exe）。如果有，会先用 taskkill 结束它，然后等 1 秒，再启动新的。

除此之外，测试运行还会额外扫描并清理由 runCZE 启动的 mpv 子进程，避免视频弹窗、音频弹窗、视频壁纸残留。

清理对象识别特征
runCZE 视频弹窗 mpv命令行包含 itoc_video_
runCZE 音频播放 mpv命令行包含 itoc_audio_
runCZE 视频壁纸 mpv命令行包含 --wid=0
💡 侧边栏的 mpv 不会被误杀：
如果 mpv 命令行包含 ItocReferenceMedia、ItocDisplayVideo、itoc_mpv_、itoc_display_，会被视为侧边栏“参考媒体”或“显示器”的 mpv，测试运行不会结束它们。

3.5 启动解释器

程序切换到 runCZE 目录，然后启动解释器。解释器会读取 runCZE.CzeData，按照时间轴播放弹窗、执行命令、显示动画。

启动方式取决于是否开启「内嵌控制台模式」：

模式启动方式输出位置
内嵌控制台模式：关闭解释器使用自带的独立控制台窗口启动独立控制台窗口，运行日志选项卡不显示输出
内嵌控制台模式：开启如果解释器是控制台 exe，则用管道捕获 stdout/stderr输出显示在「运行日志」选项卡
内嵌控制台模式：开启，但解释器是窗口模式窗口程序没有控制台输出可抓取运行日志只给提示，实际看桌面窗口

四、解释器怎么选？

测试运行使用哪个解释器，有一个明确的优先级顺序：

优先级来源说明
1测试运行专用解释器在「配置Itoc测试运行解释器」里配置的路径
2主解释器配置在「配置Itoc解释器」里当前选中模式的路径
3默认控制台模式runCZE/runCZEx64.exe
4默认窗口模式runCZE/runCZEx64window.exe
💡 推荐配置：
· 平时测试想看日志 → 把测试运行解释器配成“64位 - 控制台”，并开启「内嵌控制台模式」。
· 平时测试想看效果 → 测试运行解释器留空，用主解释器的“64位 - 窗口”模式；内嵌控制台模式可关闭。

五、运行日志与内嵌控制台模式

测试运行模块现在和「运行日志」选项卡联动。你可以在「运行日志」选项卡里：

  • 查看解释器控制台输出
  • 清空日志、停止进程、自动滚动
  • 复制全部、另存为 .txt
  • 用 Ctrl + F 打开查找面板，支持上一个/下一个、正则、全字匹配、多行模式等
  • 勾选或取消「内嵌控制台模式」
  • 点击「内嵌控制台模式设置...」打开测试运行解释器配置窗口

内嵌控制台模式的设置会保存到 shezhi.txt 的 console_mode 项，并且与「配置测试运行解释器」窗口里的复选框同步。

📌 详细说明：
运行日志面板的按钮、查找、右键菜单、快捷键、停止进程、另存为等细节，请阅读 《运行日志》。

六、相关菜单项

「编译(C)」菜单里除了“一键测试运行”，还有几个和测试相关的菜单项：

菜单项作用
一键测试运行执行完整的测试运行流程（F5）
结束进程手动结束正在运行的 runCZEx64.exe 等解释器进程，并清理 runCZE 启动的 mpv
重启进程先结束进程，再重新测试运行一次
将 测试运行引用资源目录 打开于资源管理器打开 runCZE/img/ 目录，方便查看复制的资源
删除测试运行引用资源文件清空 runCZE/img/ 目录里的所有文件
配置Itoc测试运行解释器打开测试运行解释器配置窗口，可同时设置内嵌控制台模式
导出 CzeData 为 txt（若界面提供）只导出 runCZE/runCZE.CzeData.txt，不复制资源、不启动解释器

6.1 结束进程

如果你测试时解释器卡住了，或者窗口关不掉，可以用“结束进程”强制结束。它会用 taskkill /F /IM 结束掉所有同名的解释器进程，并额外清理 runCZE 启动的 mpv 子进程。

6.2 重启进程

相当于“结束进程 + 测试运行”的组合操作。适合测试过程中改了工程，想立刻重新跑一遍的场景。

6.3 打开资源目录

打开 runCZE/img/ 文件夹。测试运行复制的图片都在这里，可以检查是否正确复制、文件名是否对得上。

6.4 删除测试资源

清空 runCZE/img/ 目录里的所有文件。适合工程里图片改了很多，想从头重新复制一遍的场景。删完之后再按 F5，会重新复制所有资源。

⚠️ 删除资源后首次运行会稍慢：
因为所有图片都要重新复制一遍。之后的运行会走“跳过相同文件”的快速路径。

七、测试运行都生成了什么？

测试运行会在 runCZE 目录下生成这些内容：

文件/目录内容
runCZE.CzeData工程数据文件（秒单位）
runCZE.CzeData.txt仅“导出 CzeData 为 txt”时生成，不参与测试运行启动
Audio.mp3背景音频（如果工程关联了音频）
img/图片资源
video/视频资源
audio/音频资源
docs/文档资源
files/其他文件
📌 这些文件会自动保留：
测试运行生成的文件不会自动删除。下次测试运行时会检查并更新它们。如果你想让工程干净一点，可以用“删除测试运行引用资源文件”手动清理。

八、常见问题

Q1：按 F5 没反应？

检查前置条件：有没有打开的工程、工程里有没有音符。如果工程已修改，确认框可能被其他窗口挡住了。

Q2：测试运行时弹窗和图片没显示？

看日志里“深度查找文件”部分，确认图片路径是否正确解析、文件是否存在。如果图片路径是相对路径，检查工程目录下是否有对应文件。也可以用“打开资源目录”看看 img/ 里有没有图。

Q3：背景音频没播放？

检查 runCZE/Audio.mp3 是否存在。如果不存在，说明工程里没有关联音频，或者音频路径解析失败。看日志里 [音频导出] 开头的行，会说明具体情况。

Q4：连续按 F5 会弹好几个窗口？

不会。测试运行会先结束旧的解释器进程，再启动新的。所以你连续按 F5，始终只有一个解释器窗口。它还会额外清理 runCZE 启动的 mpv 残留。

Q5：解释器启动后立刻闪退？

可能是数据有问题，或者解释器本身出错了。试试把测试运行解释器配成“控制台模式”，并开启「内嵌控制台模式」，这样能在「运行日志」选项卡看到报错信息。

Q6：测试运行很慢？

第一次测试运行会比较慢，因为要复制所有资源。之后的运行会走“跳过相同文件”的快速路径，通常一两秒就完成。如果资源特别多（几百张图），第一次会比较久。

Q7：怎么知道测试运行用的是哪个解释器？

看日志里 [测试运行解释器] 开头的行，会明确写出当前使用的是自定义测试解释器、主解释器配置，还是默认解释器。

Q8：为什么「运行日志」没有输出？

通常是三个原因：

  1. 没有勾选「内嵌控制台模式」；
  2. 解释器是窗口模式 exe，本身没有控制台输出；
  3. 进程还没真正启动，或者启动失败后回退到了 os.startfile。

想看输出，请使用控制台解释器，并在「运行日志」选项卡勾选「内嵌控制台模式」。

Q9：内嵌控制台模式在哪里设置？

两个地方都可以：

  • 「运行日志」选项卡上的「内嵌控制台模式」复选框；
  • 「配置Itoc测试运行解释器」窗口里的「内嵌控制台模式」复选框。

两处会同步，并写入 shezhi.txt 的 console_mode。

Q10：测试运行和编译 exe 有什么区别？

测试运行是“直接跑”，用现成的解释器读取 CzeData，速度快，不需要编译。编译 exe 是“打包成独立程序”，用 PyInstaller 把 Python 代码和依赖一起打包，速度慢，但可以分发给没有 Python 环境的人。

Q11：测试运行会修改我的工程文件吗？

不会。测试运行只读取工程文件，在 runCZE 目录下生成新文件，不会改动 .czemidi 工程文件本身。如果选了“是”保存，那保存的是你之前的编辑修改，不是测试运行造成的。

Q12：可以只测试运行一部分吗？

不支持。测试运行会处理整个工程。如果你想只看某一段，可以先用时间选区圈出范围，然后导出工程片段，再对片段测试运行。

Q13：测试运行后，窗口关不掉怎么办？

用「编译(C)」→「结束进程」强制结束。如果还不行，打开任务管理器，找到 runCZEx64window.exe 或 runCZEx64.exe，手动结束任务。测试运行的结束进程也会清理 runCZE 启动的 mpv。

Q14：测试运行时，主程序会卡住吗？

不会。测试运行是在后台线程里执行的，主程序界面仍然可以操作。不过启动解释器的瞬间可能会有一点点延迟，属于正常现象。

九、小结

「测试运行」是编辑过程中最常用的功能，让你随时看到工程跑起来的样子。

  • 入口：菜单「编译(C)」→「一键测试运行」，或 F5
  • 前置条件：有打开的工程 + 有音符数据
  • 自动完成：导出 CzeData → 复制资源 → 复制音频 → 结束旧进程/清理 mpv → 启动解释器
  • 解释器优先级：测试专用 > 主解释器 > 默认控制台 > 默认窗口
  • 资源按类型分类复制到 runCZE/ 下的子目录
  • 相关菜单：结束进程、重启进程、打开资源目录、删除测试资源、配置测试运行解释器
  • 不会修改工程文件，只读取数据生成临时文件
  • 要查看控制台输出，请配合 《运行日志》 与「内嵌控制台模式」
