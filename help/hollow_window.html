🪟 镂空窗口

“镂空”这个词在 Itoc 里其实指两件不同的事，别搞混喵：

  • 图片镂空：图片框专属。让图片的背景透明，只留下图片主体。入口是图片框面板里的「镂空图片窗口」复选框。
  • 窗口背景镂空：所有窗口类型都能用（除图片镂空外）。让窗口的背景透明，但保留标题栏和控件。入口是样式钮设置对话框里的「窗口背景」复选框——取消勾选就启用了。

两者都叫“镂空”，但实现原理、视觉表现、适用场景完全不同。这篇把两种都讲清楚，最后再做一个对比表，帮你判断什么时候该用哪个。

💡 一句话区分：
图片镂空 = 图片自己透明，窗口整体无边框，透明的是「图片的背景」。
窗口背景镂空 = 窗口背景透明，标题栏还在，透明的是「窗口的背景」。

一、两种镂空速览

图片镂空（hollow） 窗口背景镂空（色键透明）
触发入口 图片框面板 →「镂空图片窗口」复选框 样式钮 →「窗口背景」复选框取消勾选
作用对象 图片（图片框专属） 窗口背景（所有窗口类型）
透明实现 Qt WA_TranslucentBackground + 图片 alpha / 色度抠图 Win32 SetLayeredWindowAttributes(LWA_COLORKEY)
标题栏 无（强制无边框） 保留
控件 只有图片 图标、文本、按钮区都保留
透明范围 图片背景（像素级） 窗口背景（整块）
支持的窗口类型 仅图片框 普通弹窗、图片框（非镂空）、模类框
与亚克力的关系 互斥 互斥（取消背景 → 自动取消亚克力）
平台限制 Qt 跨平台 仅 Windows（sys.platform == 'win32'）

下面分两部分详细讲。

二、图片镂空（hollow）

2.1 什么时候用

图片镂空只对「图片框」窗口类型生效。常规弹窗（信息框/警告框等）、视频框、模类框都不走这套逻辑。

适合的场景：

  • PNG 透明图标、贴纸、圆形头像、异形 logo。
  • 带透明通道的 GIF 动图（部分 GIF 支持）。
  • 纯色背景的图片，比如在绿幕前拍的素材、白色背景的图标。

不适合的场景：

  • 照片、壁纸、带复杂渐变背景的图片（抠图会很难看）。
  • 需要保留完整矩形边框的图（比如截图、UI 稿）。
  • 视频框（镂空只对图片框生效）。
💡 图片镂空和无边框是绑定的： 一旦勾选镂空，图片框会自动走无边框路径，忽略样式钮里的窗口样式。这是因为有边框窗口的标题栏会遮挡透明区域，视觉上很别扭。

2.2 两种模式：alpha 与 chroma

图片镂空有两种模式，分别对应不同的透明实现：

透明通道（alpha）

这是最干净的镂空方式。它直接使用图片自带的透明通道（Alpha Channel），不做任何颜色替换。PNG 图片天然支持透明通道，所以选 PNG 时通常会自动使用这个模式。

原理： 窗口设置 Qt.WA_TranslucentBackground，QLabel 设置 background-color: transparent，然后直接把带透明通道的 pixmap 显示出来。Qt 会自动把 alpha=0 的像素渲染成透明。

优点：

  • 完全无损，像素级的透明，边缘锐利。
  • 支持半透明（alpha 值 0-255 之间），可以做柔和边缘、阴影、光晕。
  • 不需要设置透明色，配置最少。

缺点：

  • 只对带透明通道的图片有效（PNG、GIF 部分帧、WebP）。
  • JPG、BMP 这类不支持透明的格式，alpha 模式等于没效果（整张图不透明）。

自动切换： 当你选择一张 PNG 图片，并且镂空已勾选时，程序会自动把模式切到 alpha。如果你手动切到 chroma，程序也不会强制切回来，尊重你的选择。

色度抠图（chroma）

这是「绿幕抠像」的思路。你指定一个颜色（比如纯绿 #00FF00），程序会遍历图片的每一个像素，把 RGB 值完全等于这个颜色的像素改成透明（alpha=0）。

原理： 加载图片 → 转成 QImage.Format_ARGB32 → 逐像素比较 RGB → 命中的像素设置 QColor(r, g, b, 0) → 转回 QPixmap 显示。

优点：

  • 不要求图片自带透明通道，JPG、BMP 也能用。
  • 对纯色背景的图片效果很好。

缺点：

  • 容差为 0：RGB 必须完全相等才透明。如果图片有噪点、压缩伪影、抗锯齿边缘，抠不干净，会留下一圈色边。
  • 不支持半透明，抠掉的像素是完全透明，剩下的像素是完全不透明。
  • 逐像素遍历，大图会比较慢（但只在加载时执行一次）。
⚠️ 重要提示： 色度抠图的容差是 0，也就是说只有 RGB 完全等于目标色的像素才会透明。如果你的绿幕图有噪点、渐变、抗锯齿边缘，抠出来会有一圈绿色毛边。想抠干净，请用专业工具（Photoshop、GIMP）预处理，或者直接用 PNG 透明通道模式。

2.3 透明色与拾取器

只有在「镂空已勾选 且 色度抠图模式」时，透明色相关的控件才会启用。透明色由 hollow_color 字段控制，是十六进制 RGB 字符串（如 #00FF00）。

透明色输入框旁边有几个辅助控件：

  • 输入框本身： 可以直接手动输入十六进制值。
  • 「选择」按钮： 打开系统颜色选择器，可视化挑颜色。
  • 「拾取」按钮： 打开图片拾取器，从图片上取色。

图片拾取器

点击「拾取」按钮会打开一个独立的拾取窗口（600×700，模态）。窗口里显示当前图片的完整画面，你可以在画布上点击任意位置取色。

交互细节：

  • 画布上有一个十字准星跟随鼠标，显示当前点击位置。
  • 窗口底部显示当前颜色、RGB 值、点击位置的原始像素坐标。
  • 有「确定」和「取消」按钮。确定后把颜色写进透明色输入框，取消不改变。
  • 绑定 ESC 键，按 ESC 等同于取消。
  • 窗口关闭按钮（X）被拦截，点击 X 会提示「请使用「确定」或「取消」按钮关闭此窗口」。这是为了防止用户误关导致颜色丢失。
💡 透明色悬浮提示： 透明色输入框带有一个悬浮提示，内容是「透明色是将裁剪像素的颜色，容差为 0」，提醒你容差是 0 这个关键信息。

2.4 GIF 镂空

GIF 动图也支持镂空。处理流程是：

  1. 加载 GIF，分离所有帧，每帧保留自己的延迟时间。
  2. 如果镂空启用，逐帧应用镂空处理（alpha 模式直接保留透明通道，chroma 模式逐像素替换）。
  3. 用 QTimer 按每帧的延迟时间切换显示，循环播放。

性能注意： 色度抠图模式下，每一帧都要逐像素遍历，GIF 帧数多的话加载会慢。如果 GIF 本身带透明通道，建议用 alpha 模式，快得多。

停止条件： 窗口关闭、切换到其他音符、面板关闭时，GIF 定时器会停止，movie 对象也会 stop。不会出现「窗口关了但 GIF 还在后台跑」的泄漏。

2.5 无边框交互

镂空图片框强制无边框，所以没有系统标题栏，也没有系统关闭按钮。为了不让用户「关不掉」，程序自己实现了交互：

  • 左键拖动： 在图片任意位置按住左键拖动，窗口会跟着鼠标移动。用的是 mousePressEvent 记录 drag_position，mouseMoveEvent 里 move 窗口。
  • 右键关闭： 在图片上点右键，调用 close_window()，播放出场动画（如果有）后关闭。

这样即使用户不知道快捷键，也能通过鼠标完成移动和关闭。

💡 透明背景 + 鼠标事件： 镂空窗口设置了 WA_TranslucentBackground，理论上透明区域不接收鼠标事件。但程序显式开启了 setMouseTracking 和 WA_TransparentForMouseEvents=False，并确保 paintEvent 里绘制了完全透明的背景层，所以整张图片区域（包括透明部分）都能接收鼠标。这样用户点透明区域也能拖动窗口。

2.6 与缩放的配合

镂空和缩放可以同时用。处理顺序是：

  1. 先按目标尺寸缩放图片（scaled(..., Qt.KeepAspectRatio, Qt.SmoothTransformation)）。
  2. 再应用镂空处理（alpha 模式直接使用缩放后的 pixmap，chroma 模式逐像素替换缩放后的图像）。

对于 GIF，缩放是在分离帧的阶段做的：每帧先缩放，再应用镂空，再存到帧列表里。

💡 缩放会加重色度抠图的边缘问题： 缩放时的平滑插值会产生中间色，原本纯绿的边缘会变成「半绿半白」的过渡色，色度抠图容差为 0 抠不掉，会留下更明显的色边。如果必须缩放 + 色度抠图，建议先在原图上抠干净再缩放，或者用 alpha 模式。

三、窗口背景镂空（色键透明）

这一节讲的是另一种镂空——它不是图片框专属的，而是所有窗口类型都能用的「窗口背景透明」。

3.1 触发入口：样式钮里的「窗口背景」

入口在样式钮的设置对话框里。打开方式：

  1. 在 CZEmaker 面板顶部右侧找到「样式钮」下拉框。
  2. 选择「设置」，打开「窗口控制按钮与窗口样式设置」对话框。
  3. 在「窗口样式」区域下方，找到「窗口背景」复选框。
  4. 取消勾选「窗口背景」，点确定。

取消勾选后，窗口就会进入「色键透明」模式——窗口背景变成透明，但标题栏、图标、文本、按钮区都还在。

💡 和「亚克力或云母」的联动： 取消「窗口背景」时，「亚克力或云母」复选框会自动取消勾选。因为亚克力需要窗口有实际背景层，色键透明没有背景层，亚克力会失效。详见 亚克力与云母 文档。
📌 先澄清一点：「窗口背景镂空」有两种实现路径，不是一种。
取消「窗口背景」后，具体用哪套透明机制，取决于窗口样式：
· window_style = borderless → 走真透明（Qt 的 WA_TranslucentBackground），窗口连边框带标题栏全透明，只剩控件。
· window_style = normal_fixed / tool_fixed → 走色键透明（Win32 的 SetLayeredWindowAttributes），标题栏保留，内容区背景透明。

所以「3.2 效果是什么」和「3.3 实现原理」这两小节，讲的是**带边框窗口的色键透明路径**。无边框窗口的真透明路径在 3.8 里单独讲。

3.2 效果是什么

取消「窗口背景」后，窗口的视觉会变成这样：

区域状态说明
标题栏 保留（不透明） 系统画的标题栏，不受 paintEvent 影响
图标区 透明背景，图标保留 图标本身还在，只是背后的白色方块透出桌面
文本区 透明背景，文字保留 文字本身还在，只是背后的白色方块透出桌面
按钮区 保持灰色不透明底板 按钮区有自己的背景色 #F0F0F0，不受色键透明影响
窗口整体边框 标题栏有边框，内容区没有 因为内容区背景透明了，边框也看不见了

所以最终效果是：一个有标题栏的窗口，内容区的白色背景变成了透明，透出桌面。图标、文字、按钮都还在，只是背后的白色不见了。

💡 和图片镂空的视觉区别：
图片镂空是「窗口消失，只剩图片主体」——你看到的是圆形头像，四角透明。
窗口背景镂空是「窗口还在，但背景透明」——你看到的是标题栏 + 透明内容区 + 灰色按钮区，标题栏和按钮区是实心的。

3.3 实现原理

窗口背景镂空用的是 Win32 的「色键透明」（Color Key Transparency），原理分两步：

第一步：在 paintEvent 里填充色键色

程序重写了窗口的 paintEvent，在背景上填充一个特定的颜色 QColor(1, 2, 3)——也就是 RGB(1, 2, 3)，一个几乎不会和真实内容撞色的深蓝色。这个颜色就是「色键色」。

def paintEvent(self, event):
    if not getattr(self, 'window_background', True) and not getattr(self, 'hollow_enabled', False):
        painter = QPainter(self)
        painter.fillRect(self.rect(), QColor(1, 2, 3))
    super().paintEvent(event)

第二步：用 Win32 把这个颜色设为透明

窗口显示后，程序调用 SetLayeredWindowAttributes：

GWL_EXSTYLE = -20
WS_EX_LAYERED = 0x00080000
LWA_COLORKEY = 0x00000001
hwnd = int(self.winId())
ex = ctypes.windll.user32.GetWindowLongW(hwnd, GWL_EXSTYLE)
ctypes.windll.user32.SetWindowLongW(hwnd, GWL_EXSTYLE, ex | WS_EX_LAYERED)
color_ref = (3 << 16) | (2 << 8) | 1  # BGR 格式，对应 RGB(1, 2, 3)
ctypes.windll.user32.SetLayeredWindowAttributes(hwnd, color_ref, 0, LWA_COLORKEY)

这样，窗口上所有 RGB 值等于 (1, 2, 3) 的像素就会变成透明。因为 paintEvent 只在「没有内容的地方」填充这个色键色，所以最终效果就是「内容区背景透明，控件保留」。

💡 为什么用 RGB(1, 2, 3)？
因为这是个几乎不会自然出现的颜色。如果你用纯白 (255, 255, 255) 做色键，那么窗口里所有白色像素（比如白色文字、白色图标）都会被误抠成透明。用 (1, 2, 3) 这种深蓝色，就几乎不会和真实内容撞色。

3.4 哪些窗口类型支持

窗口类型支持窗口背景镂空吗说明
普通弹窗（信息/警告/错误/询问） ✅ 支持 RegularPopup 重写了 paintEvent，内容区透明，按钮区保留灰色底板
图片框（非镂空） ✅ 支持 ImagePopup 重写了 paintEvent，图片背景透明
图片框（已勾选镂空） ❌ 走图片镂空路径 paintEvent 里有 and not self.hollow_enabled 判断，勾了镂空就不走色键透明
模类框 ✅ 支持 模类框的 paintEvent 被替换，central_widget 设为透明
视频框 ❌ 不支持 mpv 窗口，不走 Qt 的 paintEvent
气泡/通知 ❌ 不支持 不是 Qt 窗口，是系统通知

3.5 平台限制

色键透明依赖 Win32 的 SetLayeredWindowAttributes，所以只在 Windows 平台生效。程序里有两道检查：

def _apply_colorkey(self):
    if sys.platform != 'win32': return
    ...

也就是说，在非 Windows 平台上，即使你取消了「窗口背景」，也不会真的透明——窗口背景还是会被填充成 RGB(1, 2, 3)，但因为没调用 SetLayeredWindowAttributes，这个颜色会实打实显示出来，变成一块深蓝色。所以非 Windows 平台不建议用这个功能（不过 Itoc 主要面向 Windows，这个问题基本遇不到）。

3.6 与亚克力的互斥

窗口背景镂空和亚克力是互斥的。原因：

  • 亚克力需要窗口有实际背景层，DWM 才能在这个背景层上做模糊合成。
  • 色键透明窗口的背景是透明的，没有背景层，亚克力无处附着。

所以程序做了双向联动：

  • 勾选「亚克力或云母」→ 自动勾选「窗口背景」。
  • 取消「窗口背景」→ 自动取消「亚克力或云母」。

详见 亚克力与云母 文档。

3.7 配置文件字段

窗口背景镂空的配置保存在音符的 cze_makers.window_control_detail 里：

  • window_background：布尔，是否绘制窗口背景。默认 true。设为 false 时启用色键透明。

示例：

{
  "window_type": "info",
  "window_title": "示例弹窗",
  "window_content": "这个窗口的背景是透明的",
  "window_control": "custom",
  "window_control_detail": {
    "close": true,
    "maximize": false,
    "minimize": false,
    "topmost": true,
    "window_style": "normal_fixed",
    "window_background": false,
    "window_material": false
  }
}

旧工程没有 window_background 字段时，默认为 true，不会自动启用色键透明。

3.8 borderless 的真透明路径

如果窗口样式是 borderless，取消「窗口背景」之后走的是Qt 的真透明（WA_TranslucentBackground），不是色键透明。区别在于：

项目色键透明（normal_fixed / tool_fixed）真透明（borderless）
透明机制 Win32 SetLayeredWindowAttributes(LWA_COLORKEY) Qt WA_TranslucentBackground
色键色 固定 RGB(1, 2, 3) 无（不需要色键）
标题栏 保留（系统画的，不受影响） 无（borderless 没有标题栏）
边框 标题栏有边框，内容区没有 无边框
平台限制 仅 Windows Qt 跨平台
典型场景 「窗口背景透明，但标题栏和按钮还在」 「窗口彻底消失，只剩控件」

支持的窗口类型：

  • 模类框：支持。模类框在 borderless 且 window_background=false 时，会走 WA_TranslucentBackground 真透明。
  • 图片框（非镂空）：支持。图片框在 borderless 且 window_background=false 时，也会走真透明。
  • 普通弹窗：不支持。普通弹窗即使选了 borderless + 无背景，也不会走真透明——它依赖色键透明，但普通弹窗的 RegularPopup 里没有实现 borderless + window_background=false → 真透明的分支，会继续走色键透明。
💡 简记口诀：
· 想「只剩内容，窗口整体消失」 → borderless + 取消背景（模类框 / 图片框）；
· 想「窗口还在，背景透明」 → 普通边框 / 工具窗 + 取消背景（所有类型）。

四、两种镂空的对比

4.1 视觉对比

项目 图片镂空 窗口背景镂空
最终视觉 只剩图片主体，四角透明 标题栏 + 透明内容区 + 灰色按钮区
标题栏 无 有
图标 无（图片本身就是内容） 有，图标保留
文本 无（图片就是内容） 有，文字保留
按钮区 无 有，灰色底板保留
透明范围 图片背景（像素级） 窗口内容区背景（整块）
透明颜色 图片自带的透明通道 / 色度抠图的颜色 固定的 RGB(1, 2, 3) 色键色

4.2 适用场景对比

场景 该用哪个 原因
圆形头像、异形 logo、贴纸 图片镂空 只有图片内容，不需要标题栏和按钮
带透明通道的 GIF 动图 图片镂空（alpha） 逐帧保留透明通道，效果最好
绿幕抠像的图片 图片镂空（chroma） 指定绿色抠掉，留下主体
想要「窗口背景透明但标题栏在」的普通弹窗 窗口背景镂空 保留标题栏和按钮，只让背景透明
想让桌面透出来的提示框 窗口背景镂空 标题栏还在，用户可以拖动关闭

4.3 两个都用会怎样

如果你在图片框上同时勾了「镂空图片窗口」和取消了「窗口背景」，程序会怎么处理？

答案：以图片镂空为准，窗口背景镂空不生效。因为代码里有这个判断：

if not getattr(self, 'window_background', True) and not getattr(self, 'hollow_enabled', False):
    # 走色键透明

and not self.hollow_enabled 这个条件保证了：勾了图片镂空，就不会走色键透明。

为什么要这样设计？因为图片镂空走的是 Qt 的 WA_TranslucentBackground（逐像素透明），色键透明走的是 Win32 的 LWA_COLORKEY（整块颜色透明）。两套机制叠加会冲突——Qt 的透明背景上再叠一个 Win32 色键，可能导致视觉异常（比如透明区域闪白、控件被误抠掉）。所以程序干脆让它二选一。

📌 三种「透明」机制的关系：
· 图片镂空：WA_TranslucentBackground + 图片 alpha / 色度抠图（图片框专属，逐像素透明）
· 色键透明（窗口背景镂空）：SetLayeredWindowAttributes(LWA_COLORKEY)（有边框时用，整块色键色透明）
· 真透明（窗口背景镂空）：WA_TranslucentBackground（borderless 时用，窗口整体透明）

后两者都属于「窗口背景镂空」，具体用哪个只看 window_style；图片镂空和它们互斥。

五、常见问题

Q1：镂空勾了但没效果？

A：先确认你勾的是哪个镂空：

  • 如果勾的是「镂空图片窗口」：检查窗口类型是不是图片框；图片是不是 PNG/GIF（alpha 模式）或纯色背景图（chroma 模式）；如果是 chroma 模式，透明色是不是真的和图片背景色一致。
  • 如果取消的是「窗口背景」：检查是不是 Windows 平台；检查是不是图片框（如果图片框勾了镂空，色键透明会被跳过）；检查是不是视频框（视频框不支持）。

Q2：色度抠图留了一圈绿边？

A：容差为 0 导致的。绿幕图如果有噪点、渐变、抗锯齿，边缘像素的 RGB 和纯绿不相等，抠不掉。解决方案：用 alpha 模式（如果图片有透明通道），或者用专业工具预处理图片哦。

Q3：取消了「窗口背景」，但窗口变成深蓝色了？

A：说明色键透明没生效。可能原因：① 非 Windows 平台；② SetLayeredWindowAttributes 调用失败（比如窗口句柄还没创建好）；③ 图片框勾了镂空（色键透明被跳过）。检查控制台有没有 [色键透明] 应用失败 的日志。

Q4：镂空图片框能调大小吗？

A：能。镂空和自定义尺寸不冲突。勾选「自定义尺寸」后填 W/H，或者点尺寸拾取按钮拖拽选区。注意缩放对色度抠图的影响（见上文）。

Q5：镂空图片框在任务栏显示吗？

A：取决于「在任务栏显示」复选框。默认勾选。但如果你在样式钮里选了工具窗，会强制不显示任务栏（工具窗的系统特性）。镂空本身不改变任务栏行为。

Q6：镂空图片框能置顶吗？

A：能。镂空图片框仍然遵循样式钮里的「窗口置顶」配置。勾了置顶，图片会浮在其他窗口上面；不勾，就是普通层级。

Q7：GIF 镂空后动画变卡了？

A：色度抠图模式下每帧都要逐像素遍历，帧数多、分辨率大的 GIF 会慢。如果 GIF 本身带透明通道，切到 alpha 模式。另外可以缩小 GIF 尺寸（自定义尺寸填小一点），减少像素量呀。

Q8：镂空窗口的透明区域能点到吗？

A：图片镂空的透明区域能点到。程序显式设置了 WA_TransparentForMouseEvents=False 和 setMouseTracking(True)，并在 paintEvent 里绘制了透明背景层，确保整张图片区域（包括透明部分）都能接收鼠标事件。(๓´˘`๓)

窗口背景镂空的透明区域也能点到——因为色键透明只是「视觉透明」，窗口本身还是一个完整的矩形，鼠标事件照常接收。

Q9：窗口背景镂空后，标题栏能拖动吗？

A：能。色键透明不影响标题栏。标题栏是系统画的，不在 paintEvent 的绘制范围内，所以不会被抠掉。用户可以正常拖动标题栏、点关闭按钮。

Q10：窗口背景镂空后，内容区的文字会不会被抠掉？

A：不会。只有 RGB 值等于 (1, 2, 3) 的像素才会被抠成透明。文字是黑色或其他颜色，不会被误抠。但如果你的文字恰好是 RGB(1, 2, 3) 这种深蓝色，那就会和色键色撞上，文字也会变透明——这种情况几乎不会发生，但理论上存在。

Q11：两种镂空能不能同时用？

A：不能（对图片框而言）。如果图片框勾了图片镂空，窗口背景镂空会被跳过。如果想让图片框的背景透明，用图片镂空就够了；如果想让模类框的背景透明，用窗口背景镂空。

Q12：窗口背景镂空支持模类框吗？

A：支持。模类框的 paintEvent 会被替换成色键填充逻辑，central_widget 设为透明。但注意：模类里的控件如果有自己的背景色（比如按钮、编组框），会保留，不会被抠掉。只有 central_widget 的背景会被透明。

六、小结

Itoc 里的「镂空」有两种，别搞混：

  1. 图片镂空（hollow）：图片框专属。让图片背景透明，强制无边框，只留下图片主体。入口是「镂空图片窗口」复选框。支持 alpha（透明通道）和 chroma（色度抠图）两种模式。
  2. 窗口背景镂空：所有窗口类型都能用。让窗口背景透明。入口是样式钮里取消「窗口背景」复选框。具体实现分两条路径：
    · window_style = borderless → 走 Qt 真透明（WA_TranslucentBackground），窗口连边框带标题栏全透明，只剩控件；
    · window_style = normal_fixed / tool_fixed → 走 Win32 色键透明（SetLayeredWindowAttributes），标题栏保留，内容区背景透明。

记住几个关键点：

  • 图片镂空是「图片透明」，窗口背景镂空是「窗口背景透明」。
  • 图片镂空强制无边框；窗口背景镂空在 borderless 下也是无边框，在 normal_fixed / tool_fixed 下保留标题栏。
  • 三者互斥：图片框勾了镂空，色键透明会被跳过；borderless 窗口走真透明，不会再叠色键。
  • 三者都和亚克力互斥：镂空 / 色键透明 / 真透明都要求背景透明，亚克力需要背景层。
  • 色键透明只在 Windows 平台生效；真透明是 Qt 跨平台的。

搞清楚了这两种镂空的区别，你就能根据场景选对工具了喵 ( ⓛ ω ⓛ *)
