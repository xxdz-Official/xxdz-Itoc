🧩 组装打包模式

前面我们讲了 CZEmaker 弹窗、全局命令、音符块、调整图层、过渡动画、批量赋音效、渲染为音频文件、渲染视频文件、渲染为 Python 代码、渲染为 CZE 数据文件、编译为 exe。现在讲另一个分发功能——组装打包模式。它和“编译为 exe”的目的类似，都是把工程变成可以独立分发的程序，但实现方式完全不同。

📌 本篇的范围：
讲的是“组装打包模式”的入口、前置条件、窗口界面、操作步骤、生成结果和常见问题。关于“编译为 exe”的完整流程，请参考《编译为 exe》文档。

一、这个功能是干嘛的？

“编译为 exe”是用 PyInstaller 把 Python 代码打包成一个独立的 .exe 文件，需要本机有 Python 环境。而“组装打包模式”不需要 Python 环境，也不需要编译，它只是把已有的文件复制、拼装到一个文件夹里。

具体来说，它会做这些事：

  • 把工程数据转换成 runCZE.CzeData
  • 把工程用到的图片复制到 img/ 文件夹
  • 把背景音频复制并重命名为 Audio.mp3
  • 把 Itoc 解释器（一个现成的 exe）复制过来并重命名
  • 把 ico/ 图标文件夹复制过来
  • 把 img/ 素材文件夹合并进来

最终得到一个文件夹，里面包含一个可直接双击运行的 exe 和它需要的所有资源。把这个文件夹打包发给别人，对方不需要安装任何东西就能运行。

二、和“编译为 exe”的区别

编译为 exe组装打包模式
是否需要 Python 环境需要不需要
是否需要 PyInstaller需要不需要
打包速度较慢（要编译）极快（只是复制文件）
能否自定义 exe 图标可以不能（图标固定）
能否自定义版权、版本可以不能（需反编译修改）
生成物一个 exe + 依赖文件夹一个文件夹，含 exe 和资源
💡 怎么选：
· 想快速出成品、不在意图标和版权信息 → 用组装打包模式。
· 想自定义图标、版本、版权，且本机有 Python → 用编译为 exe。

三、从哪里打开？

菜单位置：「编译(C)」 → 「组装打包模式」。

快捷键：目前没有默认快捷键，建议从菜单打开。

前置条件

打开组装打包前，程序会先检查：

检查项不满足时的提示怎么解决
是否有打开的工程“请先打开或保存一个工程文件”先新建或打开一个工程
工程里是否有音符“当前工程没有音符数据”先在时间轴上画几个音符

如果工程已经改过（标题栏工程名带 *），还会先弹一个确认框，建议你先保存工程再打包。

四、窗口界面

打开后会出现一个左右分栏的“组装打包模式”窗口。

区域内容
左栏模式说明、优点、缺点、解释器配置
右栏选择可执行文件版本、输入导出程序名称、继续/取消按钮

4.1 优点

左栏会列出组装打包模式的优点：

  • 无需 Python 环境——导出过程不需要本机安装 Python
  • 无需依赖第三方 pip 运行库——所有依赖都已包含在程序中
  • 打包速度极快——无需编译，只需复制拼装文件

4.2 缺点

也会列出缺点：

  • 自定义程度低——无法通过常规手段修改生成程序的文件属性（版权、版本等）
  • 软件图标固定——无法修改生成程序的图标

如果需要修改程序属性或图标，需要使用反编译工具手动处理。

4.3 解释器配置

显示当前四种解释器模式的状态：

模式说明
64位 - 窗口64 位窗口模式，推荐
64位 - 控制台64 位控制台模式
32位 - 窗口32 位窗口模式
32位 - 控制台32 位控制台模式

每种模式会显示：

  • ✅ 用户自定义——你已经配置了自定义解释器路径
  • ⚪ Itoc 2.0 默认解释器——使用程序自带的默认解释器
  • ❌ 路径无效——配置的路径不存在

当前选中的模式会显示在顶部。实际打包时使用哪个解释器，取决于你在“配置Itoc解释器”里选择的模式。

4.4 选择可执行文件版本

右栏让你选择打包时使用哪个解释器 exe：

选项说明
x64 窗口模式（窗口）- 推荐64 位，带窗口，适合大多数弹窗程序
x86 窗口模式（窗口）32 位，带窗口
x64 控制台模式64 位，带控制台窗口，适合调试
x86 控制台模式32 位，带控制台窗口

4.5 导出程序名称

一个输入框，让你输入最终生成的 exe 文件名。默认会使用当前工程名。不需要手动加 .exe 后缀，程序会自动补上。

文件名不能包含以下字符：< > : " / \ | ? *。如果包含，会弹窗提示。

4.6 底部按钮

按钮作用
取消关闭窗口，不打包
继续打包进入下一步，选择导出位置

五、操作步骤

  1. 打开一个包含音符的工程。
  2. 点击菜单「编译(C)」→「组装打包模式」。
  3. 如果工程已修改，按提示选择是否保存。
  4. 在窗口里：
    • 查看解释器配置，确认使用的解释器版本
    • 选择可执行文件版本（一般选“x64 窗口模式”）
    • 输入导出程序名称
  5. 点“继续打包”。
  6. 在弹出的文件夹选择框里，选择一个基础目录。程序会在里面创建一个以导出程序名称命名的项目文件夹。
  7. 等待打包完成，会弹窗显示项目文件夹位置和包含的文件。
  8. 到项目文件夹里找到 exe，双击测试。
💡 关于“基础目录”：
你选择的不是最终文件夹，而是一个“父目录”。程序会在这个父目录下创建一个新的项目文件夹，名字就是你输入的导出程序名称。
如果同名文件夹已存在，会自动加 _1、_2 后缀，不会覆盖。

六、生成结果

打包完成后，项目文件夹里会包含：

文件/文件夹说明
你的程序.exe主程序，由解释器复制并重命名而来
runCZE.CzeData工程数据文件，exe 启动时读取
Audio.mp3背景音频（如果工程关联了音频）
img/图片素材文件夹，含工程用到的图片
ico/图标文件夹，含程序运行需要的图标
📌 分发时注意：
要把整个项目文件夹一起打包分发，不要只发 exe 文件。因为 exe 需要同目录下的 runCZE.CzeData、img/、ico/、Audio.mp3 等文件才能正常运行。

七、常见问题

Q1：组装打包和编译为 exe 有什么本质区别？

组装打包是“复制拼装”，编译为 exe 是“编译打包”。前者不需要 Python 环境，速度极快，但图标和版权信息固定；后者需要 Python 和 PyInstaller，速度较慢，但可以自定义图标和版本信息。

Q2：为什么生成的 exe 图标不能改？

因为组装打包只是复制现成的解释器 exe，没有经过编译过程，所以无法在复制时修改 exe 的资源（图标、版本、版权）。如果确实需要修改，可以使用 Resource Hacker 等工具反编译后手动改。

Q3：打包后 exe 打不开怎么办？

检查以下几点：

  • 是否把整个项目文件夹都复制过去了？
  • runCZE.CzeData 是否在 exe 同目录下？
  • ico/ 文件夹是否存在？
  • 如果工程有音频，Audio.mp3 是否存在？

Q4：音频文件没有复制过去？

组装打包会尝试从工程里读取音频路径并复制。如果工程没有关联音频，或者音频文件路径失效，就不会有 Audio.mp3。可以手动放一个 Audio.mp3 到项目文件夹里。

Q5：图片没有复制过去？

打包时会深度扫描工程数据里的图片路径，把存在的图片复制到 img/。如果某些图片路径不正确，或者图片不存在，就不会被复制。可以在打包后手动检查 img/ 文件夹，缺什么补什么。

Q6：可以用 32 位解释器打包吗？

可以。在“选择可执行文件版本”里选 x86 的选项即可。前提是程序里已经配置了对应的 32 位解释器文件。

Q7：打包后的程序能在没有 Python 的电脑上运行吗？

可以。组装打包生成的文件夹里已经包含了运行所需的全部文件，目标电脑不需要安装 Python 或任何依赖。

Q8：打包过程中可以取消吗？

在“组装打包模式”窗口里点“取消”可以取消。但一旦选择了基础目录并开始复制，就没有取消按钮了，只能等它完成。因为复制过程通常很快，一般不需要取消。

Q9：为什么打包速度这么快？

因为组装打包不做任何编译，只是把已有的文件复制、重命名、整理到一个文件夹里。文件复制速度很快，所以整个打包过程通常几秒钟就完成了。

Q10：可以给不同的工程用同一个导出名称吗？

可以，但如果目标文件夹已存在，程序会自动加 _1、_2 后缀，避免覆盖。每次打包都会创建一个新的文件夹。

八、小结

「组装打包模式」是一种快速、免 Python 环境的分发方式，通过复制拼装文件把工程变成可独立运行的文件夹。

  • 入口：菜单「编译(C)」→「组装打包模式」
  • 前置条件：有打开的工程 + 有音符数据
  • 无需 Python 环境，无需 PyInstaller，打包速度极快
  • 可以选择 64/32 位、窗口/控制台版本的解释器
  • 可以自定义导出程序名称
  • 生成物是一个文件夹，含 exe + CzeData + img + ico + Audio.mp3
  • 缺点：无法自定义 exe 图标和版权/版本信息
  • 分发时要复制整个文件夹，不能只发 exe
