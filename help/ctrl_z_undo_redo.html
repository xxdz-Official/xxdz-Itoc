↺ 撤销与重做

做工程的时候，改错一个音符、手滑删掉一段标记、批量应用配参后发现效果不对……这些都是常有的事。如果没有撤销功能，你就得手动一点点改回去，那简直是噩梦。

Itoc 的撤销与重做功能就是为了解决这个问题：Ctrl+Z 一键回到上一步，Ctrl+Shift+Z 一键恢复。 而且它还非常厚道——不是简单地记住内存里的操作，而是把整个工程的完整快照存到磁盘上，就算程序崩溃了，只要临时文件还在，也还有机会找回来。

📌 本篇的范围：
讲的是撤销与重做的快捷键、工作原理、侧边栏历史操作入口、操作历史记录管理器、回滚设置（步数、退出保留）、磁盘文件结构。关于代码视图自己的撤销（那个是 tk.Text 内部的，不影响主工程），请参考《代码视图》文档。

一、这个功能是干嘛的？

撤销与重做做的事很简单：把你对工程的每一次修改，都存一份完整的快照，然后让你可以前后翻阅这些快照。

  • 撤销：回到修改之前的状态。
  • 重做：把刚才撤销掉的那一步再恢复回来。
  • 操作历史记录管理器：像翻书一样，看到所有历史快照，还能直接跳到其中任意一份。
💡 一句话理解：
它就像游戏的“存档 / 读档”。每次修改前自动存一个档，按 Ctrl+Z 就“读上一个档”，按 Ctrl+Shift+Z 就“读下一个档”。
只不过它比游戏更贴心——历史记录窗口能让你跳到任意一个存档点。

二、从哪里使用？

撤销与重做有四种入口，随便用哪个都行。

2.1 快捷键

快捷键作用
Ctrl+Z撤销
Ctrl+Shift+Z重做
Ctrl+Shift+H打开操作历史记录管理器

2.2 菜单

「编辑(E)」菜单的顶部有这三个菜单项：

  • 撤销：对应 Ctrl+Z，栈空时是灰的。
  • 重做：对应 Ctrl+Shift+Z，栈空时是灰的。
  • 操作历史记录管理器...：对应 Ctrl+Shift+H，永远可用。

菜单项前面会显示对应的小图标（撤销箭头、重做箭头、历史记录图标），一眼就能认出来。

2.3 快捷操作栏的按钮

在「快捷操作栏²」里，有两个按钮：↺（撤销） 和 ↻（重做）。

  • 撤销栈为空时，↺ 按钮变灰。
  • 重做栈为空时，↻ 按钮变灰。
  • 点一下效果和按快捷键完全相同。

2.4 侧边栏的「历史操作」选项卡

侧边栏上半部分有一个「历史操作」选项卡，它本质上就是操作历史记录管理器的常驻入口。

  • 打开侧边栏，点「历史操作」选项卡，就能看到当前工程的所有历史快照列表。
  • 列表里会显示每条快照的修改时间、文件名、类型（撤销/重做）、栈索引。
  • 双击某一行，主画布会直接回退到那个状态，效果和操作历史记录管理器里的“回退到此”一样。
  • 顶部同样有搜索框和刷新按钮，方便在历史记录很多时快速定位。
💡 侧边栏入口的好处：
不用按快捷键、不用翻菜单，直接在主界面左侧就能看到历史记录。尤其适合一边改工程一边随时回退的场景。
📌 三个入口，状态是同步的：
不管你是用快捷键、点菜单、点按钮，还是用侧边栏的「历史操作」，只要撤销栈或重做栈的状态发生变化，所有入口会同时刷新可用 / 不可用状态。所以不会出现“菜单里是灰的、按钮却能点”这种混乱情况。

三、工作原理：基于磁盘的快照栈

Itoc 的撤销不是“记录你按了什么键”，而是每次修改前，把整个工程的完整快照存成一个文件。这是理解后续所有行为的基础。

3.1 两个文件夹

程序运行目录下会有两个文件夹：

文件夹用途
CTRL_Z/存放“可撤销”的历史快照
CTRL_shift_Z/存放“可重做”的历史快照

快照文件名叫 step_0001.czemidi、step_0002.czemidi……按编号递增，编号越大越新。

3.2 撤销与重做的完整流程

假设你现在做了一堆修改，撤销栈里已经有若干快照了：

  1. 你按 Ctrl+Z：
  2. 程序先把当前内存里的状态存一份新快照，扔进 CTRL_shift_Z/（也就是“重做栈”）。
  3. 然后从 CTRL_Z/（撤销栈）里弹出最近的那一份快照。
  4. 加载这份快照，覆盖当前工程。
  5. 更新菜单和按钮状态。

按 Ctrl+Shift+Z 重做，就是把上面的过程反过来：先把当前状态扔进撤销栈，再从重做栈弹一份出来加载。

💡 为什么“当前状态”要先扔进另一个栈？
因为撤销之后你可能后悔了，想再恢复。如果不把“撤销前”的状态存起来，一旦撤销就再也回不去了。
这个“扔进对面栈”的动作，就是让 Ctrl+Z 和 Ctrl+Shift+Z 可以来回切换的关键。

3.3 什么时候会自动记录快照？

Itoc 会在修改内存数据之前调用一次“保存快照”。常见的触发场景包括：

操作是否记录快照
拖动音符块是
拉伸音符块 / 调整图层是
删除音符 / 删除调整图层 / 删除轨道是
粘贴音符块 / 粘贴调整图层是
应用配参（单条 / 智能 / 全部）是
切换禁用状态（Ctrl+Q）是
修改 BPM（主界面 / 窗口）是
编辑全局随机种子是
重命名轨道是
移动轨道（上移 / 下移）是
绘制调整图层是
加载 SRT 字幕是
阵列绑定 / 解绑是
添加轨道是
代码视图应用是
纯选中操作（框选、Ctrl+A）否（不算修改）
拖动判定线 / 缩放滑块否（不算修改）
切换选项卡 / 切换预览乐器否（不算修改）

3.4 最大步数限制

两个栈加起来会占用磁盘空间，所以 Itoc 有一个“最大步数”限制，默认是 30 步。

  • 超出上限时，最旧的快照会被自动删除。
  • 所以你能撤销的步数是有限的，不是“无限历史”。
  • 如果确实需要更多步数，可以在首选项里调大（见第五节）。
⚠️ 快照存的是“工程 JSON”，不是“媒体资源”：
每一次快照都是一个完整的 .czemidi 文件——纯文本，里面是音符、标记、全局命令、调整图层、编组、类名等数据。
工程引用的音频 / 视频 / 图片文件不会被复制进快照，只是引用它们的路径。
所以快照文件本身通常都很小（几十 KB 到几 MB 不等），默认 30 步对绝大多数工程来说完全够用。
唯一的例外：如果工程里嵌入了带图片资源的模类（图片以 Base64 形式内嵌在 JSON 里），那种模类会让工程文件本身变大，快照也会跟着变大。

四、操作历史记录管理器

撤销 / 重做只能“一步往前、一步往后”，但如果你一口气改了很多步，想跳到更早的某个状态，就需要操作历史记录管理器。侧边栏的「历史操作」选项卡也是同一个东西的常驻入口。

4.1 怎么打开？

  • 快捷键 Ctrl+Shift+H。
  • 菜单「编辑(E)」→「操作历史记录管理器...」。
  • 侧边栏上半部分 →「历史操作」选项卡。

4.2 界面布局

窗口从上到下分成三部分：

区域内容
顶部标题栏「操作历史记录 (磁盘快照)」+「刷新」「清空历史」两个按钮
中间表格所有历史快照的列表
底部状态栏记录数量统计 +「回退到此」按钮

4.3 表格列的含义

列含义
序号列表里的显示编号
修改时间快照文件的修改时间，格式 年-月-日 时:分:秒
文件路径快照文件名（如 step_0012.czemidi）
类型“撤销”（蓝色）或“重做”（橙色）
栈索引在对应栈里的位置

列表里撤销栈的内容排在前面，重做栈的内容排在后面，而且都是“最新在上”的顺序，所以最顶部的那一行就是“你按一下 Ctrl+Z 会回到的状态”。

💡 颜色区分：
撤销行的文字是蓝色，重做行的文字是橙色，一眼就能看出这一份是“回去”的还是“回来”的。

4.4 回退到此

这是历史记录管理器最强大的功能。

  1. 在列表里选一行（单击选中）。
  2. 点底部「回退到此」，或者直接双击那一行。
  3. 弹出确认框：“确定要回退到以下状态吗？当前之后的所有修改将丢失。”
  4. 确认后，程序加载那份快照。
  5. 同时，从选中的那份快照之后的所有快照都会被删除，因为已经回退到那个时间点了，后面的“未来”不再存在。
⚠️ 回退会丢历史：
比如你选了第 3 行回退，那么从第 3 行往后的所有快照（第 4、5、6……行）都会被删掉。
如果你只是想“先看一眼之前的状态”，建议先用 Ctrl+Z 一步步往回撤，这样还能用 Ctrl+Shift+Z 再走回来。

4.5 刷新与清空历史

  • 刷新：重新扫描两个文件夹，把最新的快照列表拉出来。一般不需要手动刷新，打开窗口时会自动刷新一次。
  • 清空历史：删掉两个文件夹里的所有快照，撤销栈和重做栈都清空。会弹确认框，清空后无法撤销。

五、回滚设置

在「文件」→「首选项」→「回滚设置」里，有两个可调项：

5.1 最大回滚步数

项目说明
范围 1 ~ 100 步
默认值 30 步
作用 限制两个栈里最多保留多少份快照

调小后，超出部分会被立即清理。比如从 30 调到 10，撤销栈里最旧的 20 份会被删除。

📌 步数越多 ≠ 越好（但影响通常不大）：
因为快照存的是纯文本 JSON，通常每份只有几十 KB 到几 MB，所以步数调大一般不会让磁盘爆炸。
默认 30 步对绝大多数工程完全够用。
唯一需要注意的是：如果工程里嵌入了带图片资源的模类（图片以 Base64 内嵌），那种工程单份快照会明显变大，此时步数就别设太高，10~20 步就够。

5.2 启用可休眠的回滚（退出时保留临时文件）

状态行为
未勾选（默认） 程序退出时，把 CTRL_Z/ 和 CTRL_shift_Z/ 两个文件夹整体删除，释放磁盘空间
勾选 程序退出时保留两个文件夹，下次启动时还能接着用
💡 什么时候勾选？
如果你正在做大工程，或者经常需要“反复折腾”，可以勾上，这样关了程序再打开，之前的历史快照还在。
如果工程已经做完、要发给别人了，就取消勾选，退出时自动清掉，省得文件夹越来越大。

5.3 立即清理所有回滚文件

「回滚设置」面板里还有一个「立即清理所有回滚文件」按钮。点它会弹确认框，确认后立刻删除两个文件夹里的所有内容，相当于手动执行一次“清空历史”。

这个按钮适合在“我已经确定不需要任何历史了，想立刻腾出磁盘空间”的时候用。

六、磁盘文件结构

理解文件夹里的内容，能帮你在出问题时快速排查。

6.1 撤销文件夹 CTRL_Z/

CTRL_Z/
├── step_0001.czemidi
├── step_0002.czemidi
├── step_0003.czemidi
└── ...

每份都是完整的工程 JSON，和你正常保存的 .czemidi 结构一模一样。文件名里的编号越大越新。

6.2 重做文件夹 CTRL_shift_Z/

CTRL_shift_Z/
├── step_0001.czemidi
├── step_0002.czemidi
└── ...

结构相同。里面存的都是“撤销掉的那些状态”。

6.3 启动时会自动扫描

程序启动时，会扫描这两个文件夹：

  • 按文件的修改时间排序，最旧在前。
  • 如果数量超过最大步数限制，多出来的旧文件会被自动删除。
  • 然后分别构建成撤销栈和重做栈。

所以如果你上次退出时勾选了“保留临时文件”，下次启动就能直接继续使用历史记录。

七、常见问题

Q1：为什么按了 Ctrl+Z 没反应？

常见原因：

  • 撤销栈为空（已经是“最初状态”了）。此时状态栏会短暂显示“已是最初状态”。
  • 焦点在某个输入框里，快捷键被输入框截获了。点一下画布再试。
  • 焦点在代码视图的编辑区里，那里的 Ctrl+Z 是撤销代码视图内部的编辑，不是主工程撤销。参考《代码视图》文档。
  • 当前在 CTRL_Z/ 里没有可用的快照（比如退出时清掉了，且这轮还没改过任何东西）。

Q2：为什么“重做”是灰的？

因为重做栈是空的。重做栈只有在“你刚刚撤销过”的时候才有内容。如果撤销之后又做了新的修改，重做栈会被清空——这是正常行为，因为修改后那条“未来线”就不存在了。

Q3：撤销可以撤销多少次？

取决于“最大回滚步数”设置，默认是 30 次。

你按 Ctrl+Z 撤到第 30 次时，栈就空了，再按会显示“已是最初状态”。想撤更多，去首选项把步数调大。

Q4：为什么工程被标记为“已修改”，但撤销栈却没变？

因为不是所有操作都会记录快照。比如：

  • 缩放滑块、拖动判定线、拖动时间选区——这些只改变视图 / 播放位置，不算工程修改，所以不记录。
  • 切换选中、切换选项卡、切换预览乐器——同理。

但有些操作会标记“已修改”却不记录快照，比如：

  • 某些配参的细微修改（如果没走到快照逻辑）。
  • 编辑器 / 视图相关但被标记为工程配置的操作。

这种情况比较少见，遇到时可以手动按 Ctrl+S 保存一下，快照逻辑会在下次修改时补齐。

Q5：撤销之后，快照文件夹里的文件会变少吗？

撤销本身不会减少文件总数，但是会在两边之间搬：

  • 撤销 = 撤销栈 -1、重做栈 +1（外加“当前状态”也扔进重做栈）。
  • 重做 = 重做栈 -1、撤销栈 +1（外加“当前状态”也扔进撤销栈）。

所以两个文件夹的总文件数在多次撤销重做后可能会缓慢增长，直到达到“最大步数”上限后被裁剪。

Q6：退出时勾选了“保留”，下次打开会怎样？

程序启动时会扫描两个文件夹，把里面的快照重新装入栈。

所以你可以：

  • 打开工程后，直接按 Ctrl+Z，回到上次退出前的某个状态。
  • 打开历史记录管理器，看到上次的完整历史。
  • 在侧边栏「历史操作」选项卡里看到同样的列表。
📌 但有个前提：
你必须打开的是同一个工程，快照才有意义。快照里存的是那个工程的完整数据，换一个工程就不适用了。
程序不会强制校验，所以理论上你可以把 A 工程的快照加载到 B 工程上——但结果会很混乱，不建议这么做。

Q7：快照会占用多少磁盘空间？

通常很少。因为快照存的是纯文本的工程 JSON，里面只有音符、标记、全局命令这些数据，工程引用的媒体文件（音频、视频、图片）不会被复制进去。

粗略估算：

磁盘占用 ≈ 单份工程 JSON 大小 × 最大步数 × 2（两个栈）

一份普通工程的 JSON 通常只有几百 KB，30 步两边加起来也就几十 MB，几乎可以忽略。

唯一的例外是嵌入了带图片资源的模类：那种模类会把图片以 Base64 形式直接存进工程 JSON，工程文件会明显变大，快照也会跟着变大。如果你的工程里有这种模类，步数可以适当调小一点。

Q8：历史记录管理器的“刷新”什么时候需要手动点？

一般不需要。窗口打开时会自动扫描一次。但如果你：

  • 在别处手动往 CTRL_Z/ 里放了文件。
  • 从别的机器拷贝了历史文件夹过来。

这时候可以点一下「刷新」让它重新扫描。

Q9：撤销到“最初状态”是什么意思？

“最初状态”指的是你打开这个工程时的状态（或者打开后又保存过的状态）。

撤到这一步时，撤销栈就空了。程序会尝试把工程恢复到“主工程路径”对应的情况：

  • 如果之前做过一些修改，撤销到最初时，工程会从“主工程文件”重新加载。
  • 状态栏会显示“已是最初状态”。
  • 再按 Ctrl+Z 不会有任何变化。
💡 小心陷阱：
撤销到“最初状态”后，程序可能会重新打开主工程文件。如果主工程文件在这期间被你手动改过（比如在别的编辑器里），重新打开时会读到那个版本，而不是你最初在 Itoc 里看到的版本。
一般不会遇到，但如果你手动改过磁盘上的 .czemidi，要留意这一点。

Q10：撤销重做会不会影响我保存的工程文件？

不会。撤销和重做只操作内存里的工程和磁盘上的快照文件夹，不会碰你手动保存的 .czemidi 主工程文件。

只有当你按了 Ctrl+S 或点了“保存工程”，程序才会写回主工程文件。

⚠️ 但撤销不会自动保存：
撤销之后，工程处于“已修改未保存”状态（标题栏会出现 *）。如果不保存就关程序，会弹“是否保存修改”。
所以撤销完记得按 Ctrl+S 保存一下，或者直接关程序时选“是”。

八、小结

「撤销与重做」是 Itoc 里最“救命”的功能之一。关键要记住：

  • 四种入口：Ctrl+Z / Ctrl+Shift+Z、编辑菜单、快捷操作栏按钮、侧边栏「历史操作」选项卡。
  • 工作原理是磁盘快照栈：每次修改前存一份完整工程到 CTRL_Z/，撤销时搬到 CTRL_shift_Z/，重做时搬回来。
  • 只有“真正修改工程”的操作才记录快照，纯选中 / 视图变化不算。
  • 默认最大 30 步，可在首选项「回滚设置」里调整（1~100）。
  • 操作历史记录管理器（Ctrl+Shift+H）能看到所有历史快照，双击可“回退到此”（但会丢掉后面的历史）。
  • 侧边栏「历史操作」选项卡是同一个功能的常驻入口，双击也能回退。
  • “退出时保留临时文件”可以让历史跨程序重启使用；不勾选则退出时自动清理。
  • 撤销 / 重做不会自动保存主工程文件，记得手动按 Ctrl+S。
